### 成因判定：帳號尚未取得 Bedrock model access

下列觀察互相佐證，指向**帳號層級**的 model access 未開通，而不是參數、Region 或程式問題：

| 觀察 | 指令／來源 | 結果 |
|---|---|---|
| Bedrock control plane 正常 | `bedrock:ListFoundationModels`、`ListInferenceProfiles`、`ListCustomModels` | 全部成功，目錄列得出 Titan 與 Claude |
| 身分與其他服務正常 | `sts:GetCallerIdentity`、`s3:ListBuckets` | 全部成功（IAM user `tkb-deploy-admin`） |
| 所有 runtime 呼叫被拒 | `InvokeModel` / `Converse` | Titan V2、Titan V1、Cohere Embed、Nova Lite／Micro、Claude Haiku 4.5、Claude Sonnet 4.5（直接 ID 與 `us.` profile）一律 `ValidationException: Operation not allowed` |
| 換 Region 仍然被拒 | `us-east-1`、`ap-northeast-1` | 同一個錯誤 |
| 直接證據 | `bedrock:GetUseCaseForModelAccess` | `ResourceNotFoundException: You have not filled out the request form. Fill out the form before getting access.` |

最後一列是決定性證據：這個帳號**從未送出 Bedrock 的 model access 使用情境表單**，所以沒有任何模型被授權，
runtime 一律以 `Operation not allowed` 拒絕。這是需要人在 AWS Console 完成的動作
（Bedrock 主控台 → Model access → 填寫使用情境表單並申請所需模型），
腳本不會、也不應該代填公司／用途欄位。

### 對 `ProbeStatus` 對照表的說明

本次的錯誤代碼是 `ValidationException`，依 Phase 14 §6.2 固定對照到 `param_unsupported`。
對照表刻意不改：狀態碼只忠實反映 `Error.Code`，實際語意保留在 `detail` 的原始訊息
（`Operation not allowed`）裡，避免把「帳號未開通」誤寫成「模型不存在」或反之。

### 解除 BLOCKED 需要做的事

1. 在 AWS Console 的 Bedrock → Model access 填寫使用情境表單，並申請
   `amazon.titan-embed-text-v2:0` 與 Claude Haiku 4.5（或 Sonnet 4.5）的存取。
2. 等待核准後重跑 `uv run python infra/scripts/check_models.py --region us-east-1`，
   確認 exit code 為 0，再把新的 `o5-<run-id>.md` 與三個 env 值補進本目錄。
3. 在 exit code 變成 0 之前，Phase 15–18 一律維持 blocked。
