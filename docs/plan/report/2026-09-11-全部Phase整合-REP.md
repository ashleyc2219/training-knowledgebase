## 4. Demo 操作順序

**開場前（現場先做完）：**

```bash
cd /Users/linjunting/AWS-Hackathon
bash scripts/run_deflect_api.sh                 # 另開一個終端機，demo 全程開著（Rote Play 要打它）
uv run python scripts/demo_rehearsal.py         # 彩排一次，確認 8 步全綠（5.5 秒）
uv run streamlit run app/demo/streamlit_app.py  # Demo UI
```

> 彩排跑完會把資料留在「跑完的狀態」。正式 demo 前在 Streamlit 側欄按一次「**重置 demo 資料**」，再跑 `uv run python -m app.ingest.seed`。

**正式順序（Streamlit 為主，共七步）：**

| 步 | 操作 | 評審看到什麼 |
|---|---|---|
| 0 | 側欄「重置 demo 資料」→ 終端機 `uv run python -m app.ingest.seed` | 空畫面 → 6 張 resolved 票、3 個 UserProblem、3 個 Feature 進 9 表與圖譜。**起點是乾淨的** |
| 1 | 左欄「餵下一張票」× 3（都是 `cancel_order`） | 中欄決策卡連三張 `escalated｜no_published_tutorial`。**系統誠實承認不知道** |
| 2 | 中欄解法確認框填解法 → 「轉真人解決」 | 票變 `resolved`，解法被記下來 |
| 3 | 中欄「**分析 Support Tickets**」 | `analyze_tickets → [{'user_problem_id': 1, 'topic': 'cancel_order', 'action': 'CREATE'}]` → 自動產出 `tutorials/cancel-order.md` v1 published。**中欄直接翻出 .md 內容，Step 3 是 `Click "Cancel Order"`** |
| 4 | 左欄「餵下一張票」（第 4 張 cancel_order） | 決策卡變 `deflected｜published_tutorial`，回教學連結；Workflow 出現一列 `replay_count = 0`。**Rote 捕捉了第一次成功的流程** |
| 5 | 左欄「餵下一張票」（第 5 張） | 一樣 deflected，但這次走**重放**；`replay_count = 1`。Muscle memory 生效 |
| 6 | 回饋分頁「匯入 v1 回饋種子」→「**執行 Feedback Review**」 | v1 均分 **2.90** → `action: REFINE` ＋ `reason` → v2。再匯入 v2 回饋種子 → 均分 **4.40**。下欄曲線上揚 |
| 7 | Release 分頁：左欄貼 changelog → 「入庫」→ 中欄「處理」 | Release 先以 `processed_at` 為空入庫（兩段式，不是黑箱）→ 處理後 `[{'release_id': 1, 'tutorial_id': 1, 'action': 'UPDATE'}]`；**新舊 steps 並排 ＋ unified diff：Step 3 從 `Click "Cancel Order"` 變成 `Click "Cancel Purchase"`**；Feature 改名 `Cancel Purchase`；版本 v3。再按一次處理 → `[]`（冪等） |
| 8 | 指標分頁 | deflection rate **1.00**、重放解決率 **0.50**、圖譜覆蓋 **0.33** |

**收尾一句話**：「這裡沒有任何 fine-tuning。改變未來行為的是**過去的結果**——三張票逼出一篇教學、低分逼出改版、Release Note 逼出更新、第一次成功變成可重放的肌肉記憶。」

**Plan B（Streamlit 掛掉／網路不通）**：直接跑 `uv run python scripts/demo_rehearsal.py`，八步全自動、5.5 秒跑完，每步都印「👀 評審看到什麼」，照著念即可。
