## 1. 實作內容（含實作邏輯）

### 1.1 `src/training_kb/writing/validators.py`（新建）

- `BusinessValidator = Callable[[dict[str, Any]], None]`：業務 validator 的固定形狀——吃已通過 schema 的 dict，合法安靜回 `None`，不合法丟 `ContentError`。
- `gap_naming_validator(*, known_feature_ids: frozenset[str])`：`feature_id` 是 `None` 就放行（設計 §14.1 明列的合法結果，由 Phase 40 決定 KEEP／CREATE），是字串就必須在既有 Feature 裸 ID 集合內，否則丟 `ContentError("feature_id_not_found: feature_id")`。「一張 Ticket 最多一個 Feature」在 schema 形狀上已成立（`feature_id` 是單一字串或 `null`），這裡只補「存不存在」。
- `step_rewrite_validator(*, allowed_steps: frozenset[int], allowed_features: frozenset[str])`：逐步檢查 `number` 在命中集合內（否則 `step_number_not_in_hit_set: steps[].number`）與 `feature_id` 存在（否則 `feature_id_not_found: steps[].feature_id`）。未命中步驟是否逐字保留屬於 Phase 51 的 `assert_unchanged`（要拿舊版全文比對），不塞進這個只看單一 payload 的 callback。
- 兩個 factory 都把 runtime context **閉包**進去：context 才是 schema 驗不出來的那一半。
- 訊息格式固定 `<代碼>: <欄位路徑>`，不含模型輸出、prompt 原文或使用者文字（00A §3.8）。
- module docstring 收錄八個 schema 的業務檢查接入點表（兩個在本檔、六個在 P21／P43／P45／P47／P50／P55），明寫「消費 Phase 的 private helper 只是包裝本檔的 factory，不得另寫一份」，避免兩份並存。

### 1.2 `src/training_kb/writing/client.py`（修改，局部插入，未重排既有程式）

- `import` 追加 `ContentError` 與 `from training_kb.writing.validators import BusinessValidator`。
- 新增 `WRITING_MAX_TOKENS: dict[str, int] = {"TutorialDraft": 2048}`（教學寫作類的唯一例外），Phase 15 的 `JUDGEMENT_INFERENCE_CONFIG`（512／0.1）保留為底稿常數；把它原本「由 Phase 18 取代」的註解改成「這是 inference_config 的底稿」。
- 新增 `inference_config(schema)`：`dict(JUDGEMENT_INFERENCE_CONFIG)` 起手，`$id` 命中 `WRITING_MAX_TOKENS` 才覆寫 `maxTokens`；永遠不設 `topP`。判斷類的 512／0.1 因此只有一份來源。
- 新增 module-private 的 `CORRECTION_TEMPLATE` 與 `_generate_with_correction(writer, system, user, schema, validate, *, operation_id, node)`：固定演算法 first → validate → （`ContentError` 才）組修正 prompt → second → validate → 仍不合法丟 `PermanentError(f"business-invalid after one correction: {exc}")`。**沒有 `while`**，第三次 request 在結構上不存在。`TransientError` 不進 `except`（`except ContentError` 只攔業務錯誤），直接往外交給 Phase 29 的單層 ASL Task Retry，也因此不消耗修正預算。
- `BedrockWriter._converse` 加一個關鍵字參數 `inference: Mapping[str, object] = JUDGEMENT_INFERENCE_CONFIG`（沒有 schema 的 tool use 屬判斷類），`generate_json` 逐次傳 `inference_config(schema)`。Titan 的 `embed` 走 `invoke_model`，完全不碰生成參數，維持原樣。
