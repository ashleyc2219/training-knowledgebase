## 1. 實作內容與邏輯（逐檔說明）

### 1.1 `src/training_kb/analytics/ratings.py`（新增）

本 Phase 唯一的產品檔，四個**純函式**：不讀 DynamoDB、不呼叫模型、不判規則狀態、不寫任何 item。
輸入是已經讀好的 `Feedback` 物件與核定類別集合，輸出數值與 ID 集合。

| 公開名稱 | 簽名（與 00A §6.10 逐字一致） | 邏輯 |
|---|---|---|
| `average_rating` | `def average_rating(feedback: Iterable[Feedback]) -> float \| None` | 先把 `rating is not None` 的值濾出來；空清單回 `None`，否則 `sum / len`。分母是**有評分**的筆數（00A D-44），`rating is None` 不進分子也不進分母。 |
| `cross_version_average` | `def cross_version_average(values: Sequence[float \| None]) -> float \| None` | 輸入是**每版已算好的平均**。濾掉 `None` 之後取算術平均，所以每一版權重相同；全是 `None`（或空序列）回 `None`。 |
| `negative_feedback_ids` | `def negative_feedback_ids(feedback: Iterable[Feedback], approved: frozenset[str]) -> frozenset[str]` | 逐筆判 `low = rating is not None and rating <= 2`、`flagged = category is not None and category in approved`，任一成立就把 `item.id` 丟進 `set`，最後回 `frozenset`。 |
| `format_average` | `def format_average(value: float \| None) -> str` | `None` → `"尚無評分"`；否則 `Decimal(str(value)).quantize(Decimal("0.1"), rounding=ROUND_HALF_UP)`。 |

另外宣告一個模組層常數 `NO_RATING_DISPLAY = "尚無評分"`，讓「尚無評分」這個字串只有一處定義；
它不在 00A §6.10 的契約裡，後續 Phase 要顯示字串時請照常呼叫 `format_average`，不必 import 這個常數。

三個刻意的設計點（都對應 Phase 文件 §6 的三個重點）：

1. **`None` 不等於 0**。沒有任何有效評分時回 `None`，不是 `0.0`。
   若寫成 `sum(...) / max(len(...), 1)`，沒人評分的版本會看起來比 1 分還糟，
   而且會讓 Phase 55 的「前後平均嚴格提高」誤判成立。這是 Phase 文件 §9 明列的停止點，有測試站崗。
2. **集合不是加總**。回傳型別固定 `frozenset[str]`，同一筆 Feedback 同時命中「低分」與「核定類別」
   只會佔集合裡的一格；呼叫端拿不到兩個可以相加的計數，所以「8 變成 10」這種錯誤在型別上就被擋掉。
3. **等權不是加權**。`cross_version_average` 收的是每版平均，不是回饋清單；
   A v1 八筆與 A v2 十筆權重相同（3.6375），不是把 18 筆混成一池的 67/18 ≈ 3.7222。

兩個容易踩的實作細節，程式裡有註解說明：

- `format_average` 一定要 `Decimal(str(value))`。直接 `Decimal(2.875)` 會拿到二進位誤差版
  （實際是 2.874999…），`ROUND_HALF_UP` 之後變成 `2.8`，與設計 §11.2 要求的 **2.9** 不符。
- `negative_feedback_ids` 一定要先 `rating is not None` 再比較。反過來寫 `item.rating <= 2`
  遇到 `rating=None` 的回饋會拋 `TypeError`。

## 5. 遇到的問題與解法

### 5.1 整套 pytest 在收集階段被別的 Phase 擋住

不加 `--ignore` 直接跑 `uv run pytest tests -q -W error`，會在 collection 階段中斷：

```text
ERROR tests/integration/test_weak_targets.py
ERROR tests/unit/test_feedback_diagnosis.py
ERROR tests/unit/test_release_hits.py
ERROR tests/unit/test_release_locate_feature.py
ERROR tests/unit/test_site_pages.py
!!!!!!!!!!!!!!!!!!! Interrupted: 5 errors during collection !!!!!!!!!!!!!!!!!!!!
```

錯誤內容是 `ImportError: cannot import name 'FEATURE_MATCH_THRESHOLD' from
'training_kb.pipelines.release'`、`cannot import name 'NO_PREVIOUS_TEXT' from 'training_kb.site'`
這一類——**全部是同一批其他 Phase（P44／P45／P46 一帶）進行中的測試檔**，
它們的測試檔已進 repo 但對應實作還沒補完。依 COMMON R3.5 用 `--ignore` 排除並記在這裡，
**沒有去修別人的測試檔或實作**。同樣地，`uv run ruff check src tests infra` 的 11 個錯誤
（`src/training_kb/pipelines/feedback.py` 的 7 個 F401、`tests/unit/test_release_locate_feature.py`
的 4 個 E501）也都是別的 Phase 的檔，本 Phase 沒有碰。

排除的這 5 支檔與本 Phase 沒有任何共用程式：本 Phase 只新增兩支全新的檔案，
不可能是造成它們紅燈的原因。

### 5.2 `ruff format` 把行尾註解搬到錯的位置

對自己新建的測試檔跑 `ruff format` 之後，`test_negative_ids_cover_three_independent_boundaries`
裡「# 兩個條件同時命中」這個註解被搬到 list 的右中括號後面，讀起來像在說明整個 list。
手動把註解移回 `fb("f_304", 1, "缺少資訊")` 那一行，再跑一次 `ruff format --check` 確認穩定
（`2 files already formatted`）。

### 5.3 人工驗收腳本第一版把 v2 算成 4.4545

第一次寫驗收腳本時，把負面測試用的「待分類探針」`f_200`（5 分）也放進計算平均的 v2 清單，
平均變成 4.4545。這是**腳本**的問題不是實作的問題：設計 §11.2 的 v2 是 `f_101`–`f_110` 十筆，
測試 `test_average_rating_reproduces_design_v1_and_v2` 用的正是這十筆並斷言 4.4。
把腳本改成「平均用十筆、負面另外加探針」之後兩邊都對得上（§4.3 是修正後的輸出）。

### 7.2 給下一個 Phase 的介面（Phase 54 的 `VersionMetrics` 直接用這四個）

import 路徑只有一條（`analytics/__init__.py` 不 re-export）：

```python
from training_kb.analytics.ratings import (
    average_rating,
    cross_version_average,
    format_average,
    negative_feedback_ids,
)

def average_rating(feedback: Iterable[Feedback]) -> float | None: ...
def cross_version_average(values: Sequence[float | None]) -> float | None: ...
def negative_feedback_ids(feedback: Iterable[Feedback], approved: frozenset[str]) -> frozenset[str]: ...
def format_average(value: float | None) -> str: ...

NO_RATING_DISPLAY: str = "尚無評分"     # 模組常數，不在 00A 契約內；顯示請呼叫 format_average
```

使用時的三條規則：

1. **門檻比較一律吃未四捨五入的 float**（例如 Phase 44 的 `avg < 3.5`、Phase 55 的「嚴格提高」），
   `format_average` 只在最外層顯示時用，不可回填。
2. `average_rating` 回 `None` 代表「尚無評分」，**不是 0**。
   Phase 54 的 `VersionMetrics.average` 與 Phase 55 的前後比較都要先處理 `None`。
3. `negative_feedback_ids` 回 `frozenset[str]`。要數量就 `len(...)`；
   跨版彙總請用集合聯集，不要把兩版的長度相加（同一筆 ID 不會跨版重複，但語意上仍以集合為準）。

**Phase 54 對接**：`VersionMetrics.average = average_rating(repository.list_feedback_of_version(vid))`、
`VersionMetrics.negative_ids = negative_feedback_ids(同一份清單, approved)`、
`sample_size` 請自己數（本 Phase 不提供筆數，`average_rating` 只回平均）。
