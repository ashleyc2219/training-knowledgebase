## 1. 實作內容與邏輯（逐檔說明）

### 1.1 `src/training_kb/ingress.py`（修改，追加 `# ---- Phase 42 ----` 區段）

固定匯入是「只有程式判斷」的一條路徑：沒有 adapter 選擇、沒有模型、不建 `RawEvent`、
不進 Rote、不啟動 Step Functions、不寫 `PROC#`。順序固定成四關，每一關都先於下一關：

```text
純欄位（validate_*）→ 圖譜（版本存在 / 退役）→ 操作紀錄（永久去重 / 續跑）→ 寫入
```

**新增的公開名稱**

| 名稱 | 簽名／值 |
|---|---|
| `FEEDBACK_FIELDS` | `frozenset[str]` = `{id, tutorial_version, rating, category, comment, user, ts, project_id}` |
| `VIEW_FIELDS` | `frozenset[str]` = `{tutorial_version, user, ts, project_id}` |
| `FEEDBACK_ID_PREFIX` | `"f_"` |
| `ImportResult` | `@dataclass(frozen=True)`；`status: Literal["saved","duplicate","rejected"]`、`object_id: str \| None`、`message: str`、`invalid_fields: tuple[str, ...]` |
| `validate_feedback` | `(payload: Mapping[str, object], *, now: datetime) -> Feedback` |
| `validate_view` | `(payload: Mapping[str, object]) -> TutorialView` |
| `import_feedback` | `(payload: Mapping[str, object], *, repository: Repository, operations: OperationCoordinator, now: datetime) -> ImportResult` |
| `import_view` | `(payload: Mapping[str, object], *, repository: Repository, operations: OperationCoordinator, now: datetime \| None = None) -> ImportResult` |

**新增的 private helper**：`_rejected`、`_project_id`、`_text`、`_optional_text`、
`_stable_user`、`_rating`、`_import_ts`、`_assert_open`、`_dedupe`、`_saved_message`。

逐項邏輯：

- **`_rating`** 用 `type(value) is int`，不是 `isinstance`。`bool` 是 `int` 的子類別，
  `isinstance(True, int)` 為真，`rating=True` 會被存成 1 分而污染平均（文件 §9 第一列）。
  `models.Feedback` 自己也有 `rating_is_strict_int`；入口再判斷一次的理由是**要吐
  `IngressError(fields=("rating",))` 而不是 pydantic `ValidationError`**（00A §6.8）。
- **`_import_ts`** 一律走既有的 `_parsed_ts`，不只用 `parse_iso`：`parse_iso` 放行微秒，
  下游 `view_pk` 的 `to_iso` 會丟 `PermanentError`——那不是使用者輸入錯誤該有的形狀。
  `required=False`（Feedback）缺值回 `None`，由 `validate_feedback` 補 `now`；
  `required=True`（View）缺值就是不合法，**不補值**：補了會讓「先瀏覽、後開票」這個
  指標前提（`MET` Rule 4／5）變成偽造的證據。
- **`_stable_user`** 直接重用 Phase 13 的 `source_ids.stable_user_from_import`
  （`^[a-z0-9_-]{2,64}$`，丟的正是 `IngressError(fields=("user",))`），不另寫一份判斷。
- **`_text`** 呼叫既有的 `missing_nonempty_strings`，所以「什麼叫缺值」全專案仍然只有一份定義。
  未知欄位用 `sorted(set(payload) - FEEDBACK_FIELDS)` 一次收齊，與缺值、格式錯**同時**回報
  （`IngressError.__init__` 自己會排序去重）——F51 要的是「指出不合法欄位」，不是只講第一個。
- **`_assert_open`** 只呼叫 Phase 26 的 `assert_accepts_feedback(tutorial)`，不自己比
  `tutorial.status`；接住它的 `IngressError` 直接轉 `rejected`，不比對訊息字串。
  呼叫點在 `import_feedback`（拿得到 `Tutorial` 之後），不是 `validate_feedback`。
- **`_dedupe`** 是泛型函式（PEP 695：`def _dedupe[MetaT: StrictModel](...)`），回饋與瀏覽
  共用。它回 `(operation_id, 是不是真的重複)`：**`accept` 回 duplicate 不等於物件已經存在**
  （00A D-45）。只有 ledger 有紀錄、目標 item 卻不在，是**續跑**，本次補寫。
- **`import_feedback`** 寫 `FEEDBACK#<id>` metadata 與一條指向**提交時指定的那一版**的
  `REFERS_TO#VERSION#<version_id>` 邊（`COL` Rule 7），**不改綁 `current_version`**；
  然後 `operations.complete(...)`。成功訊息在 `ts` 是補的時候附上
  「來源未提供 ts，改記匯入時間 …，非使用者實際提交時間」。
- **`import_view`** 只查版本存在、**不查退役**（設計 §8.4：退役頁的瀏覽數是重開票率的分母）。
  主鍵是 `view_pk(版本, 使用者, 時間)` 的 SHA-256，`canonical_id` 取 `parse_pk(pk)[1]`
  （那 64 個 hex），`operation_id` 才不會超過 80 字的執行名稱上限。**不建 `VIEWED` 邊**
  （設計 §9.2）。`now` 是可選的**接受時間**（缺值 `now_utc()`），與事件時間 `view.ts` 是兩件事。

### 1.2 `src/training_kb/handlers/import_.py`（新檔）

`training-kb-import` 的唯一入口（00A D-56）。`IMPORT_KINDS = ("feedback","view","ticket","release")`、
`IMPORT_DEADLINE_SECONDS = 300.0`、`SOURCE_FIELDS = ("domain","adapter","event_type")`、
`_DEPS: Deps | None = None`、`handler(event: dict[str, Any], context: object) -> dict[str, object]`、
`_item`／`_lower_headers`／`_event_payload`／`_import_one`。

- `kind` 不在四種內、或 `items` 不是陣列 → `PermanentError`，**相依還沒組**就先擋
  （呼叫方式錯誤不該先去連 DynamoDB 與 S3）。
- **多筆 batch 的展開在這裡**（P36 note 的「目前只取 `items[0]`」）：`event["items"]` 逐筆
  `_import_one`，一筆 `rejected` 不影響其他筆。`adapters.py::_batch_item` **沒有動**
  ——那是 Rote 工具的「一次一筆」語意。
- `ticket`／`release` **純委派** `normalize_then_accept` 的六個 keyword 參數（D-60），
  `domain`／`adapter`／`event_type` 由匯出檔自己帶、**不從 payload 反推**，缺了整筆
  `PermanentError`。它回的是 **`list[Acceptance]`**（D-73）：`object_id` 取第一筆、
  訊息列出全部 operation ID，全部 duplicate 才回 `duplicate`。
- `_DEPS` 是暖啟動快取；測試直接 monkeypatch 它。

### 1.3 `infra/training_kb_stack.py`（修改，`# ---- Phase 42 ----` 區段，Edit-only）

模組層常數 `IMPORT_FUNCTION`／`IMPORT_HANDLER`／`IMPORT_TIMEOUT`／`IMPORT_PREFIXES`／
`IMPORT_MACHINES`／`IMPORT_DDB_ACTIONS`，`__init__` 末端的 `self.import_function`，
以及 private helper `_import_machine_arns()`。

- `code=`／`layers=`／`environment=base_env` 全部沿用 P41 的 `self._function(...)`
  （共用 `self.deps_layer`，R2），**沒有**再做一支 layer。

  它也不需要 `TKB_GITHUB_WEBHOOK_SECRET`。

  S3 只有 `operations/*`（**沒有** `site/*`、沒有其他私有前綴）、DynamoDB 只有
  `GetItem`／`PutItem`／`UpdateItem`／`Scan`、`with_index=False`（不給 GSI）。
  沒有 `bedrock:InvokeModel`、沒有 `dynamodb:DeleteItem`、沒有萬用字元。
- `states:StartExecution` 由 **`_import_machine_arns()`** 以 `Stack.format_arn(...,
  arn_format=ArnFormat.COLON_RESOURCE_NAME)` **從名稱組 ARN**，一次授權
  `training-kb-ticket-analysis` 與 P52 之後才建立的 `training-kb-release-update`
  （IAM 允許引用尚不存在的資源，所以 P52 不必回頭碰這支 Lambda）。
  `training-kb-feedback-review` 不在清單裡：固定匯入不啟動它。

## 5. 遇到的問題與解法

1. **Task 1 的 commit 把 Task 2／3 的實作一起塞進去了。** 我一次寫完整個 Phase 42 區段才想到
   後兩個 Task 就沒有紅燈可跑。原本想 `git commit --amend` 修掉，**結果 amend 打到的是同一
   秒鐘另一個 agent（P54）剛推上來的 commit**，把我的修改折進了他們的 commit。處理方式：
   `git reset --soft` 回到他們那一支的原始 SHA（內容逐字還原），再用 `git commit -- <路徑>`
   把我的修改獨立成一支 `fix(ingress): Task 1 只留匯入欄位契約`，後面三個 Task 才逐一重新
   跑紅燈。**controller 之後把「絕不 amend／reset／rebase」寫進 COMMON.md R3.4**；我從那之後
   一律新開 commit，並且每一次 commit 都帶明確 pathspec（`git commit -- <我的檔>`），
   不讓別人剛 stage 的檔混進來。
2. **`ruff UP047`**：`_dedupe` 用 `TypeVar` 會被要求改成 PEP 695 的 `def _dedupe[MetaT: StrictModel](...)`。
   改掉之後 mypy 與 ruff 都綠。同理 `IMPORT_MACHINES` 要標成 `tuple[PipelineName, ...]`，
   否則 `STATE_MACHINE_NAMES[pipeline]` 在 mypy strict 下是 `Invalid index type "str"`。
3. **`states:StartExecution` 的授權範圍**（controller 追加）：原本用
   `self.ticket_analysis.grant_start_execution(...)`，只涵蓋當下存在的那一條。改成
   `Stack.format_arn(..., arn_format=ArnFormat.COLON_RESOURCE_NAME)` **從名稱組 ARN**，
   一次授權 `ticket-analysis` 與尚未建立的 `release-update`（IAM 允許引用不存在的資源），
   P52 就不必回頭改我的 Lambda。`ArnFormat` 要明寫成 `COLON_RESOURCE_NAME`，
   預設的 `SLASH_RESOURCE_NAME` 會組出 `stateMachine/<name>` 這種不存在的形狀。
4. **infra 測試的 layer 守門會在乾淨 clone 上炸**（controller 追加）：P41 把 `is_built()` 收緊成
   「要看得到 `python/pydantic` 與 `python/jsonschema`」，但我的 `test_import_lambda.py` 與
   P54 的 `test_analytics_stack.py` 都還在工作樹 `mkdir(build/lambda-layer/python)`；本機會綠
   只是因為 `build/` 剛好留著真的裝好的套件。解法：新增
   `tests/unit/infra/conftest.py` 的共用 `fake_layer` fixture（monkeypatch `LAYER_PATH` 到
   `tmp_path`，依 `build_lambda_layer.MARKERS` 造目錄），三支 infra 測試都改用它，
   `test_ticket_asl.py` 裡重複的那一份也移過來。**驗證方式**：把 `build/lambda-layer` 整個
   搬走再跑 `uv run pytest tests/unit/infra -q` → `34 passed in 6.85s`，之後搬回來。
5. **`-W error` 下的既有紅燈**：整套跑起來沒有任何 warning 轉成 error；唯一的 ruff 紅燈是
   `tests/unit/test_release_retire.py`（P52 進行中），沒有動它。
6. **雲端部署的 webhook secret**：P41 的 secret 存在它自己 session 的 scratchpad 裡，我拿不到。
   直接從已部署的 `training-kb-webhook` 讀回環境變數再帶進 `cdk deploy`，
   所以這次部署**沒有改動**那支 Lambda 的 secret。secret 只在 shell 變數裡，沒有落到 repo、
   報告或 log。
