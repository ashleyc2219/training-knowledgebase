## 1. 實作內容（含實作邏輯）

用 AWS CDK v2（Python）建立唯一的資料 stack `TrainingKbDataStack`（stack id `TrainingKbData`），

### 1.1 `infra/training_kb_data_stack.py`（新建，owner P09）

模組常數逐字採用 00A §6.11／§3.4：

```python
TABLE_NAME = "training_kb"
TARGET_INDEX = "by_target"
PRIVATE_PREFIXES = ("tutorials/", "operations/", "stepfunctions/", "demo/previews/")
```

`TrainingKbDataStack.__init__` 依序宣告四樣東西，公開 `self.table`／`self.bucket`／`self.data_role`
三個屬性給後續 Phase（P41、P57）引用，避免任何人再建第二張表：

1. **DynamoDB 表**：`table_name="training_kb"`、`PK(S) HASH` + `SK(S) RANGE`、
   `PAY_PER_REQUEST`、`removal_policy=RemovalPolicy.RETAIN`。
   接著 `add_global_secondary_index(index_name="by_target", partition_key=target(S),
   projection_type=KEYS_ONLY)` —— **只有這一個 GSI，沒有排序鍵**，因為設計 §9.1 要求
   「先投影查詢需要的鍵，完整資料回基表取得」，這正是 Phase 08 `query_by_target` 只當候選的理由。
2. **S3 bucket**：邏輯 id `TrainingKbContent`（實際名稱交給 CDK 產生，確保全域唯一，程式不寫死）、
   `BlockPublicAccess.BLOCK_ALL`、`BucketEncryption.S3_MANAGED`、`enforce_ssl=True`、
   `removal_policy=RETAIN`。**本 Phase 不做 website hosting、不加任何公開 policy**
   （`site/*` 公開屬於 Phase 57，00A §6.11 已明訂交接方式）。
3. **最小資料角色**：`iam.Role(assumed_by=ServicePrincipal("lambda.amazonaws.com"))` 加三條 statement——
   - dynamodb 7 個動作（`GetItem`／`BatchGetItem`／`Query`／`Scan`／`PutItem`／`UpdateItem`／
     `ConditionCheckItem`），資源只有表 ARN 與 `<表 ARN>/index/by_target`。
     **刻意沒有 `DeleteItem`**：本案沒有刪除業務資料的流程；Phase 24 的交易寫入由
     `PutItem`／`UpdateItem`／`ConditionCheckItem` 這些 item 層級動作授權
     （IAM 裡沒有 `dynamodb:TransactWriteItems` 這個動作名）。
   - `s3:GetObject`／`s3:PutObject`，資源是四個私有前綴的**物件 ARN**（`<bucket>/tutorials/*` 等），
     不含 `site/`。
   - `s3:ListBucket`，資源是**bucket ARN**（不是 `bucket/*`，因為它是 bucket 層級動作），
     並用 `StringLike: {"s3:prefix": [...]}` 把可列出範圍限定在同樣那四個前綴。
     沒有這條，真實 S3 對沒有列出權限的呼叫者會把「key 不存在」回成 403 而不是 404，
     Phase 07 的 `get_object -> None` 分支在雲端就不成立（00A §3.8、§6.11）。
4. **三個 `CfnOutput`**：`TrainingKbTableName`、`TrainingKbBucketName`、`TrainingKbDataRoleArn`
   （名稱逐字取自 00A §3.5），部署後直接對應 `.env` 的 `TKB_TABLE_NAME`／`TKB_CONTENT_BUCKET`。

| 測試 | 鎖住什麼 |
|---|---|
| `test_exactly_one_table_with_one_index` | 1 張表、`training_kb`、`PK/SK`、唯一 `by_target`／`target`／`KEYS_ONLY` |
| `test_no_extra_datastore_or_pipeline_is_declared`（6 個 parametrize） | RDS／OpenSearch／Neptune／Lambda／StateMachine／CloudFront 各 0 個 |

## 5. 遇到的問題與解法

| # | 問題 | 解法 |
|---|---|---|
| 1 | pytest 不會把專案根目錄放進 `sys.path`，`import infra` 失敗（實測 `ModuleNotFoundError: No module named 'infra'`）。不能改 `pyproject.toml` 加 `pythonpath`。 | 在測試檔開頭把專案根目錄 `insert` 進 `sys.path`，再 `from infra.training_kb_data_stack import ... # noqa: E402`。這是**本 repo 既有慣例**（`tests/unit/test_check_models.py` 對 `infra/scripts/` 就是這樣做的），不是新發明。 |
| 2 | mypy strict 對 Phase 文件的 `**kwargs: object` 報 8 個錯：`**dict[str, object]` 轉送給 `Stack.__init__` 的 `env`／`description`／`tags`… 每個具名參數各一次 `incompatible type`。 | 改成 `**kwargs: Any`（CDK Python 範本本身的寫法）。`Any` 在 mypy strict 下合法，也不需要 `# type: ignore` 消音。Phase 文件已同步修正並寫明理由。 |
| 3 | 加了 `infra/app.py`（它 `from infra.training_kb_data_stack import ...`）之後，`mypy src infra` 報 `Source file found twice under different module names: "training_kb_data_stack" and "infra.training_kb_data_stack"`。 | 新增 `infra/__init__.py`（只有 docstring）。這也讓 `uv run python -m infra.app` 的模組路徑變明確。已確認不影響 `tests/unit/test_check_models.py`（它是直接 `sys.path.insert` 到 `infra/scripts`）。 |
| 4 | 本機 shell 把 `node` 定義成會拒絕的 function。 | 一律 `command npx aws-cdk@2 <子命令>`（`2.1141.0`）。實測 `aws_cdk.assertions.Template.from_stack`（jsii 會 spawn node）在 `uv run pytest` 下**正常運作**，不需要另外設 `PATH`——`/opt/homebrew/bin/node` 本來就在 PATH 上，被擋的只是互動 shell 的 function。 |
| 5 | 非互動環境不能用 `--require-approval any-change`（會停在 IAM 確認）。 | 改 `--require-approval never`。判斷依據：IAM 內容在 template 與 Phase 文件第 6 節逐條寫明，且單元測試已鎖住「不得有萬用字元」。已寫進 Phase 文件並附理由。 |
| 6 | `--outputs-file` 產生的 `cdk-outputs.json` 不該進版本庫。 | 寫到專案外的 scratchpad 路徑，實際值抄進 Phase 文件驗收記錄與本報告。已確認 repo 根目錄沒有 `cdk-outputs.json`，也沒有改 `.gitignore`（`cdk.out/` 早已被忽略）。 |
