## 1. 實作內容（含實作邏輯）

新增一支用完即丟的 spike `infra/scripts/o3_report.py`，把「跨 DynamoDB 與 S3 的發布切換」
五個失敗切點各在真實 AWS 上跑一次，並產出可追溯的 O3 報告。它**不是 `Publisher`**，
驗的是協定：`Repository.transact_write` 是 Phase 24 才有的方法，此時不存在，
所以直接用 boto3 client 的 `transact_write_items` 與 S3 `PutObject`。

腳本分七段：

1. **契約常數**：`O3CutPoint`（00A §6.11 的五個觀察點名稱，逐字採用、不與 P59 的注入點名稱混用）、
   `SLUGS = ("spike-a", "spike-b")`、`OLD_GENERATION="v1"`／`NEW_GENERATION="v2"`、
   `PUBLIC_SITE_PREFIX="site/"`、`SDK_CONFIG`（connect 2s／read 30s／SDK 不重試，
   切點觀察才不會被暗中補救）。
2. **資料結構**：`PublicView(slug, site_version, current_version, published_at)`、
   `CutPointResult(cut_point, views, exposed_bodies, partial_visible, note)`，兩個都是 frozen dataclass。
3. **純函式判定**：`is_partial` 兩層判斷——先看同一篇的公開頁與指標是否同世代（F37），
   再看所有篇是不是同一個世代、而且就是這次該看到的那一個（F49）。另有 `site_generation`
   （從索引頁抓 `data-site-version` 標記，缺物件回 `None`）、`generation_of`
   （`spike-a@v2` -> `v2`）、`build_view`（把一次 GET ＋ 一次一致讀取收成一列）。
   把 AWS 讀取與判定切開，缺 site 物件／缺 VERSION item 這類邊界才能純函式測。
4. **觀察**：`observe(slugs, *, table, bucket)` 對每個 slug 做一次 `ConsistentRead=True`
   的基表讀取（`by_target` GSI 是最終一致，刻意不走）與一次 `site/tutorials/<slug>/index.html` 的 GET。
5. **最小雙儲存提交協定與切點注入**：
   - 全舊初始狀態 `reset_to_old_generation`：兩篇 `current_version=<slug>@v1`、v1 已發布、
     v2 已寫好但 `published_at` 不存在；`site/` 只有 v1。item 形狀照 00A §3.6
     （模型欄位 ＋ `PK`／`SK`／`entity`／`_revision`，沒有第三類屬性）。
   - `publish_transaction`：一次 `TransactWriteItems`，每篇兩個 Update——
     `TUTORIAL#<slug>` 切 `current_version`（條件 `current_version = :old` 檢查基底未改變）、
     `VERSION#<slug>@v2` 寫 `published_at`（條件 `attribute_not_exists(published_at)`）。
   - 協定 A：staging -> 交易 -> 逐篇寫 `site/`（切點 a1／a2／a3／c1）。
     協定 B：staging -> 先寫 `site/` -> 才交易（切點 b1）。兩種順序都跑，漏跑等同未驗證。
   - 注入用「執行到這裡就停」的旗標，不用 `sleep`；停下來之後不做任何補救。
   - `exposed_bodies` 記的是該切點當下真的能從 `site/` GET 回來、而且屬於新世代的內容，
     而且一定在任何回復動作**之前**讀——`c1` 因此在刪掉公開頁之後仍留著 4 筆曝光紀錄。
6. **報告**：`o3_verdict`（任一切點 partial 就 FAIL）、`render_o3_report`（六欄表 ＋ 交易換算 ＋
   判定；FAIL 時附 00A §4.2 的停止語句、六個被阻擋的 Phase、Phase 59 切點 4 的 O3 缺口標記，
   以及三個**都標「尚未核定」**的決策出口）。
7. **隔離資源與命令列**：`create_spike_resources`／`delete_spike_resources`／`main`。

**`expected` 的裁決（Phase 文件只說「v1 代表全舊、v2 代表全新」，沒有逐切點對照）：**
以「DynamoDB 交易是否已提交」為界，交易是這次發布唯一的原子提交點，交易前該看到全舊、
交易後該看到全新，所以 `a1`／`b1` 是 `"v1"`，`a2`／`a3`／`c1` 是 `"v2"`（`EXPECTED_GENERATION`）。
這個選擇不影響任何一列判定：`a2`／`a3`／`b1`／`c1` 都先在「同一篇的公開頁與指標不同世代」
那一層就判成 partial。已寫進 Phase 文件 §5。

## 5. 遇到的問題與解法

| 問題 | 解法 |
|---|---|
| `boto3.client(service)` 傳變數字串時 mypy strict 對不上 overload | 拆成 `dynamodb_client()` 與 `s3_client()` 兩個字面量呼叫，共用一個 region 快取 dict；沒有用 `# type: ignore`。 |
| 證據要寫私有 `operations/o3/<run_id>.json`，但隔離 bucket 跑完必須刪，且不得寫正式 bucket | 寫進隔離 bucket 的該 key（示範 00A §3.4 的佈局）、寫完立刻讀回比對 bytes，刪除前下載並把同一份 JSON 逐字抄進報告的「原始觀察值」一節。不另開 00A 路徑表沒有的新檔。 |
| Phase 文件要求「用瀏覽器開公開頁確認 partial 肉眼可見」，但本 Phase 不得新增公開讀取入口 | 隔離 bucket 維持 Block Public Access 全開、不放公開 policy，改用 `aws s3 cp s3://.../index.html -` 讀原文對照；兩個索引頁在同一時刻一個顯示 `spike-a v2`、一個顯示 `spike-b v1`，partial 一樣是肉眼看得到的。已修 Phase 文件並說明等價性。 |
| `c1` 的曝光紀錄若在刪除後才讀就會是空的 | `run_cut_point` 固定「先讀曝光、再做回復、最後 observe」，讓「事後刪除不消除曝光」變成可斷言的行為（`results[-1].exposed_bodies != ()`）。 |
| `main` 不在 00A §6.4 的 gate 工具清單裡 | 照 00A 優先：不改 00A，也不改任何 canonical 名稱；`main`／`build_parser`／隔離資源函式是這支腳本自己的入口，別的 Phase 不消費，補記在 Phase 文件 §5。 |
