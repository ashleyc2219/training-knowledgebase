讓 Phase 10 的 `ops_pk`／`operation_ref` 直接接在第 5 段之後，不必改動前四段：

1. **常數** — `META = "META"`（值必須等於決策紀錄的 `Sort-Key`）、
   `RELATIONS = frozenset({"REFERENCES", "SUPERSEDES", "APPLIED_TO", "ASKS_ABOUT", "REFERS_TO"})`
   （設計 §9.2 的五種關係，多一種都不行；依 00A §6.2 只在 `keys.py` 內部使用，外部不 import）。
2. **私有守門員** — `_bare(value)` 是「不准重複加前綴」的**唯一**入口檢查（非 `str`／空字串／含 `#`
   一律 `ValueError`，訊息含 `bare identifier`）；`_pk(kind, value)` 供八個單值 builder 共用。
   十個 builder 全部經過 `_bare`：八個經 `_pk`，`step_pk`、`view_pk` 直接呼叫。
3. **十個 PK builder** — `tutorial_pk`／`version_pk`／`feature_pk`／`ticket_pk`／`release_pk`／
   `feedback_pk`／`rule_pk`／`proc_pk` 走 `_pk`；`step_pk(version_id, number)` 先擋 `bool`
   再擋非正整數（Python 的 `bool` 是 `int` 子類別，`True` 會變成假的第 1 步），輸出
   `STEP#<version_id>#<number>`；`view_pk(tutorial_version, user, ts)` 先用 `to_iso(ts)`
   把時間轉成整秒 UTC `Z` 字串，再把三元組以
   `json.dumps(..., ensure_ascii=False, separators=(",", ":"))` 固定編碼後取 SHA-256。
4. **三個 parser** — `parse_pk` 用 `partition("#")` 只切第一個 `#`，**刻意不維護前綴白名單**，
   所以 Phase 10 追加 `OPS#`／`CONFIG#`／`SEQ#`／`LEASE#` 時不必回頭改它；
   `parse_step_pk` 用 `rpartition("#")` 從**右邊**切，先確認 `kind == "STEP"`、有分隔符、
   步驟號全是數字，才回 `(version_id, int(number))`。
5. **關係邊** — `edge_sk(relation, target_pk)` 先擋非白名單關係（訊息 `unsupported edge relation`），
   再用 `parse_pk(target_pk)` 確認終點是完整 PK（避免 `REFERENCES#Prepare` 這種半截邊），
   才組 `<關係>#<終點 PK>`；`parse_edge_sk` 同樣只切第一個 `#`（終點自己就含 `#`，
   用 `split("#")` 會把 `FEATURE#Prepare` 切成 `FEATURE`），關係不在白名單時丟
   `invalid edge sort key`。

## 1. 改了什麼

### （必修 1）`parse_step_pk` 對畸形鍵過度寬鬆 — `src/training_kb/keys.py`

原本照抄計畫的條件 `if kind != "STEP" or not separator or not number.isdigit():` 改成：

```python
    if (
        kind != "STEP"
        or not separator
        or not version_id
        or not number.isdecimal()
        or str(int(number)) != number
    ):
        raise ValueError(f"invalid step primary key: {value!r}")
```

判準改成 **round-trip 封閉**：`step_pk(*parse_step_pk(pk)) == pk` 對任何能通過的字串都必須成立。
`isdecimal()` 只解決 `³`（`isdigit()` 為真但 `int()` 會丟自己的訊息）；`３` 與 `03` 要靠
`str(int(number)) == number` 這道正規形檢查。兩者順序不可對調——`or` 由左至右短路，
`isdecimal()` 必須排在 `int()` 之前，否則 `³` 會先讓 `int()` 丟出非契約訊息。

實測舊 vs 新（`uv run python`，把舊版本複製成 `old_parse_step_pk` 並列比較）：

```text

'STEP#slug#03'   舊: 回 ('slug', 3)                新: raise ValueError(invalid step primary key: 'STEP#slug#03')
'STEP#slug#３'    舊: 回 ('slug', 3)                新: raise ValueError(invalid step primary key: 'STEP#slug#３')
'STEP#slug#³'    舊: raise ValueError(invalid literal for int() with base 10: '³')
                 新: raise ValueError(invalid step primary key: 'STEP#slug#³')
round-trip 封閉： True
```
