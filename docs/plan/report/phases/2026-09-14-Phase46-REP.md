新增的公開名稱：

| 名稱 | 做什麼 |
|---|---|
| `REFINE_NODE = "refine_steps"` | 寫進 `CallTrace` 的節點名；`generate_json(node=)` 一律傳它 |
| `RefinePlan` | 七個欄位的 frozen dataclass，代表一個**未發布**的下一版與它的來歷 |
| `evidence_fingerprint` | 版本＋類別＋排序去重 ID 的 SHA-256（64 位十六進位） |
| `refine_operation_id` | `op-feedback-<指紋>`，經 P32 的 `operation_id_for` |
| `refine_reason` | 逐字 `feedback:<去重後筆數> 則 <類別>` |
| `evidence_of` | 回（唯一類別, 排序 ID）；跨類別或缺漏 → `ContentError` |
| `prepare_refine` | 主流程，回 `RefinePlan \| None` |

module-private helper：`_rules_for_hits`、`_assert_unchanged`、`_apply_rewrite`、
`_known_feature_ids`、`_reuse_or_call`、`_guard`。

**指紋只吃穩定的東西。** `evidence_fingerprint` 的 payload 只有 `version_id`、`category`
與 `sorted(set(ids))`，以 `ensure_ascii=False, sort_keys=True, separators=(",", ":")`
編成 UTF-8 再 SHA-256。平均分、留言原文、執行時間都**不進指紋**——顯示文字改一個字就換
一個指紋的話，F23 的永久去重會在第一次改文案時失效。

**處理順序固定**（00A §6.9，與 P51 的 UPDATE 相同）：

```text
step_indexes == ()  -> None（NO_STEP，F24）
evidence_of         -> 跨類別或有缺漏 -> ContentError
_guard              -> 指紋不符／未接受 -> CoordinationError；已產完整版 -> None（F23）
基底核對            -> 不是該篇最近已發布的版本 -> ContentError
acquire_lease       -> 拿不到 -> TransientError（交 ASL Retry，不自行迴圈等待）
選規則 -> 配版號 -> 模型（或重用）-> 程式核對 -> validate -> create_version -> verify
release_lease（finally）-> RefinePlan
```

**「已產版」用 `verify_version_complete` 判斷，不是 `status`。** 狀態只說流程走到哪，
產物齊不齊要看 S3 全文、VERSION item、STEP 與三種邊。`record.version_id` 有值但不完整
代表上次寫到一半，要沿用同版號與 `record.model_output_refs[-1]` 補齊，**不再呼叫 Writer**。

**只算本次注入的規則。** `_rules_for_hits` 先取命中步驟的 `step.type`，再用 P19 的
`rules_for_content`（回 **dict**，D-03）挑 active 規則。`select_active_rules` 每個型態最多
回一條，所以 `rules_applied` 的上限是「命中步驟的不同型態數」，不是所有 active 規則；
未改動步驟的規則與 candidate／retired 一律不入選（F29、`APL` Rule 2）。

**四種越界改寫都在 `create_version` 之前擋掉**，所以被拒的改寫不留半個產物：漏回命中步驟、
多回未命中步驟（兩者都由「改寫集合 != 命中集合」擋）、改 `feature_id`／`type`、新文字
strip 後為空。`_assert_unchanged` 再逐欄 `model_dump()` 比對未命中步驟與四個段落，
`zip(..., strict=True)` 讓「步驟數量變了」也是錯誤。

**lease 的語氣。** scope 逐字 `TUTORIAL#<slug>`（`LEASE#` 前綴由 P11 自己補）；`now` 取
`record.updated_at`（**本計畫選擇**：深層程式不讀系統時鐘，00A §3.5，與 P51 用 `now_utc()`
不同是刻意的）。拿不到就丟 `TransientError` 交 ASL 有限重試，**不自行迴圈等待**；
`release_lease` 放在 `finally`，所以改寫失敗也不會鎖死這一篇。

## 5. 遇到的問題與解法

1. **`prompt_refine_steps` 的 `diagnosis` 參數會造成循環 import。** 00A §6.9 的簽名要求
   收 `diagnosis`，但 `DiagnosisResult` 住在 `pipelines/feedback.py`，而該檔 import
   `writing/prompts.py`。P47／P50／P51 的做法是改成只收字串與既有模型物件，但那會偏離
   00A 的簽名。解法：在 `prompts.py` 定義 module-private 的 `_Diagnosis` Protocol（兩個
   唯讀屬性），簽名維持 00A 原樣，執行期沒有 import 成環，mypy strict 也過。

2. **`repo.get_version(...)` 與 `repo.get_object(...)` 都回 `T | None`。** 直接取 `.slug`
   與 `.decode()` 會被 mypy strict 擋下（`files = ["src", "infra"]`）。兩處都先擋 `None`
   再用，並各自丟看得懂的 `ContentError`。

3. **單元測試需要一整片 `Repository` 行為。** Phase 文件把 `world.repo` 畫成手寫記憶體
   fake，但 `create_version`／`verify_version_complete` 會用到 `put_meta`／`put_edge`／
   `scan_entity`／`query_by_target`／S3 條件寫入／`_missing_parts`。改用 moto ＋ 真
   `Repository` 子類（比照 `tests/unit/test_publisher_single.py`），只加三個觀察鉤子。
   踩到的坑：表要宣告 `by_target` GSI，否則 `list_feedback_of_version` 讀不到回饋。
   已獲 controller 同意。

4. **真實表上的測試要能重跑。** operation id 由指紋決定，用固定識別碼的話第二次執行會
   撞到同一筆 `OPS#`（已完整）而回 `None`，測試就失去意義。解法：`TKB_P46_RUN_TAG`
   （未設時用隨機 8 位十六進位）參與 slug／Feature／Feedback ID／project，每次執行都是
   一組全新的 demo 資料，斷言的仍是「同一次執行內同 operation 重送」這件事本身。

5. **重送重用的語意比想像的嚴格。** 見 §3 Task 3 的紅燈註記：模型輸出在呼叫後**立刻**
   保存（在業務驗證之前），所以不合格的輸出會被釘住，同 operation 重送必然再次失敗。
   這是設計要的（`ContentError` 走 Catch 不重試，要重跑得換證據＝換指紋＝換 operation），
   已寫進 Phase 文件 §11 的「本計畫選擇」第 3 則。
