```python
LEGAL_STEP_TYPES = frozenset(StepType)          # frozenset[StepType]

```

私有輔助三支：`_section_problems`、`_feature_problem`、`_step_problems`，另有模組常數 `_FEATURE_SPLITTERS = (",", "、", ";", "/", "+", " and ")`。

### 驗證邏輯（順序即 Phase 文件 §6 的流程圖）

1. `_section_problems`：`title`／`problem`／`expected_outcome` 去空白後為空 → 收「缺少 Title / Problem / Expected Outcome」；`prerequisites` 沒有任何非空白項 → 收「缺少 Prerequisites（沒有前置條件時請寫「無」）」；`steps` 為空 → 收「缺少 Steps」並**提早返回**（唯一的提早收斂：沒有步驟時繼續往下只會印出「1 到 0 的連續整數」這種看不懂的話）；`[step.number for step in steps] != list(range(1, n+1))` → 收「步驟編號必須是 1 到 n 的連續整數，實際是 [...]」。
2. `_step_problems`：以 `enumerate(content.steps, start=1)` 的**位置**當步號（不是 `step.number`，因為編號本身可能已經壞掉），逐步檢查 `text` 非空、`step.type in LEGAL_STEP_TYPES`，再問 `_feature_problem`。
3. `_feature_problem`：`strip()` 後為空 → 「第 i 步沒有引用 Feature」；**先比對 `known_feature_ids`，命中就直接合格**；比不到才看 `_FEATURE_SPLITTERS`，含分隔符號 → 「第 i 步引用了多個 Feature：<值>」，否則 → 「第 i 步引用的 Feature 不存在：<值>」。這個順序讓名稱真的含 `/` 的既有 Feature（`Import/Export`）仍然通過，只有「查無此 Feature 而且長得像兩個」才報多引用。
4. `validate_content`：兩組問題**合併**後才判斷（`problems.extend(...)`），有任何一句就丟 `ContentError("教學內容驗證失敗：" + "；".join(problems))`，無問題回 `None`。

### 三個刻意的取捨

- **一次列完所有問題。** Phase 18 只允許一次修正（設計 §14.3），五段有問題就先丟出會把那唯一一次機會浪費在最前面的小問題上，步驟引用的問題要等下一輪，而下一輪不存在。
- **訊息不帶 `step.text` 全文。** 這段訊息會被 Phase 18 原樣送回模型、也會落進操作紀錄；帶全文等於讓使用者原始回饋沿著錯誤路徑外流。訊息只含段落名稱、步驟編號與 `feature_id`。
- **驗證器不是修正器。** 缺 Feature 不自動補、多引用不自動取第一個（D05）；函式不讀 DynamoDB、不呼叫模型、不寫檔案、不修改 `content`（`TutorialContent` 本身是 `frozen=True`，結構上也改不了）。

### 測試側（`tests/unit/test_validate_content.py`，14 個案例）

- fixture `known_feature_ids` → `frozenset({"Prepare", "Share Summary", "Notification Settings"})`。
- helper `four_step_content(...)`：keyword-only override `title`／`problem`／`prerequisites`／`expected_outcome`／`numbers`／`step2_feature`／`step3_feature`／`step4_feature`／`step3_type`／`step3_text`；`numbers` 決定實際步數，`numbers=()` 就是「`steps` 為空清單」那個邊界。
- helper `_step(...)`：**先用一般建構式，`ValueError` 才退回 `model_construct`**。pydantic v2 的 `ValidationError` 是 `ValueError` 子類、`StepType("scroll")` 也丟 `ValueError`，所以一個 `except` 就涵蓋「schema 擋得住」的全部情況（已用 `issubclass(ValidationError, ValueError)` 實測確認）。`TutorialContent` 同法。這讓 `problem="  "`、`numbers=[1,2,4,5]`、`feature_id=""`、`type="scroll"` 這些會被 Phase 03 擋下的值仍能抵達 `validate_content`，紅燈才不是 `ValidationError`。

## 5. 遇到的問題與解法

1. **不合格變體會停在 `ValidationError`，證明不了第二道防線。** Phase 03 的 `bare_id`／`filled`／`StepType`／`contiguous_steps` 已經擋掉大部分測試輸入。解法照 Phase 文件 §7：helper 先試一般建構式，`ValueError` 才退回 `model_construct`；先實測 `issubclass(pydantic.ValidationError, ValueError) is True` 才敢只寫一個 `except`。
2. **測試 helper 一度用 `TutorialContent(**fields)` 需要 `# type: ignore[arg-type]`。** 雖然 mypy 只吃 `src`／`infra`，仍改成具名參數兩段寫法消掉消音註解，維持「全專案無 type: ignore」。
3. **跑全套時撞到別的 agent 進行中的檔案。** 期間 `tests/integration/test_github_webhook_handler.py`（P30 `handlers/`）與 `tests/unit/pipelines/test_asl.py`（P29）出現 `ModuleNotFoundError`，依 COMMON 規則用 `--ignore` 跳過並記錄、不去修（當時 392 passed / 23 skipped）。**寫報告前重跑，對方已落地，全套 415 passed / 23 skipped、無需 `--ignore`。**
4. **`step.type` 在訊息裡的字面。** `StepType` 是 `StrEnum`，Python 3.12 的 `f"{StepType.READ}"` 給 `read`（不是 `StepType.READ`）；繞過 schema 的裸字串 `"scroll"` 也原樣印出，訊息兩種來源都可讀。

## 9. 未完成／疑慮

1. **`_FEATURE_SPLITTERS` 是本 Phase 的選擇，不是規格**（Phase 文件 §6.4 已載明）。名稱含 `,`／`、`／`;`／`/`／`+`／` and ` 而**尚未建立成 Feature** 的情況會被報成「引用了多個」。正確做法是先建立／更名該 Feature，或改成明確的清單欄位；**不得**為了讓測試變綠而放行零個或多個引用（D05）。已建立的含分隔符號名稱不受影響（清單命中優先，`Import/Export` 有測試把關）。
2. **`_step_problems` 用位置當步號**，所以編號壞掉時訊息裡的「第 i 步」是位置序，不是 `step.number`。這在編號不連續時同時會有「步驟編號必須是 1 到 n 的連續整數」那句，兩句合看不會誤導；若日後 P22 想用 `number` 對齊使用者看到的 Markdown 行號，要一起改訊息與測試。
3. **無 integration 測試**：本 Phase 是純函式，Phase 文件與 00A §3.2 都只指定 `tests/unit/test_validate_content.py` 一支，未新增 `@pytest.mark.aws` 測試。
4. **`prerequisites` 的「至少一項非空白」是本實作對「五段齊全」的解讀**（照 Phase 文件 §7 Task 1 Step 3 的程式碼逐字採用），訊息附帶引導「沒有前置條件時請寫「無」」。P22 `render_markdown`／`parse_markdown` 若允許空的 Prerequisites 區塊，兩邊要對齊。
