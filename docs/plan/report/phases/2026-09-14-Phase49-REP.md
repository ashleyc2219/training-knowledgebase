controller 預建的檔案原本只有 docstring。本 Phase 用 `Edit` 在檔內追加一個區段，**不碰

公開名稱（與 00A §6.9 逐字核對過）：

| 名稱 | 簽名 | 作用 |
|---|---|---|
| `FEATURE_MATCH_THRESHOLD` | `float = Thresholds().cosine_match` | 語意採用線；`Thresholds.cosine_match` 的**別名**，本檔沒有第二份 `0.85`（D-35） |
| `LOCATE_QUERY_NODE` | `str = "locate_feature_query"` | 語意層「查詢那一次」的 `node` |
| `LOCATE_CANDIDATE_NODE` | `str = "locate_feature_candidate"` | 語意層「每個候選一次」的 `node` |
| `normalize_feature_name` | `(value: str) -> str` | `strip()` ＋ `casefold()`；只用於比對，不寫回圖譜。**P50 會 import** |
| `locate_feature` | `(release: Release, *, repository: Repository, writer: Writer, operation_id: str) -> Feature \| None` | 三層定位 |
| `update_feature_aliases` | `(feature: Feature, *, old_name: str, new_name: str, repository: Repository) -> Feature` | 改名收尾，全有或全無 |

模組私有輔助：`_lookup_keys`、`_all_features`、`_names_of`、`_normalized_match`、`_semantic_match`。

**定位邏輯（`locate_feature`）**——固定三層，前一層命中就不進下一層，目的是「能不呼叫模型
就不呼叫」（設計 §10）：

1. **第 1 層｜完全相同字串。** 依 `_lookup_keys(release)` 的順序（`old_name` → `feature` →
   `new_name`，用**原字串**去重）逐一呼叫 Phase 27 的
   `Repository.find_feature_by_name_or_alias`。它在「同一個字串命中兩個 Feature 的 alias」
   時丟 `PermanentError`（D07），本 Phase **原樣往上拋**，不吞、也不改判成 `None`。
   `old_name` 排最前面，是因為圖譜保存的是改版**之前**的名稱。
2. **第 2 層｜正規化比對。** `_all_features` 用 `scan_entity("FEATURE", consistent=True)` 一致
   讀取整張表，先濾掉 `SK != META` 再 `item_to_model`（邊沒有模型欄位，直接餵會整筆
   `ValidationError`），結果依 `feature_id` 升序。查詢鍵與候選的 `name ＋ aliases` 都過
   `normalize_feature_name` 之後比對；同一個正規化名稱對到兩個 Feature 一律 `PermanentError`。
3. **第 3 層｜語意定位。** 查詢鍵用 `" / ".join(keys)` 算一條向量（`node=LOCATE_QUERY_NODE`），
   每個候選用 `" / ".join([name, *sorted(aliases)])` 各算一條（`node=LOCATE_CANDIDATE_NODE`），
   以 Phase 16 的真 `cosine` 比分。候選已排序 ＋ 嚴格 `>` 比較 ⇒ 同分固定取 `feature_id`
   最小者。最高分 `>= FEATURE_MATCH_THRESHOLD` 才採用（F15），否則回 `None`。
   **候選為空時直接回 `None`**，連查詢那次 `embed` 都不算（本計畫選擇，見 §6）。

回 `None` 是**合法業務結果**：呼叫端以 KEEP 結束，不改版、不建立 Feature，這條路徑永遠不會
產生新的 Feature 主鍵（D06）。

**改名收尾（`update_feature_aliases`）**——一次全有或全無：

1. `new_name` / `old_name` 先 `strip()`；任一為空就是呼叫端接錯線，直接 `PermanentError`
   （`changed` / `removed` 沒有兩個名稱可搬，本函式只在 `renamed` 流程末端被叫）。
2. 組出目標 `aliases = sorted((舊 aliases + old_name) - new_name)`。移除 `new_name` 用
   `normalize_feature_name` 比對，所以 `prepare` 這種只差大小寫的舊別名也會一併移掉，
   結果不會違反 `Feature` 的「別名不得等於現名」不變量。
3. **先檢查、再寫入**：把「新名稱 ＋ 全部目標別名」的正規化集合，與**其他每一個** Feature 的
   `name ＋ aliases` 比對，任何一個撞到就 `PermanentError`（D07），`update_meta` 呼叫次數為 0。
   順序不能換——先寫再檢查會留下「name 已改、alias 撞名」的半套資料。
4. 全部通過才 `repository.update_meta(pk, {"name": ..., "aliases": ...},
   expected_revision=repository.revision_of(pk))`。`expected_revision` 的唯一取值來源就是
   `revision_of`（Phase 06 §5）：item 上的欄位叫 `_revision`、`get_meta` 會濾掉它，不得自己
   挖 item 湊一個。
5. 回傳 `feature.model_copy(update={"name": display, "aliases": aliases})`。pydantic v2 的
   `model_copy` **不重新驗證**，所以值在上面就已經 `strip` 過。**`feature_id` 沒有被更新，
   PK 因此完全不變（D06）。**

## 5. 遇到的問題與解法

### 5.1 共用檔 import 區塊被切成兩段 → `ruff` E402／I001

P50 在同一支 `release.py` 上把自己的 import 放在 `# ---- Phase 50 ----` 註解**之後**。我把
Phase 49 的 import 加在自己的區段時，ruff 先報 6 條 `E402`（module level import not at top of
file），移到檔首之後又報 `I001`（ruff 把註解中間的 import 視為**同一個** block，整塊未排序）。

**解法**：把兩段 import 合併成檔首**單一排序 import block**，P50 的
`# ---- Phase 50 ----` 註解跟著它的 `@dataclass` 一起往下移。這是 import 區塊本來就共用的性質
（COMMON.md R3.2「要加 import 就用 Edit 插單行」），我沒有動 P50 任何一行**程式**、沒有改名、
也沒有對既有檔跑 `ruff format`。→ **要請 controller 知會 P50**（§9）。

### 5.2 邊界值 `0.85` 會不會被浮點推過門檻

`cosine` 是 `dot / (norm_left * norm_right)`，用一般整數種子構造 `0.8499` 很容易變成
`0.84990000000000003`。改用文件建議的「單位向量」技巧並**先實測**（§3.0）：查詢
`[1.0] + [0.0]*1023`、候選 `[s, sqrt(1-s²)] + [0.0]*1022`，`0.85`／`0.8499`／`0.90` 三個值
算出來都是精確的 `s`。

### 5.3 mypy strict 擋下 `list[str]` → `list[DynamoValue]`

`Repository.update_meta(changes: Mapping[str, DynamoValue])`，而 `list` 是不變的，所以
