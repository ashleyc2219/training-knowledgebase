### 1.2 `demo/seed_loader.py`

五段，職責分得很開：

1. **讀檔與 schema**（`load_seed`）。十份檔案按固定順序讀，逐筆用 Phase 03／04 的
   `StrictModel` 解析（`extra="forbid"`，多一個欄位就爆），pydantic 的 `ValidationError`
   一律轉成 `ContentError`。接著 `_reference_problems(bundle)` 做引用完整性：
   `current_version`／`supersedes`／`slug`／`rules_applied`／回饋與瀏覽的 `tutorial_version`／
   規則證據與 `derived_from`／批次的前後版本，還有「兩個核定批次不得共用任何 `version_id`」。
   五段內容用 Phase 23 的 `validate_content` 驗（步驟零個或兩個 Feature 就在這裡被擋下，
   **不另寫一套**）。`seed_digest(directory)` 是十份檔案的 SHA-256，維護者簽名時填進
   `seed_commit`；它**不含** `approvals/` 與兩份產物，否則簽名會讓自己失效。
2. **重算**（`verify_recipe`）。八個 `RecipeCheck`，期望值寫在 `RECIPE_TARGETS`，
   **實際值一律從 `bundle` 的原始資料現算**：`average_rating`／`negative_feedback_ids`（P53）與
   `reopen_stats`（P54）。`RecipeReport.o7_ready = schema_ok and recompute_ok and not missing_approvals`。
3. **寫入**（`apply_seed`）。順序：Feature → Tutorial → 版本 → Release → Feedback（外加
   `REFERS_TO` 邊）→ View → Ticket → Rule。版本走 Phase 23 的 `create_version`（全文、diff、
   VERSION item、`REFERENCES`／`SUPERSEDES`／`APPLIED_TO` 邊、自我核對），再用 Phase 06 的
   compare-and-swap 補上模擬 `published_at`（`create_version` 依 D25 永遠不寫它），最後再呼叫一次
   `verify_version_complete`。已存在且完全相同的版本直接跳過，所以可以重跑。
4. **分群**（`cluster_demo_tickets`）。逐筆 `ensure_embedding` → `assign_cluster`（P38），
   每筆算完立刻寫回 `cluster_id`，下一筆才比得到已成形的群中心。**沒有任何「模型不可用就預填」的分支。**
5. **CLI**（`main`）。`python -m demo.seed_loader verify <目錄>`。

## 5. 遇到的問題與解法

1. **`import demo` 在 pytest 下不成立。** 專案根不在 `sys.path`。照 Phase 文件 §4 的建議，在
   `[tool.pytest.ini_options]` 加 `pythonpath = ["."]`（pytest 8 內建），而不是在七支測試檔各抄一次
   `sys.path.insert`。`packages.find where = ["src"]` 沒有動。

2. **`list_feedback_of_version` 回 0 筆。** 第一次跑 moto 整合測試時八個版本都 `verify_version_complete`
   通過，但指標一筆回饋都掃不到。原因是那個查詢走 `by_target` GSI 找
   `FEEDBACK#<id> --REFERS_TO--> VERSION#<id>` 的邊，而 `put_meta` 只寫 metadata item。
   解法是在 `apply_seed` 補上與 `ingress._complete_feedback` **同一條** `put_edge`，不是另寫查詢。

3. **空字串會被 `evaluate_batch` 當成「已核定」。** §6.6 要求 `batches.json` 的
   `approved_by`／`approved_at` 留空字串，但 P55 的 `_batch_problems` 判的是 `is None`。
   解法：`load_seed` 把空字串讀成 `None`，批次的核定值**只從 `approvals/<batch_id>.json` 讀**，
   而且四個欄位都非空 ＋ `seed_commit` 對得上才算數。
