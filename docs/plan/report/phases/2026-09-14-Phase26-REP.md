### 1.1 `src/training_kb/content.py`（檔尾追加第 9 段，約 120 行）

只在檔尾追加一段「教學退役與後繼導向」，**沒有重排、沒有改任何既有簽名**；既有 import
區塊只是加名字（`datetime`、`to_iso`、`IngressError`／`PermanentError`／`TransientError`、
`tutorial_pk`、`Tutorial`／`TutorialStatus`、`DynamoValue`），沒有刪除既有匯入。

| 成員 | 行為 |
|---|---|
| `RETIRED_NOTICE` | `"此教學已退役，內容僅供歷史查閱。"`。**公開頁唯一的過期說明**，字面值全專案只有這一處（00A §6.6）；P57 的完整退役頁 `from training_kb.content import RETIRED_NOTICE`。 |
| `resolve_successor(slug, successor, *, repository)` | 四項檢查固定順序，任一關不過回 `None`、**不丟例外**。 |
| `retire_tutorial(slug, *, reason, successor, repository, now)` | 只改 `TUTORIAL` metadata 的 `status` 與 `successor`，回傳寫入後重讀的 `Tutorial`。 |
| `assert_accepts_feedback(tutorial)` | `status == retired` 時丟 `IngressError(..., fields=("tutorial_version",))`，否則什麼都不做。 |

**`resolve_successor` 的判準**（設計 §8.4）：

```text
successor is None 或 == slug -----------> None   自我導向讓讀者原地打轉
repository.get_tutorial 查不到 ---------> None   壞連結
target.status != TutorialStatus.ACTIVE -> None   已退役的後繼只會再推一次
target.current_version is None ---------> None   沒有已發布版本＝讀者看不到內容
沿 target.successor 走到 visited 裡的節點 -> None 形成循環
否則 -----------------------------------> successor
```

鏈走訪用 `visited = {slug, successor}` 而不是固定跳數上限：`visited` 直接描述「不形成循環」，
也順便擋掉 `A -> B -> C -> B` 這種**不含起點**的環。走到 `None` 停；中途節點查不到也回 `None`
（鏈斷了就無法證明它不成環，不放行比較安全）。**回 `None` 不是失敗**——F19 明訂無合法後繼
仍要完成退役。

**`retire_tutorial` 的寫入範圍**：

| 欄位／物件 | 動作 |
|---|---|
| `status` | 設為 `TutorialStatus.RETIRED.value`（純 `str`，與 `model_dump(mode="json")` 同型別）；已是 `retired` 時不重寫。 |
| `successor` | **只在目前為空且新解析結果合法時寫入**；已有值時一律保持原值（改後繼是維護者的另一次明確決定）。 |
| `current_version` | 不動。 |
| `VERSION`／`STEP`／S3 `.md`／`.diff`／既有 `FEEDBACK` 與邊 | **完全不碰**。 |

`reason` 與 `now` 只做驗證：`reason` 去頭尾不可為空（否則 `PermanentError`），`now` 交給
`to_iso` 擋掉 naive datetime 與帶微秒的時間。兩者都**不寫進 item**——`Tutorial` 是嚴格模型
（00A §3.6、D-40），多塞 `retired_at`／`retired_reason` 會讓下一次 `get_meta` 直接
`ValidationError`；實際紀錄由 P52 寫進 `operations/<operation_id>/retire.json`。

`changes` 為空時**完全不呼叫 `update_meta`**，這就是冪等：連退兩次不多花一次條件寫入，
也不把 `_revision` 往上推去害正在讀的人白白失敗一次。

`expected_revision` 取自 `Repository.revision_of(pk)`（D-27，owner 是 P06，本 Phase 只消費）。
條件不成立時 `update_meta` 丟 `CoordinationError`，這裡**轉成 `TransientError`** 交給 P29 的
單層 ASL Task Retry，不靜默覆蓋別人的修改、也不自己迴圈重試。

## 5. 遇到的問題與解法

1. **`FakeTable` 需要 `update_item`。** Phase 27 的假表只有四個讀寫操作，沒有 `update_item`，
   而本 Phase 的核心寫入就是 `update_meta`。解法是照 `update_meta` 實際送出的形狀實作
   （`UpdateExpression` 固定是 `"SET " + ", ".join("#fN = :vN")`、`ConditionExpression` 固定是
   `#revision = :expected`），任何別的形狀直接 `AssertionError`。這樣 `update_meta` 的保留屬性
   守門與 CAS 都跑真程式，「第二次退役零次條件寫入」才是被真的計數驗出來的。
2. **怎麼製造 revision 不符而不作弊。** 沒有 monkeypatch `revision_of`（那等於自己餵答案），
   而是在假表加一個 `bump_before_update` 開關：`update_item` 在**比對條件之前**把 `_revision`
   加一，等於「別人在我讀完 revision 之後、寫進去之前改了這一篇」的真實交錯。
3. **`to_iso` 對 naive datetime 丟的是 `ValueError` 不是 `PermanentError`。** `clock._aware`
   丟 `ValueError`，只有「帶微秒」才丟 `PermanentError`。Phase 文件只寫「拒絕」，測試按實際
   類別斷言，並把這個區別寫回文件。
4. **`site.py` 的 `RETIRED_PLACEHOLDER` 與 `RETIRED_NOTICE` 撞名。** P24 先放了一份同值的佔位
   常數。直接刪掉會違反「守門不得移除 P24 既有公開名稱」，兩份字面值並存又會讓改字漏掉一邊。
   解法是把 `RETIRED_PLACEHOLDER` 變成 `RETIRED_NOTICE` 的別名，字面值只留 `content.py` 一處。
5. **Task 1 綠燈被 Task 2 的 import 擋住。** 測試檔一開始就同時 import 兩個函式，Task 1 的最小
   實作落地後仍然紅在 `cannot import name 'retire_tutorial'`。把 Task 1 的 import 收斂成只有
   `resolve_successor`，Task 2 Step 1 再加回去——這正好就是 Phase 文件 Task 2 Step 2 預期的紅燈
   訊號，兩個 Task 的紅→綠因此各自獨立可觀察。

## 9. 未完成／疑慮

1. **公開站的人工驗收延後。** Phase 文件 §8 要求「用公開 URL 實際點一次後繼連結確認可讀」。
   本 Phase 不寫 `site/`、公開站也還沒真實部署（controller 的離線開發裁決），這一項與 P41 起的
   真實接線一併延後。目前只有「href 逐字是 `../<successor>/index.html` 且頁面無絕對網址」這條
   自動化斷言。
2. **後繼連結印的是 slug 不是 topic。** 這是 renderer 簽名不變（00A §6.7）＋ renderer 不碰儲存層
   的必然結果，已寫回 Phase 文件。若 P57 要改成人看得懂的標題，得在 P57 自己讀一次後繼的
   `Tutorial`；那是 P57 的實作自由，不需要改本 Phase 的任何簽名。
3. **退役頁何時真的上線，由 P52 決定。** `retire_tutorial` 回傳之後，公開站上那一篇的 HTML 還是
   退役前的版本。P52 若沒有接著走 P24／P25 的發布路徑重寫，讀者就看不到退役提示。本 Phase 已在
   §7 的介面表與 Phase 文件 §全域限制寫明，但**沒有**測試能證明 P52 真的會這麼做。
4. **鏈中間節點查不到時一律回 `None`。** 嚴格說「鏈斷掉」不等於「成環」，這是刻意選的保守解：
   無法證明不成環就不導向。若之後資料上出現大量 dangling successor，這個判準會讓合法的後繼被
   誤拒——但在 MVP 的教學數量下不會發生，也比把讀者推到壞連結安全。
5. **`FakeTable` 的 `update_item` 只認 `update_meta` 目前的表達式形狀。** 這是刻意的（形狀一變就
   `AssertionError`，而不是默默放行），但代表 P06 若改寫 `update_meta` 的表達式，本檔的假表要
   跟著改。整合測試 `test_retired_feedback_rejected.py` 用的是 moto 真表，不受這個限制。
