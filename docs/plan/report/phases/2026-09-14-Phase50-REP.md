同一支檔 P49 是 owner，本 Phase 只用 `Edit` 追加自己的區段，沒有動 P49 的任何一行程式。
**唯一碰到別人行的地方是檔首那一個 import block**：P49 為了過 `ruff` 的 E402／I001 把 import
合併成單一排序區塊，所以本 Phase 需要的名稱只能加進同一個區塊（散開會被 isort 判成未排序）。
實際只做兩件事：既有三行各多一個名稱（`Iterator`、`ContentError`、`ReleaseKind`／`Tutorial`／
`TutorialStatus`／`TutorialStep`），另外新增兩行（`prompt_safety_net_confirm`、`StepConfirmation`）。
沒有重排、沒有 `ruff format`。

交付四個公開名稱與三個私有 helper：

| 名稱 | 說明 |
|---|---|
| `StepHit(slug, version_id, number)` | frozen dataclass，欄位順序照 00A §6.9。frozen 才進得了 `set`，呼叫端才能做 `set(direct) \| set(net)`。 |
| `find_release_hits(feature_id, *, repository)` | **只有五行**：呼叫 P27 的 `find_current_published_steps_referencing`，用 P20 的 `parse_version_id` 取 `slug`，去重後依 `(slug, number)` 升序回 tuple。沒有第二份 `query_by_target` 篩選（D-38）；P27 的 `PermanentError` 原樣往上拋。 |
| `needs_safety_net(release, feature, hits)` | 純函式：`hits` 為空就觸發；否則只有 `release.kind is ReleaseKind.RENAMED` 且 `old_name` 正規化後不在 `feature.name`／`aliases` 裡才觸發（F16）。不碰 `Repository`／`Writer`，所以「要不要花錢」這一步本身零成本。 |
| `SAFETY_NET_CANDIDATES = 5` | 候選預算（最多五個步驟 → 最多五個版本 → 最多五次確認呼叫）。不是 cosine 門檻。 |
| `safety_net(release, *, repository, writer, operation_id)` | 補漏路徑，見下方流程。 |
| `_current_published(repository)` | 每篇 **active** 教學的 `(slug, current 已發布 version_id)`，依 slug 升序。 |
| `_release_names(release)` | `feature` → `old_name` → `new_name` 去重後的 tuple；查詢向量與 prompt 的 `<change>` 都用它。 |
| `_score_steps(...)` | 查詢向量一次 + 每個目前已發布步驟一次 `embed`，排成 `(-score, slug, number, version_id)` 後 `sort()`。 |

`safety_net` 的流程：

```text
embed(改版名稱)                     -> 1 次（node=safety_net_query）
每個目前已發布步驟 embed + cosine    -> N 次（node=safety_net_step）
取前 SAFETY_NET_CANDIDATES=5 名     -> 依 version_id 分組
每組一次 prompt_safety_net_confirm + generate_json（node=safety_net_confirm）
  reason 去空白後為空               -> ContentError（設計 §7.4，不降級成 KEEP）
  confirmed_step_numbers 不在該版    -> 丟棄、不重問（P18 對照表：StepConfirmation 不走 correction）
回 tuple[StepHit, ...]，依 (slug, number) 升序；零確認就是 ()
```

判斷類模型參數**不在本 Phase 決定**：`generate_json` 拿到的 schema 是 `StepConfirmation`，
P18 的 `inference_config(schema)` 用 `$id` 查表，`StepConfirmation` 不在 `WRITING_MAX_TOKENS`
裡，所以落在判斷類預設 `maxTokens` 512、`temperature` 0.1（00A §3.7）。本 Phase 沒有、也不該
自己傳一份參數。

    slug: str

def find_release_hits(feature_id: str, *, repository: Repository) -> tuple[StepHit, ...]: ...

def prompt_safety_net_confirm(version_id: str, steps: Sequence[TutorialStep],

使用約定（P51／P52 請照這個接）：

- 兩個查詢函式都回 `tuple[StepHit, ...]`，依 `(slug, number)` 升序，重跑 byte 相同；

  自己先反查，也永遠不會刪掉明確命中；它回 `()` 就是「補漏沒有結果」，依 F18 記未命中並 KEEP。

- `safety_net` 會丟 `ContentError`（模型回的 `reason` 空白），它是 `PermanentError` 子類。
- node 名稱：`safety_net_query`、`safety_net_step`、`safety_net_confirm`（P52 的 ASL Task 名仍是
  `find_steps`／`safety_net`，兩層不得互換，D-51）。

## 9. 未完成／疑慮／建議 controller 裁決

1. **退役教學在兩條路徑上的行為不一致（建議 controller 裁決）。**
   `find_release_hits`（＝P27 的反查）**會**回退役教學 current 已發布版的步驟，因為
   `retire_tutorial` 保留 `current_version` 與 `published_at`、而 `_is_current_published` 不看
   `status`；本 Phase 自己寫的 `safety_net._current_published` **會**排除退役教學。
   兩邊的取捨我在程式與文件都寫明了，但**真正該修的地方是 P27 或 P52**：如果業務上「退役教學不
   應該被改版」，應該在 `Repository.find_current_published_steps_referencing` 或 P52 的
   `task_find_steps` 過濾，而不是在 P50 的包裝層偷加一層（那會違反 D-38）。本 Phase 不動它。
