在 `src/training_kb/content.py` 追加三節（§5 Markdown 全文、§6 unified diff、§7 私有 key 與

| 名稱 | 形狀 | 邏輯 |
|---|---|---|
| `PRIVATE_TUTORIAL_PREFIX` | `"tutorials/"` | 00A §3.4 |
| `PUBLIC_SITE_PREFIX` | `"site/"` | 00A §3.4 |
| `escape_markdown(text)` | `str -> str` | 兩層轉義：行內符號 `` \ ` * _ [ ] < > # \| ( ) `` 逐字加反斜線；再處理只有在行首才有意義的 `-`、`+` 與「數字後接句點」。 |
| `unescape_markdown(text)` | `str -> str` | 只把反斜線後的下一個字元原樣取出（`re.sub(r"\\(.)", r"\1", …)`），**不看被轉義的是哪個字元**，所以日後改 `_MD_SPECIALS` 也不會讓舊全文解錯；結尾落單反斜線丟 `ContentError`。 |
| `render_markdown(content)` | `TutorialContent -> str` | 五段固定樣板，區塊間恰好一個空行、檔案以一個換行結尾。 |
| `parse_markdown(markdown)` | `str -> TutorialContent` | `render_markdown` 的精確反函式；缺區塊、壞步驟行、模型層限制一律 `ContentError`。 |
| `make_diff(prev, cur, *, previous_name, current_name)` | `str \| None, str -> str` | `difflib.unified_diff` + `lineterm=""`；`prev is None` 回 `""`（F50 選 C）。 |
| `markdown_key(slug, number)` / `diff_key(slug, number)` | `-> str` | `tutorials/<slug>/v<n>.md`／`.diff`。 |
| `put_private_artifact(repository, key, text, content_type)` | `-> None` | 只允許私有前綴；`put_object(..., if_none_match=True)`，412 才比對 bytes。 |

實作邏輯的四個關鍵決定：

1. **轉義與反轉義嚴格一對一。** `escape_markdown` 只「插入」反斜線，不改寫、不刪字；
   `\` 自己也在 `_MD_SPECIALS` 裡先被加倍，所以原文裡真的寫著 `\<` 的情況不會與轉義產物混淆。
   `unescape_markdown` 因此對**任何**字串滿足 `unescape(escape(x)) == x`，測試用 11 個
   參數化案例（含空字串、`+ 也是清單`、`(type=read, feature=X)`、`反斜線\`）鎖住。
2. **每個欄位只有一行。** `_one_line(label, value)` 先拒絕 `\n`／`\r`（`feature_id` 另外拒絕括號），
   再轉義。這讓 `_STEP_LINE` 的 `([^)]*)` 沒有歧義，也讓 diff 的最小變更單位就是「一步」。
3. **解析只丟 Phase 02 的錯誤。** `parse_markdown` 把 pydantic 的 `ValidationError` 轉成
   `ContentError`，訊息只帶「N 個欄位」不帶欄位值（欄位值可能是使用者原文）。
4. **只攔 `ObjectAlreadyExists`。** 用型別（D-30）而不是訊息字串分辨「同操作重送」與其他
   永久失敗；沒設定 bucket 之類的 `PermanentError` 原樣往上拋，測試直接斷言
   `not isinstance(caught.value, ContentError)`。

## 5. 遇到的問題與解法

| 問題 | 原因 | 解法 |
|---|---|---|
| `SyntaxWarning: invalid escape sequence '\ '`，`-W error` 下整檔失敗 | `escape_markdown` 的 docstring 裡逐字列出 `` \ ` * _ … `` | docstring 改成 raw string（`r"""`），並把說明中的 `` `\\` `` 改寫成「反斜線」避免再出現多餘跳脫。 |
| mypy strict：`Argument "type" to "StepDraft" has incompatible type "str \| Any"; expected "StepType"` | Phase 文件的 `parse_markdown` 寫 `type=match[2]`，但 `StepDraft.type` 宣告成 `StepType`，本專案不用 `# type: ignore` | 加 `_step_type(value) -> StepType`：不在 `LEGAL_STEP_TYPES` 就丟 `ContentError("步驟 type 不合法：…")`。**順帶補掉一個真漏洞**：`StepType("scroll")` 丟的是裸 `ValueError`（不是 `ValidationError`），照文件原碼會直接外洩給呼叫端，違反「呼叫端只認得 Phase 02 錯誤契約」。已加 `test_illegal_step_type_in_markdown_is_rejected` 鎖住，並回寫 Phase 文件。 |
| `site/tutorials/<slug>/v<n>.html` 這種公開 key 裡面也有 `tutorials/` | 00A §3.4 的公開佈局是 `site/` + `tutorials/...` | `put_private_artifact` 的守門條件 `not key.startswith("tutorials/")` 本來就擋得住（它以 `site/` 開頭），另外補一個測試 `test_public_site_copy_of_a_private_key_is_refused` 明確鎖住這個形狀，避免日後有人「優化」成 `"tutorials/" in key`。 |

1. `markdown_key`／`diff_key` 的 `slug`／`number` 會先過 `make_version_id` 守門，不合法丟
