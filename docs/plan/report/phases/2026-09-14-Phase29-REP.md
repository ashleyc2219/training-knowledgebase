## 1. 實作內容（含實作邏輯）

建立 `training_kb.pipelines` 套件，三條 Standard Step Functions（`ticket-analysis`／`release-update`／`feedback-review`）共用的 Task 執行契約與 ASL 失敗語意都在這裡。

### 1.1 `src/training_kb/pipelines/__init__.py`

只有 docstring 的套件入口，**刻意不做 re-export**：00A 第 6.9 節把 import 路徑逐字定在 `training_kb.pipelines.common` 與 `training_kb.pipelines.asl`（例如 `from training_kb.pipelines.asl import CATCH, RETRY, task_state`），只留一條路徑，下游 Phase 38／41／48／52 不會出現兩種寫法指向同一個物件。`writing/__init__.py` 會 re-export 是因為它要藏住 `client.py`，這裡沒有這個需求。

### 1.2 `src/training_kb/pipelines/common.py`

- `PipelineName = Literal["ticket-analysis", "release-update", "feedback-review"]`：只有三條，Analytics 是獨立 Lambda 不是 pipeline。
- `JSONValue = None | bool | int | float | str | list["JSONValue"] | dict[str, "JSONValue"]`：全專案唯一定義（遞迴 alias，mypy 1.20 與 Python 3.12 執行期都接受）。
- `TaskFn = Callable[[dict[str, JSONValue], "Deps"], dict[str, JSONValue]]`。
- `PIPELINE_NAMES: tuple[str, ...] = get_args(PipelineName)`：白名單由型別導出，不另手打一份字串清單。
- `Deps`（`@dataclass(frozen=True)`）：本 Phase **只有** `operations: OperationCoordinator` 與 `now: Callable[[], datetime]` 兩個欄位，docstring 標明 Phase 38 會以「修改本檔」方式追加 `repository`／`writer`／`settings`（預設 `None`）與三個 `need_*`（D-36）。
- `run_sequence(pipeline, payload, tasks, deps)`：先擋未知 pipeline 名稱與缺 `operation_id` 的 payload（都丟 `PermanentError`），再把 `payload` 複製一份依序餵給每個 Task。**自己完全沒有重試**（沒有 `for attempt in range(...)`、沒有 `time.sleep`、沒有 SDK retry 設定），重試只由 ASL 的 `Retry` 管（00A §3.7「只有一層管理重試」）。攔截用 `except Exception` 是刻意的：`PublishError`／`CoordinationError` 在 00A §4.1 不是 `PermanentError` 的子類，只攔那兩類會讓它們繞過操作紀錄；攔到之後先 `deps.operations.fail(operation_id, str(error), isinstance(error, TransientError), now=deps.now())`，再 `raise` **原例外**，不吞錯也不轉型。

### 1.3 `src/training_kb/pipelines/asl.py`

- 固定常數：`FAIL_STATE_NAME = "PipelineFailed"`、`TASK_TIMEOUT_SECONDS = 120`、`RETRY`（D-53 的兩條 retrier，逐字照 00A §3.7）、`CATCH`（一條 `States.ALL -> PipelineFailed`，`ResultPath` 是 `$.failure`）、`ASL_LOCAL_PATH = "infra/stepfunctions/{pipeline}/v{number}.json"`、`ASL_SNAPSHOT_KEY = "stepfunctions/{pipeline}/v{number}.json"`。
- `task_state(resource_arn, next_state)`：唯一的 Lambda Task 模板——**直接函式 ARN**（沒有 `arn:aws:states:::lambda:invoke` 信封，因此沒有 `Payload` 外層）＋ `TimeoutSeconds: 120` ＋兩條 `Retry` ＋一條 `Catch`。`Parameters` 封套（`pipeline`／`task`／`state.$`，D-49）刻意不產生，因為這個簽名看不到 pipeline 與 task 名稱，由 P41／P48／P52 各自補。
- `assert_safe_asl(definition)` → `_check_scope` → `_check_task`：遞迴進 `Map` 的 `ItemProcessor`／`Iterator` 與 `Parallel` 的 `Branches`，錯誤訊息帶完整 state 路徑（`AssignCluster.ItemProcessor.InnerTask`）。每個 Task 檢查三件事：前兩條 `Retry` 逐字等於 `RETRY`、沒有任何 retrier 涵蓋 `States.ALL`（那等於連 `PermanentError` 也重試）、恰一條 `States.ALL` 的 `Catch` 導向**同一層** `States` 內的 `Fail` state。另外每個 `Choice` 必須有 `Default`（Choice 沒有 Retry／Catch 是正確的）。
- `canonical_json(definition)`：`json.dumps(..., ensure_ascii=False, indent=2, sort_keys=True).encode("utf-8")`，同一份定義每次同 bytes。
- `save_asl_snapshot(repository, pipeline, number, body)`：先擋未知 pipeline 名稱，key 用 `ASL_SNAPSHOT_KEY.format(...)`，`put_object(..., if_none_match=True)`；撞到 `ObjectAlreadyExists` 時**先核對 bytes**——相同視為同一次部署重送（冪等，回同一個 key），不同就 `PermanentError`，既有快照不被覆蓋。本地檔與 S3 快照是同一份 bytes。

## 5. 遇到的問題與解法

1. **`RETRY` 淺複製會污染共用常數。** Phase 文件草稿寫 `[dict(item) for item in RETRY]`，但 `dict(item)` 只複製一層，所有 Task 會共用同一個 `ErrorEquals` list，任何一處就地 `append` 就污染全部定義——這與草稿自己的註解「要放進 ASL 時一律複製成新的 list」矛盾。改用私有的 `_copies(...)`，連 list 值一起複製；產出的 JSON 與草稿完全相同，測試斷言不受影響。
2. **`mypy --strict` 不接受草稿的裸 `dict` 註記。** `JSONValue` 是 union，`state.get("ItemProcessor")` 回來的是 union，不能直接當 dict 用。`_check_scope`／`_check_task` 的參數改成 `Mapping[str, JSONValue]`，取值後一律 `isinstance` 收斂；順帶多一條檢查：`States` 裡的值不是物件時丟 `PermanentError(f"state 不是物件：{where}")`。
3. **`_copies` 的回傳型別。** `list[dict[str, JSONValue]]` 不能塞進 `dict[str, JSONValue]`（list 是不變的），所以 `_copies` 宣告回 `list[JSONValue]`，`task_state` 與 `_check_task` 的比較都用同一個型別，mypy 才過。
4. **`save_asl_snapshot` 的 `repository` 型別。** 草稿沒有註記，strict 不接受；照 00A §6.9 註記成 `Repository`。測試用鴨子型別的 `FakeRepository`，`mypy` 的 `files` 只有 `src`／`infra` 不掃 `tests/`，兩邊不衝突。
5. **多 agent 同一個 checkout。** 中途 `uv run ruff check src tests infra` 曾因別人進行中的 `tests/integration/test_github_webhook_handler.py` 報 3 個錯（I001／F401），沒有去碰；最後一次全跑時對方已修好，整個 repo 乾淨。提交一律 `git add <我的檔案> && git commit -m ... -- <同一批檔案>`。

## 7. gate 狀態／給下一個 Phase 的介面清單

### gate 狀態

- **本 Phase 只宣稱「本機契約測試通過」。** ASL 只做靜態產生與 `assert_safe_asl` 靜態檢查，**沒有**建立 state machine、沒有部署、沒有任何雲端執行。Python Lambda 未處理例外在 Step Functions 看到的 `errorType` 是不是類別名（第一條 retrier 的 `"TransientError"` 會不會命中），**由 P41 用 `get-execution-history` 實證**，實證前不得寫成已驗證；這句話同時寫在 `asl.py` 的 module docstring 裡。
- O2 PASS、**O3 FAIL**、O5 BLOCKED 的現況不變。本 Phase 沒有啟用任何會建版或公開發布的路徑：`run_sequence` 失敗時只呼叫 `operations.fail(...)` 再往外丟，測試裡的 publish spy 呼叫次數是 0。
