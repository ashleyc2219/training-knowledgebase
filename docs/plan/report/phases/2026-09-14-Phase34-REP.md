## 1. 實作內容（含實作邏輯）

在 Phase 33 建立的 `src/training_kb/rote.py`「--- 3. 兩層命中與候選排序（Phase 34 追加）---」
段落下追加四個名稱與兩個常數，**只在該段落內追加**，沒有重排既有程式、沒有改 P33 的公開簽名。

- **`JACCARD_THRESHOLD = 0.8`**（00A §5.4 的「唯一門檻常數」表列在 P34 名下）：第二層欄位重疊度
  下限，用 `>=` 比較。程式裡只有這一份 `0.8`。
- **`PROC_MIN_SUCCESS = 3`**（**P34 首建**，P35 只 `import`）：可重放所需的最少完整成功次數
  （設計 §7.2、決策 F03）。程式裡只有這一份 `3`；docstring 明寫「P35 不得為同一個數字另取名字」。
- **`jaccard(left, right) -> float`**：`len(left & right) / len(union)`。空聯集**明確回 `0.0`**
  而不是數學慣例的 `1.0`（設計 §7.2「空集合不當成命中」）；不做 `round`，直接比較原始浮點數。
- **`replayable(proc) -> bool`**：只有兩個硬條件 `status == ProcStatus.ACTIVE` 且
  `success_count >= PROC_MIN_SUCCESS`。Layer 1 與 Layer 2 共用**同一份**判斷（決策 F03），
  「還沒滿三次」由 `success_count` 表達，不新增 `candidate` 狀態。
- **`_order_key(scored) -> tuple[float, float, str]`**：決策 F04 的三段排序鍵
  `(-score, -last_used.timestamp(), signature)`，配 `min(...)` 使用。第三個鍵是用來消除平手的；
  `last_used` 由 P04 的 aware validator 保證必填且帶時區，所以直接取 `.timestamp()`，
  **不補值、不把 naive 時間當 UTC、不用 `now_utc()` 墊檔**。
- **`pick_layer2(event, candidates) -> ProvenWorkflow | None`**：先取 `event_stable_keys(event)`
  （P33 的同一份取法，不自己再取一次 key），對候選做「`replayable` ＋同 `domain` ＋同 `adapter`」
  三重過濾，算 Jaccard 後只留 `>= JACCARD_THRESHOLD`，再用 `_order_key` 取第一個；沒有合格候選回
  `None`。即使 `list_procs(domain, adapter)` 已依範圍查詢，這裡**仍再過濾一次**，讓純函式可單獨測試，
  也不倚賴查詢層是否寫對條件（範圍定義＝決策 D19：來源網域＋adapter 類型，不看顯示名稱／email／專案）。
- **`find_replayable(event, signature, *, repository) -> ProvenWorkflow | None`**：全系統唯一的
  兩層順序——`repository.get_proc(signature)` 拿 exact item，`exact is not None and replayable(exact)`
  才是 Layer 1 命中（**不查候選清單**）；否則落到 `pick_layer2(event, repository.list_procs(...))`。
  exact 存在但 retired／成功不足時**不直接放棄**（設計 §7.2 的第二層條件是「第一層未命中」，
  決策 D20 與 Rule 20），而那筆 exact PROC 會在 Layer 2 被同一個 `replayable` 濾掉，
  所以不需要另外把它排除。docstring 明寫「P37 的 `Rote._pick_proc` 直接 import 本函式，
  不得自己再抄一次三行順序」（00A §6.8 明文要求）。

新增 import 兩行：`from collections.abc import Mapping, Sequence`（加 `Sequence`）、
`from training_kb.models import ProcStatus, ProvenWorkflow`、`from training_kb.repository import
Repository`。`repository.py` 不 import `rote`，沒有循環相依；`rote.py → adapters.py` 的單向相依未受影響。

## 5. 遇到的問題與解法

1. **Task 1 的紅燈訊號與 Phase 文件不同字**：文件預期
   `cannot import name 'jaccard'`，實測是 `cannot import name 'JACCARD_THRESHOLD'`——
   Python 報的是 import 清單裡**第一個**解析失敗的名字。不是行為差異，修文件說明即可（第 6 節第 2 點）。
2. **`pick_layer2` 與 `find_replayable` 回 `ProvenWorkflow | None`**：Phase 文件的測試片段直接寫
   `pick_layer2(...).signature == TIE_LOW`，失敗時會變成 `AttributeError: 'NoneType' object has no
   attribute 'signature'`，讀不出是「沒選到」還是「選錯」。改成先 `assert picked is not None`
   再比 `signature`，斷言內容與覆蓋範圍不變，並修文件（第 6 節第 3／4 點）。
3. **同 checkout 其他 agent 的檔案暫時壞掉**：收尾量測時 Phase 24 agent 已加入
   `tests/unit/test_publisher_single.py`，但 `src/training_kb/publishing.py` 尚未提交，
   造成 `ModuleNotFoundError: No module named 'training_kb.publishing'`（收集期錯誤）與該檔的
   `I001` lint 錯誤。依 COMMON.md「別人的檔案暫時失敗用 `--ignore` 並記錄，不去修」處理，
   未碰該檔與 `publishing.py`／`site.py`／`repository.py`。
4. **`from training_kb.repository import Repository` 會不會循環 import**：先確認
   `repository.py` 不 import `rote`，而且 `rote.py` 早就經 `pipelines/common.py` 間接載入
   `repository`，所以直接 import 沒有新增相依方向。實測 `pytest` 與 `mypy` 都通過。
5. **測試檔的 import 形狀**：Task 1 與 Task 2 的文件片段是兩個獨立的
   `from training_kb.rote import ...`，Python 合併後同模組只能有一行。先寫成括號多行，
   最後收斂成單行（94 字元，未超過 `line-length = 100`），與 `tests/integration/test_rote_lookup.py`
   及 repo 既有慣例一致（commit `bcd59da`）。
6. **00A 裁決 D-01（§5 Consumes 偽簽名的語言標記）**：檢查 Phase 34 文件的 Consumes 區塊，
   **已經是 ` ```text `**，D-01 已套用完畢，不需要再改。程式照 00A §6.8 的簽名逐字實作。
