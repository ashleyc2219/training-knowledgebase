### 1.2 十個邏輯實體與 `Entity` union

照 00A §5.1 逐欄實作，順序固定：

```text
Tutorial -> TutorialVersion -> TutorialStep -> Feature -> Ticket
-> Release -> Feedback -> TutorialView -> AuthoringRule -> ProvenWorkflow
```

```python

          | Release | Feedback | TutorialView | AuthoringRule | ProvenWorkflow)
```

實際執行結果：

```text

 'Release', 'Feedback', 'TutorialView', 'AuthoringRule', 'ProvenWorkflow']
```

### 1.3 共用 helper

```python
def aware(value: datetime) -> datetime:
    """確認時間帶時區。模型內不補 now，時間一律由呼叫端傳入（Phase 02 的規則）。"""
    if value.tzinfo is None or value.tzinfo.utcoffset(value) is None:
        raise ValueError("datetime must be timezone aware")
    return value
```

放在 `TutorialContent` 之後、十實體之前（本文件 Task 1 Step 3 片段把它畫在 `Ticket` 前，但那樣會插進 Phase 03 的 primitive 區塊）。

## 5. 遇到的問題與解法

1. **`Feedback(rating=True)` 預設會過**：`StrictModel` 依 D-69 不開 `strict=True`，pydantic 寬鬆模式把 `True` 轉成 `1`。解法照文件用 `@field_validator("rating", mode="before")` + `type(value) is not int`，在轉型前就攔下來。
2. **`aware()` 的放置位置**：文件片段把它畫在 `Ticket` 之前，但那樣要插進 Phase 03 的 primitive 區塊。改放在 `TutorialContent` 之後、十實體之前，Phase 03 的程式碼一行都沒動。
3. **`AuthoringRule.evidence` 與 `applied_to` 原本共用一個 validator**：加入「≥ 5 個不同」後兩者規則不同，拆成 `applied_to_is_bare` 與 `evidence_has_five_distinct_ids` 兩個 validator。
4. **`uv run ruff check src tests` 目前不是全綠**：兩個 `I001` 都在 Phase 14 的檔案（`tests/integration/test_o5_probe.py:18`、`tests/unit/test_check_models.py:3`），不是我的檔案，依 COMMON 規則不去修、只記錄。改用 scope 到自己檔案的 `uv run ruff check src/training_kb/models.py tests/unit/test_entities.py tests/unit/test_entity_invariants.py`（外加 Phase 01–03 的測試）全部通過。
5. **測試檔 import 排版**：文件 Task 2 Step 1 的括號單行 import 會被 `ruff I001` 判為未排版，改成既有 `tests/unit/test_model_primitives.py` 的一行一個名稱格式；測試函式本體與斷言逐字沿用。
