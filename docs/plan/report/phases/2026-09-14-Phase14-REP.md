### 1.2 實作邏輯

- **`classify_error(error)`**：從 `error.response["Error"]["Code"]` 查 `ERROR_STATUS`；查不到一律 `unknown`
  且把原始代碼留在 `detail` 裡。不是 `ClientError` 的例外（連線失敗等）也走同一條路，回 `unknown`。
- **`list_candidates(bedrock, *, output_modality)`**：`ListFoundationModels` 的 `modelSummaries` 逐筆
  留下 `ON_DEMAND` ∈ `inferenceTypesSupported` 且 `modelLifecycle.status == "ACTIVE"` 的 `modelId`；
  清單為空才 fallback 到 `list_profile_candidates()`（`ListInferenceProfiles`，control plane 不會在
  foundation model 清單裡列出 profile）。兩邊都空回 `()`。
- **`rank_candidates(candidates, *, preferred)` / `resolve_candidates(...)`**：這是對 Phase 文件的**必要補強**
  （見第 6 節）。`rank_candidates` 用 `startswith` 只保留命中偏好前綴的候選，並依 `preferred` 的順序排序
  （同 rank 時保留原順序）；`resolve_candidates` 先濾 ON_DEMAND 清單，濾不到才去查 profile。
  這讓「目錄裡有一堆別的廠牌模型、但 Claude 只支援 `INFERENCE_PROFILE`」的真實情況也能選到 Claude，
  同時保證**不會為了多驗證而對每個模型送計費請求**。
- **`probe_embedding(runtime, model_id, *, region)`**：body 固定只有 `{"inputText", "dimensions", "normalize"}`
  三個鍵，**不帶任何生成參數**。`invoke_model` 的回應 `body` 是 `StreamingBody`，一律
  `json.loads(raw["body"].read())`。接著三道檢查：維度必須是 1024（否則 `param_unsupported`，
  detail 寫實際維度）、所有元素必須是有限數值（`math.isfinite`，擋 `NaN`／`Infinity`）、都通過才回 `ok`。
- **`probe_generation(runtime, model_id, *, region)`**：`converse` 的 `inferenceConfig` 精確只有
  `{"maxTokens", "temperature"}`，**不設 `topP`**，也不用 `additionalModelRequestFields`。
  成功時 detail 記 `stopReason=...、<inputTokens> tokens`。
- **`error_detail(error)`**：依 §6.3，detail 只放 `Code: Message`，並用 regex 把任何 `arn:...` 換成 `<arn>`，
  不貼完整 request／response、憑證或 ARN。
- **`probe_candidates(...)`**：依序探測候選，**第一個 `ok` 就停手**；全失敗回最後一筆；候選為空直接回
  `unavailable`（不送任何 request、不填猜測 ID）。所有嘗試都收進 `attempts`，供報告列出。
- **`render_env(probes)`**：第一行 `TKB_BEDROCK_REGION=<region>`，之後**只有 `status == "ok"` 的 probe**
  才輸出自己的 model ID 那一行。沒通過就整行不存在。
- **`render_o5_report(probes, *, run_id)`**：標題 `# O5 模型可用性報告 <run_id>：PASS|BLOCKED`
  （全部 `ok` 才 PASS）＋一張 purpose／model／region／status／detail 的表。簽名與 Phase 文件逐字相同。
- **`render_run_context(...)`**（私有補充區塊）：Region、帳號別名、執行時間、SDK 逾時、
  兩條路徑各自的參數、候選嘗試明細（含 token 數），BLOCKED 時再附上停止語句。
- **`render_table(probes)`**：Phase 文件 §2 的 stdout 表格，欄寬 `purpose=10`／`model_id=29`／`status=6`，
  分隔列 `11-+-31-+-8-+-27`，與文件的範例逐字相同。
- **`account_alias(region)`**：`iam:ListAccountAliases`；沒有別名就退回 `sts:GetCallerIdentity` 的帳號號碼，
  都拿不到寫「未知」。任何例外都不會讓 probe 失敗。
- **`main(argv)`**：`--region`（必填）＋ `--run-id`／`--report-dir`（選用，預設 UTC 時間戳與
  `docs/plan/report/`）→ 用 `SDK_CONFIG` 建 `bedrock`／`bedrock-runtime` 兩個 client →
  `resolve_candidates` → 兩個 probe → 報告寫檔 → stdout 印表格與 `.env` 片段 →
  **全部 `ok` 回 `0`，任一非 `ok` 回 `2`**。

## 5. 遇到的問題與解法

### 5.1（主要）所有 Bedrock runtime 呼叫都回 `ValidationException: Operation not allowed`

第一次對真實帳號跑 Titan probe 就失敗。做了下列對照實驗釐清是「程式／參數問題」還是「帳號問題」：

| 實驗 | 結果 |
|---|---|
| 用 `aws bedrock-runtime invoke-model` CLI 直接送同一個 body | 同一個錯誤 → 不是我的程式 |
| body 只留 `{"inputText":"ping"}`（拿掉 `dimensions`／`normalize`） | 同一個錯誤 → 不是參數 |
| 換模型：Titan V1、Cohere Embed、Nova Lite／Micro、Claude Haiku 4.5、Claude Sonnet 4.5 | 全部同一個錯誤 → 不是特定模型 |
| 換呼叫方式：`InvokeModel` 與 `Converse` | 全部同一個錯誤 → 不是 API |
| 換 Region：`us-east-1`、`ap-northeast-1` | 全部同一個錯誤 → 不是 Region |
| control plane：`ListFoundationModels`／`ListInferenceProfiles`／`ListCustomModels` | 全部成功 → 不是 IAM 對 Bedrock 沒權限 |
| 其他服務：`sts:GetCallerIdentity`、`s3:ListBuckets` | 全部成功 → 帳號與憑證本身正常 |
| **`bedrock:GetUseCaseForModelAccess`** | **`ResourceNotFoundException: You have not filled out the request form. Fill out the form before getting access.`** |

**結論**：帳號 123456789012 從未送出 Bedrock model access 的使用情境表單，因此沒有任何模型被授權，
runtime 一律以 `Operation not allowed` 拒絕。這是需要人在 AWS Console 完成的動作
（Bedrock → Model access → 填寫使用情境表單），腳本不會也不應該代填公司／用途欄位。
**解法：判定 O5 BLOCKED，不填任何猜測值。**

### 5.2 `list_candidates` 的 ON_DEMAND 過濾會濾掉全部 Claude

`us-east-1` 的所有 Claude（含 Haiku 4.5、Sonnet 4.5）`inferenceTypesSupported` 只有
`INFERENCE_PROFILE`，沒有 `ON_DEMAND`；而 TEXT 的 ON_DEMAND 清單因為 Nova／Llama 等模型而**不為空**。
所以 Phase 文件「候選為空才查 inference profile」這條規則永遠不會觸發，Claude 永遠選不到。

**解法**：`list_candidates` 維持文件原樣（只在清單為空時 fallback），另外加
`rank_candidates` / `resolve_candidates` 負責用偏好前綴挑選，濾不到才查 profile。
已回寫 Phase 文件（第 6 節）。附帶好處：不會對目錄裡其他廠牌的模型送計費請求。

### 5.3 `detail` 用 `repr(error)` 可能帶進 ARN

Phase 文件 §6.3 明文「`detail` 只放錯誤代碼與 SDK 的錯誤訊息，不貼完整 request／response、憑證或 ARN」，
但 §7 的最小實作寫 `repr(error)`，兩者衝突。**解法**：新增 `error_detail(error)` 回 `Code: Message`，
並把任何 `arn:...` 置換成 `<arn>`；已回寫 Phase 文件的兩段程式片段。

### 5.4 測試如何匯入 `infra/scripts/check_models.py`

腳本不在 `src/` 的安裝套件裡，repo root 也不在 `sys.path`。不能改 `pyproject.toml`（加 `pythonpath`），
也不想動別的 Phase 擁有的 `tests/conftest.py`。**解法**：在兩支測試檔各自
`sys.path.insert(0, <infra/scripts>)` 後再 `from check_models import ...`，並加 `# noqa: E402`。
好處是紅燈訊號就是文件預期的 `cannot import name ...`。

### 5.5 `ValidationException` 的語意落差

本次的錯誤代碼是 `ValidationException`，依 §6.2 的固定對照會記成 `param_unsupported`，
但實際語意是「帳號未開通」。**刻意不改對照表**：狀態只忠實反映 `Error.Code`，真實語意留在 `detail`
的原始訊息（`Operation not allowed`）裡，並在 O5 報告明寫這一點，避免把「沒權限」誤讀成「參數錯」
或反過來。已記在 O5 報告的「對 `ProbeStatus` 對照表的說明」一節。
