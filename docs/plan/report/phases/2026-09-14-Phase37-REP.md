### 1.1 `rote.py` 第 6 段（新增）

| 名稱 | 形狀 | 邏輯 |
|---|---|---|
| `RoteRoute` | `Literal["layer1","layer2","agent","agent_after_replay_failure"]` | 本次走哪一條路；`commit_success` 的分支條件就看它。 |
| `AGENT_MAX_TOOL_CALLS` | `= 6` | tool loop 的硬上限（固定三步 × 兩輪修正額度）。F14 展開是確定性後處理，不算進額度。 |

| `NormalizationResult` | 九個欄位的 frozen dataclass | `signature`／`domain`／`adapter`／`keys` 都是**本次事件**的，不是被重放那筆 PROC 的。 |

| `Rote.normalize_all` | `-> tuple[NormalizationResult, ...]` | 三層順序的唯一實作。 |
| `Rote.normalize` | `-> NormalizationResult` | 就是 `normalize_all(...)[0]`（00A §6.8）。 |
| `Rote.commit_success` | `-> ProvenWorkflow \| None` | 只有拿到非空 `execution_arn` 且 `validated` 才提交。 |
| `_Run`（私有） | 一次序列的執行狀態 | `root["steps"]` 與 `outputs` 是同一個 list，append 後上一步立刻可被 `$steps[k]` 引用。重放與 Agent 共用同一份取值規則。 |
| `_agent_prompt`／`_tool_specs`／`_tool_choice`／`_exchange`／`_output_summary`／`_validated_entity` | 私有 | prompt、工具清單、讀回模型選擇、把結果接回對話、canonical dict → 模型物件。 |

**三層順序（`normalize_all`）。** `structure_signature(event)` → `find_replayable`（Phase 34 的
**唯一**一份兩層順序，本 Phase 只 import 不重抄）→

- 沒命中 → `_run_agent(..., route="agent")`。
- 命中 → `_replay`；丟 `PermanentError`（`IngressError` 是子類）就
  `_persist(on_replay_failure(...))` 再 `_run_agent(..., route="agent_after_replay_failure",
  replayed=selected.signature)`。
- **`TransientError` 原樣往上拋**：那是服務故障不是這條 PROC 壞掉，不累加 `fail_count`、
  也不回退 Agent（有一條專門的測試把這件事鎖起來）。

**Agent tool loop。** `converse_with_tools(system, messages, tools, operation_id, node)` 每一輪
回一個 `toolUse`；程式執行、把**只有 `$steps[k]` 與欄位名稱**（不含任何值）的結果接回對話。
工具丟 `PermanentError`（含 validate 不過）時，錯誤回饋給模型並用 `_next_parser(tried)`
（`sorted`，所以同一份事件每次挑到同一個）換一個沒試過的 parser 重來一輪；換 parser 的次數
一樣算進 `AGENT_MAX_TOOL_CALLS`。每一輪開始前先 `assert_time_left(deadline, step=AGENT_NODE)`，
額度與期限雙重封頂。額度用完仍不合法就整次接入失敗，**沒有** entity、execution 或成功 PROC。

**prompt（00A §6.5、D-67）。** 只給三個分區：`<allowed_tools>`（程式產生的八個名稱）、
`<event_ref>$event</event_ref>`、`<source_data>`（`domain`／`adapter`／`event_type` 與已核定的
最上層 key **名稱**，先經 Phase 17 的 `_as_data` 轉義）。**標題、body、login、ID 一個都沒有**——
人工驗收（§4）對六個 fixture 真值做過掃描，`prompt 洩漏的 payload 原文：[]`。

**`commit_success` 的五個分支。** 空 ARN 或 `validated=False` → `PermanentError`；先
`validate_recorded_steps(result.steps)`（Rule 12／13 的最後一道防線）；`stored` 是 retired →
回 `None`（F53，不覆寫 `steps`、不重置計數）；`route in ("layer1","layer2")` → `on_replay_success`
（`stored is None` 時是 `PermanentError`，不憑空建立）；其餘（`agent`／`agent_after_replay_failure`）
→ `on_new_success`。`updated is stored` 代表 `record_proc_sample` 回了 `False`，直接回傳、
**省掉一次 `update_meta`**（Phase 35 報告第 7 節指定的用法）。

**F14 多筆子 Release（`_sub_releases`）。** 只有最後的 entity 是 `Release` 而且序列裡有
`normalize_release` 才展開：用那一步的 `parsed` path 取回 parser 的輸出（**重用，不重跑
parser**），`changes` 長度 n > 1 時對 `k = 1..n` 各產一個 `index=str(k)` 的步驟變體，除了
已記錄的那個 `k` 直接重用結果之外，其餘各跑一次 `normalize_release → validate`。
**重放與 Agent 兩條路都展開**（偏差 #7）。

**持久化（`_persist`）。** 全新簽名 `put_meta(..., create_only=True)`；其餘
`update_meta(pk, proc_changes(proc), expected_revision=revision_of(pk))`。`changes` 一律由
Phase 35 的 `proc_changes` 產生，**不自己拼**；`CoordinationError` 原樣往上拋，函式內不重試。

## 5. 遇到的問題與解法

1. **`validate` 的輸出再驗一次會失敗（真正的設計問題）。** Phase 36 報告第 7 節第 1 點說
   「canonical dict 已經是 `model_dump(mode="json")`，再驗一次會得到同一個物件（冪等）」。
   **不成立**：dump 帶著 `cluster_id`／`feature_ids`／`embedding`，而 `validate_ticket` 第二道
   檢查就是「接入不得預填分析欄位」，所以會丟 `IngressError`。實際紅燈逐字是
   `IngressError: 接入不得預填分析欄位`。解法：`_validated_entity` 只做**還原**
   （`Ticket.model_validate`／`Release.model_validate`），Phase 31 的入口驗證由序列最後一步的
   `validate` 工具執行（`validate_recorded_steps` 保證最後一步一定是它）；`ValidationError`
   仍收斂成 `IngressError`，不外洩給只認 `IngressError` 的 webhook handler。已寫進 Phase 文件 §12 #4。
2. **循環 import 的方向要挑一邊。** `adapters` 函式內 import `ingress`；`rote` 需要
   `assert_time_left`、`ingress` 需要 `Rote`。兩邊都放模組層就是循環。裁決：
   **`rote` 模組層 import `ingress`，`ingress` 用函式內 import 取 `rote` 與 `adapters`**——
   三層邏輯集中在 `rote.py`，那支檔案的可讀性優先；`ingress.py` 模組層完全沒有
   `import adapters`（controller 的硬條件）。型別用 `TYPE_CHECKING`。
3. **`RoteDeps` 的可寫屬性擋住 frozen dataclass。** 00A §6.8 的 Produces 片段把五個相依寫成
   可寫變數，mypy strict 會說
   `Protocol member RoteDeps.operations expected settable variable, got read-only attribute`。
   改成唯讀 `@property`：更寬鬆，普通屬性、`@property` 與 bound method 三種形狀都滿足。
4. **F14 在重放路徑會漏掉子 Release。** Phase 文件的 F14 段落只描述 Agent 路徑；但一筆改到
