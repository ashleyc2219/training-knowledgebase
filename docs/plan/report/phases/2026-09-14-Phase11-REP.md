### 1.1 `src/training_kb/operations.py`（在 Phase 10 的 class 上追加，不重排、不改既有簽名）

| 新增 | 內容 |
|---|---|
| `SEQUENCE_ATTEMPTS: int = 8` | `next_sequence` 的 CAS 重試上限（00A §6.4）。有限次數，超過丟 `CoordinationError`。 |
| `SEQUENCE_PREFIX = "SEQ#"`／`LEASE_PREFIX = "LEASE#"` | 兩個非業務前綴（00A §3.3）。呼叫端傳 `PROJECT#<id>`／`TUTORIAL#<slug>`，前綴由本模組補。 |
| `OperationRecord.accept_seq: int \| None` | 位置固定在 `retryable` 與 `accepted_at` 之間（00A §6.4 欄位順序）。 |
| `_number(item, field) -> int \| None` | 與既有 `_revision` 同形的整數守門員（`bool` 不算數字；缺就 `None`，舊 item 不必遷移）。 |
| `OperationCoordinator.next_sequence(scope) -> int` | `put_meta_item(pk, {"counter": 0}, create_only=True)` 起頭 → 讀 `counter`／`_revision` → `update_meta(..., expected_revision=剛讀到的)` 寫回加一；搶輸重讀再試，上限 8 次。 |
| `OperationCoordinator.acquire_lease(scope, owner, *, ttl_seconds, now) -> bool` | `ttl_seconds <= 0` 丟 `PermanentError`；`put_meta_item(create_only=True)` 成功就拿到；已存在時自己比 `to_iso(now) < expires_at` 判定到期，再用 `expected_revision` 搶佔，搶輸回 `False`。 |
| `OperationCoordinator.release_lease(scope, owner) -> None` | item 不存在或 `owner` 不是自己就直接返回（非持有者清不掉別人的租約）；CAS 失敗也安靜返回（新持有者不該被蓋掉）。 |
| `accept()` | 在條件寫入**之前**呼叫 `next_sequence(f"PROJECT#{project_id}")`，號碼只寫進本次真的建立的 `OPS#` item；`duplicate` 分支完全不寫入，天然不重新取號。 |
| `record_version()` | **改成只能寫一次**（見第 7 節「代修 Phase 10 review 項目」）。 |

實作邏輯重點：

- **只用三個既有原語。** `put_meta_item`／`get_meta_item`／`update_meta`，沒有碰 boto3 表物件、沒有改 `repository.py`。`SEQ#`／`LEASE#` 的 PK 自己用 f-string 組（**不經 `ops_pk`**：`ops_pk` 內部的 `keys._bare` 會因為字串含 `#` 丟 `ValueError`）。
- **號碼缺口是設計選擇。** 取號在條件寫入之前，所以重送會燒掉一個號碼（`resend` 案例實測 `seq_counter=4`、`accept_seq` 四次都是 1）。接受順序只要求單調遞增、可比較，不要求連號（同 D26 對版號缺口的取捨）。改成「先查再寫」會把 Phase 10 的三個分支變成有競態的四個分支，所以不補洞。
- **到期不靠 TTL。** `expires_at` 是固定長度 ISO-8601 UTC 字串，字典序等於時間序；`ttl` 屬性只給 DynamoDB 長期清理。
- **鎖不決定順序。** 順序一律由 `accept_seq` 決定；`o2_report.pending_in_accept_order()` 就是這條規則的實作點。

### 1.2 `infra/scripts/o2_report.py`（新增）

六段：契約常數與五個案例 → 兩個 dataclass → 真實後端器材 → 五個案例 → 判定與報告 → 隔離表／證據／命令列。
`O2Case`、`O2CaseResult`、`run_o2_case(case, *, table, region)`、`o2_verdict`、`render_o2_report(results, *, run_id, table, region)` 的簽名**逐字**照 00A §6.4。

五個案例的做法：

| 案例 | 注入點 | 怎麼做 |
|---|---|---|
| `restart` | `after_record_version` | `subprocess` 開**真的子程序**：accept → 版號替身 → `record_version` → `os.kill(os.getpid(), SIGKILL)`（`Tutorial.current_version` 刻意還沒切）。父程序確認 `returncode == -9`，再用**全新** `Repository` + `OperationCoordinator` 接手：`accept` 回 `duplicate`、版號替身讀到 ledger 已有 `version_id` 就直接沿用，不取第三個號。 |
| `resend` | `after_accept` | 同一筆事件送四次，每次都換一組全新物件。第一次刻意在 `accept` 之後就停手（教學還沒建），第二次因此走 **D-45 的合法續跑**：`duplicate` 但目標物件不存在 → 沿用同一個 `operation_id` 補寫。補寫不多一筆 `OPS#`、不換 `accept_seq`，所以和重複處理分得開。 |
| `lease_expiry` | `owner_vanishes` | `worker-a` 拿租約後永遠不釋放。時間用可注入的 clock 往前撥（不真的睡）：`ttl-1` 秒接手失敗、`ttl+1` 秒接手成功；接手前先把**到期但還沒被刪除**的 item 讀回來記進觀察值（`readable_after_expiry=True`、`ttl_attr_set=True`）。接手者仍照 `accept_seq` 排序處理。 |
| `interleaved` | `release_and_feedback_same_slug` | 兩個 coordinator 交替呼叫，**搶鎖順序刻意與接受順序相反**（先接受的是 release，先拿鎖的是 feedback 的 worker）。拿到鎖的人仍挑 `accept_seq` 最小的做，做完 `release_lease` 換手。 |
| `closed_execution` | `already_exists_closed` | 最小 stub `ExecutionAlreadyExists`（**不實作 `PipelineStarter`**，那是 P32）。`resume_after_already_exists()`：ledger 有 `version_id` 就回原結果；沒有就 `CoordinationError`，**不回成功、不換名重跑**。 |

`run_o2_case` 判定失敗**不丟例外**（FAIL 是 gate 的合法結論）；只有真的跑不動（憑證、表不存在）才讓例外往上跑——那是「沒有證據」，不是 FAIL。
`main()` 會 `--provision` 建隔離表、跑五案、把證據 PUT 進正式 bucket 的私有 `operations/o2/<run_id>.json` 並讀回核對、寫報告、刪表，最後把建立／刪除時間與 `table_exists -> False` 一併寫進報告的「隔離測試表生命週期」。exit code：PASS 回 0、FAIL 回 2。

## 5. 遇到的問題與解法

| 問題 | 原因 | 解法 |

| Phase 10 的 `test_a_write_conflict_without_a_readable_record_fails_loudly` 被 `accept` 取號打掛 | 它的 `_AmnesiacRepository` 對**所有** PK 回 `None`，比它自己的 docstring（「永遠讀不回 `OPS#`」）更寬；`next_sequence` 因此讀不到 `SEQ#` item | 把 fake 收窄成只對 `OPS#` 失憶（`return None if pk.startswith("OPS#") else super().get_meta_item(pk)`），實作與 docstring 一致 |

| `render_o2_report` 的 `.format(row)` 被 ruff `UP032` 擋下 | Phase 文件的示範碼用單一引數 `.format` | 改成輸出逐字相同的 f-string，並把差異寫進 Phase 文件 |
| `run_o2_case` 的簽名沒有 `run_id`，但 `evidence_ref` 要填 `operations/o2/<run_id>.json` | 00A §6.4 把簽名列為 canonical，不得加參數 | 加 `current_run_id()` 讀環境變數 `TKB_O2_RUN_ID`（`main` 先設定），沒設回 `adhoc`；簽名逐字不動 |

## 9. 未完成／疑慮

1. **`tests/integration/test_operations_ledger.py` 是 Phase 10 的檔案，本 Phase 動了它兩次**：一次把 `_AmnesiacRepository` 收窄成只對 `OPS#` 失憶（`accept` 取號的必要後果），一次加 `record_version` write-once 的測試（controller 指定）。兩處都在本報告第 5／7 節說明；如果 Phase 10 的 owner 有不同意見，請以 controller 裁決為準。
2. **`accept_seq` 是專案層級、不是全域**，而且允許缺口。Phase 32／46 如果要排序，必須在同一個 `project_id` 內比較，不能拿兩個專案的號碼互比，也不能用「號碼連續」推論有沒有漏事件。
3. **lease 仍不是正確性保證。** 本 Phase 只證明「到期後可接手、非持有者不能釋放」。時鐘偏移時兩個 owner 可能同時以為自己持有，所以會改變版本鏈的寫入一律要自己帶條件（`o2_report.publish_stub` 就是示範：即使拿著 lease 也仍用 `expected_revision`）。
4. **版號替身不是 `allocate_version`。** `restart`／`interleaved` 的 `<slug>@v<n>` 是本 Phase 自備的字串替身；Phase 20 要用真正的 `allocate_version` 在同一組情境再驗一次（00A §4.2 的追驗欄已列 P20）。
5. **closed execution 用的是最小 stub**，沒有呼叫真的 Step Functions。「同名冪等只在執行未結束時成立」這一條在本 Phase 只驗了**協調紀錄夠不夠判斷**；真的 `ExecutionAlreadyExists` 由 Phase 32 接 boto3 adapter 時再驗。
6. **早一次的 `operations/o2/20260914t182535z.json` 留在正式 bucket**（私有前綴，2145 bytes）。它是合法的 gate 證據，沒有刪；若要保持 `operations/o2/` 只有一份，請由維護者決定是否刪除。
7. **TTL 屬性只驗到「有設定、到期 item 仍讀得到」**。DynamoDB 真正的刪除時機是「typically within a few days」，不可能在一次 gate 執行裡觀察到，本報告也沒有宣稱觀察過它。
