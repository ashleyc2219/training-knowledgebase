## 1. 實作內容（含實作邏輯）

### 1.1 `src/training_kb/vectors.py`（新建，55 行）

無 AWS 相依的純函式模組，三個函式：

- `_checked(vector, *, expected=None) -> list[float]`：共用的向量輸入檢查。
  **檢查順序是刻意的**：先擋空集合 → 再比長度 → 逐一檢查元素。元素檢查固定是
  「先排除 `bool` → 再判斷是不是 `int`／`float` → 確定是數值才 `math.isfinite`」。
  `True` 是 `int` 的子型別，`isinstance(True, (int, float))` 與 `math.isfinite(True)`
  兩個都會成立，所以 `bool` 必須第一個擋；`isfinite` 放最後才不會對字串丟 `TypeError`
  （那會變成家族外的例外，Phase 29 只會記成 `retryable=False`）。
- `cosine(left, right) -> float`：固定 `dot / (norm_left * norm_right)`，不先除一次再除一次、
  不四捨五入。這個順序讓 `cosine([1,0,0,0,0], [17,7,6,5,1])` 精確等於字面值 `0.85`
  （|left|=1、|right|=sqrt(289+49+36+25+1)=20、內積 17），Phase 38／49 的門檻測試才能用 `==`。
  零向量沒有方向，明確丟 `PermanentError`，不當成 0 相似度。
- `centroid(vectors) -> list[float]`：逐維相加除以筆數；只有一筆時回它自己
  （Phase 38 的單樣本群走同一條路徑，不特判）。

本 Phase **不定義** 0.85 門檻常數——唯一來源是 Phase 02 的 `Thresholds.cosine_match`（00A §5.4）。

### 1.2 `src/training_kb/writing/client.py`（修改，+38 行，無任何既有行被搬動或改寫）

三處局部插入，讓 Phase 17／18 之後還能繼續在同一支檔擴充：

1. `import math`（接在 `import json` 之後，符合 ruff isort 順序）。
2. `TITAN_DIMENSIONS = 1024`，放在 `JUDGEMENT_INFERENCE_CONFIG` 之後。這是「向量幾維」
   這個數字的唯一一份（00A §5.4 指名 owner 是 `writing/client.py`／P16），送出的 body 與
   收回的回應都拿同一個常數比。
3. `_validated_embedding(value) -> list[float]`，放在私有 helper `_error_code` 之後。
   與 `vectors._checked` 同一套順序，但額外先確認 `isinstance(value, list)`——Titan 真的回
   `{"not": "a list"}` 這種東西時，`len()` 會先炸成 `TypeError`。
4. `BedrockWriter.embed(text, *, operation_id, node) -> list[float]`，放在共用的
   `_request_once` 之後、生成類的 `_converse` 之前（與 `Writer` Protocol 的方法順序一致）。
   邏輯依序是：

   - 空白 `text` 在**送出之前**就丟 `PermanentError`：不產生 request、不計 attempt。
     Titan 也會回 `ValidationException`，但先擋可以少一次計費請求，錯誤訊息也指向真正的欄位。
   - body 固定 `json.dumps({"inputText": text, "dimensions": TITAN_DIMENSIONS, "normalize": True})`
     三個鍵，**沒有任何生成參數**（`maxTokens`／`temperature`／`topP` 都不得出現，設計 §14.3）。
   - 走 Phase 15 的 `_request_once(..., kind="embedding")`，所以重試層數、trace 一筆、
     錯誤分類（`TransientError`／`PermanentError`）與訊息只留錯誤碼這些規則完全沿用，沒有第二套。
   - **Titan 用 `invoke_model`（Claude 才用 `converse`）**，回應的 `body` 是 `StreamingBody`
     不是 dict，一律 `json.loads(response["body"].read())`，而且只能讀一次。
   - 最後過 `_validated_embedding`：非 list／長度非 1024／含 `bool`／含字串／含 `NaN`／含
     `Infinity` 全部 `PermanentError`。

## 5. 遇到的問題與解法

1. **測試檔要能被 mypy 檢查，但專案的 mypy 只看 `src`。**
   controller 交辦「以 mypy 可檢查的方式」加 Protocol 斷言，而 `[tool.mypy] files = ["src"]`
   不含 tests，又不准改 `pyproject.toml`。解法：把 `tests/unit/test_titan_writer.py` 寫成
   strict 可過的形狀（欄位逐一標註、`invoke_model` 回 `dict[str, Any]` 而非裸 `dict`），
   再用 `uv run mypy src tests/unit/test_titan_writer.py` 顯式檢查。這對 Phase 文件的原稿
   是**行為完全相同**的型別註記差異，已同步改文件並在 §6 列出。

2. **Phase 文件的 Task 2 紅燈訊號預期是 `AttributeError`，實際先撞到 `ImportError`。**
   因為我的測試檔多 import 了 `TITAN_DIMENSIONS`（00A §5.4 指名的常數）。沒有為了對齊文件
   而拿掉 import——改成兩個訊號都留證（§3），並修 Phase 文件的預期敘述。

3. **`_validated_embedding` 對非 list 的輸入必須先判型別。**
   文件的 `{"not": "a list"}` 案例若先做 `len(value) != 1024` 會是 `TypeError` 而不是
   `PermanentError`；`isinstance(value, list)` 放在 `or` 的**左邊**靠短路求值擋掉。
   （文件原稿本來就是這個順序，測試 `{"not": "a list"}` 那一筆就是在鎖它。）

4. **`bool` 與 `NaN` 兩個安靜的坑。** `isinstance(True, (int, float))` 是 `True`、
   `math.isfinite(True)` 也是 `True`，所以 `bool` 只能靠「先擋」；`float("nan") >= 0.85`
   永遠是 `False`，一個 NaN 向量不會爆炸，只會讓 Phase 38 安靜多開一個 cluster。
   `vectors._checked` 與 `_validated_embedding` 兩邊都逐一有測試鎖住。

5. **`git status` 顯示 Phase 16 文件是未追蹤檔（`??`）。**
   `docs/plan/unfinish/` 下的 Phase 文件在這個 checkout 本來就未追蹤；比對 Phase 15 的
   `7874ed0 docs(plan): 更新 Phase 15 文件`（也是 688 行的新增檔）確認是既有慣例，
   照同樣方式只 add 自己那一支。
