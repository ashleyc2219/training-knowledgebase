本 Phase 產出的**公開名稱與簽名**（給 Phase 45／48／58 用）：

```python
ReviewMode = Literal["formal", "demo"]

@dataclass(frozen=True)
class WeakTarget:
    tutorial_id: str
    version_id: str
    category: str
    feedback_ids: tuple[str, ...]

def is_weak(avg: float | None, n: int, top_category_count: int, *,
            mode: ReviewMode, thresholds: Thresholds) -> bool: ...

def select_weak_targets(*, repository: Repository, mode: ReviewMode, now: datetime,
                        thresholds: Thresholds | None = None) -> tuple[WeakTarget, ...]: ...
```

module-private（不是跨模組 API）：`_top_category(feedback, approved) -> tuple[str, tuple[str, ...]]`。

邏輯：

1. **`is_weak`（純函式）** —— 三個條件 AND，任一不成立就不是弱教學：
   平均 `< thresholds.weak_average`（3.5）、樣本數 `n >= production_feedback`（10；
   `mode="demo"` 改用 `demo_feedback`＝8）、同一核定類別筆數 `>= recurring_category`（5）。
   - 比較用**未四捨五入**的值：`3.49` 算弱、`3.5` 不算（設計 §11.2）。
   - `avg is None`（該版一筆評分都沒有）一律 `False`，不把零評分當 0 分（設計 §12.1）。
   - 三個門檻數字**全部**從 `Thresholds` 讀，模組內沒有第二份字面值（00A §5.4）。
   - 未知 mode 丟 `PermanentError` 而不是默默退回 formal——用錯門檻會挑出一批不該改的教學，
     ASL 的 Catch 把它導向失敗終點才是正確行為。

2. **`select_weak_targets`** —— `scan_entity("TUTORIAL", consistent=True)`（`meta_only` 用預設
   `True`，所以只回 `META` item，不會混進 `TUTORIAL#` 底下的關係邊）逐篇檢查：
   - `status != ACTIVE`、`current_version is None`、`get_version(...)` 回 `None`、
     `published_at is None` → 跳過。只看**現在**的 `current_version`，不掃舊版、
     不做「上次檢視之後」的浮水印切分（設計 §7.5）。
   - `list_feedback_of_version(version_id)` 取該版全部回饋，再用 `now` 當截止點過濾：
     `row.ts is not None and row.ts <= now`。
   - `rated = [有評分的回饋]`；平均用 Phase 53 的 `average_rating(rated)`，`n = len(rated)`
     ——分子與分母吃同一群回饋（00A D-44）。
   - `_top_category` 取筆數最多的核定類別與它的全部 Feedback ID。
   - `is_weak` 成立就包成 `WeakTarget(slug, version_id, category, ids)`。
   - 回傳 `tuple(sorted(..., key=version_id))`。回空 tuple 是正常結果，不是錯誤。

3. **`_top_category`** —— 只數 `category in approved` 的回饋，所以 `待分類` 與 `None` 既不進
   同類計數也不進 `feedback_ids`。同類 ID 先用 `set` 去重再 `sorted`。平手時用
   `min(groups, key=lambda name: (-len(groups[name]), name))`：筆數多者優先、其次類別名稱
   升序。**不可以用 `max`**——它在平手時回的是 dict 插入順序（也就是 DynamoDB 這次剛好先回
   哪一筆），重送會挑到不同類別，Phase 46 的證據指紋就不穩定。

`WeakTarget` 的 `feedback_ids` **只裝 `category` 這一類的證據**，不混別類：Phase 45 的診斷
就是針對這一類在問「哪幾步出問題」，混類會讓它指錯步驟（00A §6.9）。

## 5. 遇到的問題與解法

1. **Phase 43 還沒合併。** brief 已預警：`approved_categories(repository)` 與
   `PENDING_CATEGORY` 目前不存在於 `ingress.py`，只有 controller 預先宣告的
   `DEFAULT_FEEDBACK_CATEGORIES`（值就是初始兩類）。依 dispatch 訊息的指示先 import 這個常數，
   行為與「P43 讀不到 `CONFIG#feedback_categories` 時的回傳值」相同；程式裡留了註解，
   P43 合併後改一行即可。`_top_category` 的 `approved` 仍然是參數，不受影響。

2. **同檔三人併行。** `pipelines/feedback.py` 在我實作期間被 P45／P46／P47 同時追加。
   做法：每次 Edit 前重讀該段；只在自己的 `# ---- Phase 44 ----` 區段內動刀；需要的 import
   用單行插入或就地擴充既有那一行（例如 `from collections.abc import Iterable, Mapping`
   → `..., Sequence`），沒有重排整個 import 區塊，也沒有跑 `ruff format`。
   期間 `ruff check` 曾短暫報別人預先加、尚未使用的 import（`hashlib`／`json`／`defaultdict`
   等 F401），沒有去動它們，他們補完程式後自動消失。

3. **`ruff format --check` 不是 gate。** brief §4 收尾清單列了它，但 COMMON.md §1 明說
   gate 不含 `ruff format`，而且對既有檔一定紅。因此只跑 `ruff check`／`mypy`／`pytest`，
   共用檔不跑 format。

4. **`_average` 的歸屬中途改變。** 先照 Phase 文件寫了本地 `_average`（文件當時的前提是
   Phase 53 還沒做）。Task 3 結束後 controller 通知 Phase 53 已完成，依 D-44「平均只有一套
   算法」刪掉本地副本改成 `from training_kb.analytics.ratings import average_rating`。
   兩者算法逐行相同（`[r for r in feedback if r.rating is not None]`，空則 `None`），
   所以既有測試不必改斷言值，只把目標函式換掉。

5. **平手測試要「一定紅」而不是「碰運氣紅」。** 單元測試刻意把「缺少資訊」放在清單前面，
   `max` 版本一定回它；如果只靠整合測試，紅燈就取決於 DynamoDB 這次剛好先回哪一筆。

### 給 Phase 45／48／58 的介面（`from training_kb.pipelines.feedback import ...`）

```python
ReviewMode = Literal["formal", "demo"]

@dataclass(frozen=True)
class WeakTarget:
    tutorial_id: str        # 裸 slug，例如 "prepare-meeting"
    version_id: str         # 裸版本 ID，例如 "prepare-meeting@v1"
    category: str           # 命中的核定類別；沒有任何核定類別時是 ""（此時不會命中）
    feedback_ids: tuple[str, ...]   # 全部屬於上面那個 category，已去重且升序

def is_weak(avg: float | None, n: int, top_category_count: int, *,
            mode: ReviewMode, thresholds: Thresholds) -> bool: ...

def select_weak_targets(*, repository: Repository, mode: ReviewMode, now: datetime,
                        thresholds: Thresholds | None = None) -> tuple[WeakTarget, ...]: ...
```

呼叫約定與保證：

- 不做去重：「同一批證據不要再產生新版」是 Phase 46 的 `evidence_fingerprint` ＋ O2 操作紀錄
  的責任，本函式每次都照實回報命中。
- module-private、**不要跨模組 import**：`_top_category`。
