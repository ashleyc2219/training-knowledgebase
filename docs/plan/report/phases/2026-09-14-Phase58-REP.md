## 1. 實作內容與邏輯（逐檔說明）

四支檔各有固定分工（00A §3.2 的 `demo/` 表），**名稱不互搬**。

### 1.1 `demo/cli.py`（新增）

公開名稱：`SUBCOMMANDS`、`build_parser()`、`main(argv=None)`。

| 子命令 | 走哪條路 | 送什麼 |
|---|---|---|
| `seed --dir` | `load_seed` → `verify_recipe` →（核定齊備才）`apply_seed` | **唯一直接寫入**；`o7_ready` 為假時印 `missing_approvals`、回 `1`、**零寫入**、**不建立任何 client** |
| `trigger-ticket --ticket-id [--dir]` | `lambda.invoke` | `training-kb-import`，`kind="ticket"`，`items` 恰一筆 |
| `trigger-release --release-id [--dir]` | `lambda.invoke` | `training-kb-import`，`kind="release"`，`items` 恰一筆 |
| `trigger-review --mode` | `states.StartExecution` | input **逐字** `{"mode": <mode>}`；execution name 由 operation id 導出 |
| `import --file --kind` | `lambda.invoke` **逐筆** | 每個 item 各一次 invoke，逐筆印 `saved`／`duplicate`／`rejected` |
| `metrics --version` | `lambda.invoke` | `training-kb-analytics`，`{"action": "metrics", "version_ids": [...]}` |

關鍵設計：

- **全檔唯一的 boto3 出口是 `_boto_client(service)`**。測試把這個名字換掉，就能直接觀察
  「這次執行要過哪些 client」——所以「沒有呼叫 dynamodb」是**被證明**的，不是推論。
  區域一律 `load_settings().aws_region`（缺值丟 `PermanentError`），**沒有寫死區域、
  沒有金鑰字面值、不接受金鑰參數**（測試 `test_cli_source_has_no_credentials_or_region_literal`
  直接掃原始碼）。
- **`trigger-review` 逐字對齊 D-61**：`operation_id_for("feedback-review", f"{project_id}-{UTC 日期}")`
  → `execution_name(...)`，canonical id 用 `-` 不用 `#`，與 P48 的 `review_operation_id`
  同一個算式；input 只有 `mode`，沒有 `project_id`、沒有任何排程時刻欄位。
- **`trigger-ticket`／`trigger-release` 的原文來源是本機種子檔**（見 §5 第 1 點的裁決），
  可信入口設定由 `TICKET_ENTRIES`／`RELEASE_ENTRY` 宣告，不從 payload 反推（D-60）。
- **`seed` 沒有 `--force`。** 核定缺席就是缺席；`demo/seed_loader.py` 沒有、也不得有任何
  自動填值路徑（設計 §18 O7）。

### 1.2 `demo/preview.py`（新增）

公開名稱：`PREVIEW_PREFIX = "demo/previews/"`、`PREVIEW_NODES = ("preview-off", "preview-on")`、
`PREVIEW_HEADER`、`PreviewResult(run_id, rule_id, off_key, on_key, model_calls)`、
`run_rule_toggle_preview(tickets, *, rule, repository, writer, run_id)`。

流程固定：同一批 `tickets` 串成一個 `source_text` → 第一次 `prompt_write_tutorial(..., rules_block="")`
（`node="preview-off"`）→ `TutorialContent.model_validate` → `render_markdown` → 加檔頭 →
`put_object(..., if_none_match=True)` 寫 `off.md`；第二次 `rules_block=render_rules_block([rule])`
（`node="preview-on"`）→ 同樣流程寫 `on.md`。

- **寫得到的只有那兩個 key。** 函式裡沒有 `put_meta`／`put_edge`／`update_meta`／
  `allocate_version`／`create_version`，也不回傳 `version_id`。
- **同 `run_id` 重跑**在第一次條件寫入就 `ObjectAlreadyExists`（`PermanentError` 子類）中止，
  而且只白跑一次模型呼叫（`off` 那次），不會蓋掉現場已經展示過的對照檔。
- **檔頭**第一行固定 `合成資料示範｜隔離預覽｜不寫入正式教學與統計`，第二行帶 `run_id`、
  規則開關狀態、規則 ID 與 **writer 類別名**——O5 BLOCKED 時要能一眼分辨「隔離預覽」與
  「模型未開通」（Phase 文件 §8 的現況核對建議）。
- `PREVIEW_PREFIX` 已經在 Phase 09 `infra/training_kb_data_stack.py:PRIVATE_PREFIXES` 裡，
  天生落在私有前綴；它是 **S3 key 前綴不是本機路徑**，程式沒有拿它組過任何本機路徑。

### 1.3 `demo/view_model.py`（新增，純計算）

公開名稱：`DASHBOARD_BLOCKS`、`SYNTHETIC_NOTICE`、`TIME_KEYS`、`TIME_LABELS`、`GATE_NOTE`、
`PENDING_APPROVAL`、`FALLBACK_NOTE`、`NO_RATING`、`NO_SAMPLE`、`REOPEN_NOTE`、`CANDIDATE_NOTE`、
`ACTIVE_NOTE`、`RETIRED_NOTE`、`STATUS_NOTES`、`Banner`、`render_banner`、`CallBreakdown`、
`call_breakdown`、`SeedRepository`、`Dashboard`、`load_dashboard`、`dashboard_view`。

`dashboard_view(*, repository, approved, project_id, batch) -> dict` 的四個 key 逐字是
`DASHBOARD_BLOCKS`：

| 區塊 | 形狀 | 來源 |
|---|---|---|
| `最新教學與版本差異` | `{"simulated_history": {slug: row}, "live_run": {version_id: row}}` | `current_published_versions`（P48）＋ 私有 `tutorials/<slug>/v<n>.diff` |
| `每版評分與回饋數` | `{version_id: {average, display, sample_size, negative, note, notice}}` | `version_metrics`（P54）＋ `format_average`（P53） |
| `重開票筆數與分子分母` | `{version_id: {count, numerator, denominator, rate, note, notice}}` | `version_metrics(...).reopen`（P54 的 `ReopenStats`） |
| `規則狀態與來源證據` | `{notice, counts, rules: [...]}` | `list_rules` ＋ `rule_counts`／`applied_count`（P54） |

- **指標公式一份都不在這裡。** 平均、負面回饋、十四天窗口與呼叫數全部轉呼
  `training_kb.analytics`；守門測試 `test_demo_package_has_no_second_metric_formula`
  掃過整個 `demo/`，找到 `days=14` 或 `sum(...)/len(...)` 的樣式就紅燈。
- **零值處理**：`average is None` → `display = "尚無評分"`、`note = "尚無評分"`；
  `rate is None`（零分母）→ `note` 以 `N/A：樣本不足` 開頭。**畫面不會出現 0 分或 0%。**
- **每一列數字都帶 `notice = f"{SYNTHETIC_NOTICE}｜批次：{batch}"`**（R11 的合成資料標示）。
- `render_banner` 固定輸出
  `【合成資料示範】｜批次：…｜時間標示：…｜gate：O5 模型未開通（BLOCKED）｜O7 待維護者核定`，
  `fallback_reason` 非空時追加 `｜目前顯示預先執行結果；本次現場失敗原因：<reason>`。
- `call_breakdown(trace)`：`total` 轉呼 `bedrock_call_count(trace)`，逐筆用
  `json.loads(trace.to_json())` 依 `node` 分組、數 `attempt >= 2` 當 `retries`。
- **`SeedRepository`**：把 `SeedBundle` 包成 `dashboard_view` 需要的**唯讀** Repository 形狀
  （只有讀取方法，連一個 `put_*` 都沒有），讓 Dashboard 在**離線**的維護者筆電上就能由
  `demo/seed` 現算（P56 §7.2 第 4 條）。全文與 diff 用 Phase 22／23 的**同一組函式**
  （`render_markdown`／`make_diff`）現算，不另寫一份。

## 5. 遇到的問題與解法

1. **`trigger-ticket`／`trigger-release` 要送什麼？** Phase 文件只寫 `--ticket-id`，但受控匯入
   Lambda 的 `ticket`／`release` 需要「可信入口設定 ＋ 原始事件」（D-60），而 CLI 又不准讀
   DynamoDB。**解法：** 從**本機種子檔**讀原文（`--dir`，預設 `demo/seed`），可信入口設定由
   `demo/cli.py` 宣告（值取自 `tests/fixtures/o6/approved-sources.json` 已登記的手動匯入來源），
   組成 manual batch payload。原文不由 CLI 捏造，測試直接斷言 `inner["text"]` 非空。
2. **`rules_for_content` 在剛種好的表上直接炸。** P56 的種子把 `R-012` 寫成 `status: active`，
   但**沒有**產生 `operations/rules/validated_at.json`（那份檔只有 P55 的 `apply_rule_status`
   會寫），所以 P19 的 `select_active_rules` 丟
   `PermanentError: 缺少最近驗證時間：R-012`。**解法：** 測試先用 `pytest.raises` 把這件事
   證出來，再用 `apply_rule_status` 補齊兩條規則後往下跑；缺口寫進 Phase 文件與本報告 §9。
3. **D-68 字面上的 `rules_applied == ["R-007"]` 在這份種子下不成立。** `R-012` 也是 active
   （`applies_when=read`），而 `create_first_version` 走 `ALL_STEP_TYPES`，所以正式版本會是
   `["R-007", "R-012"]`。**解法：** 改驗「`R-007` 確實被注入並記進 `rules_applied`，而且
   `applied_count` 只被正式版本加一、不被兩份預覽加」，並在 Phase 文件標「本計畫選擇」。
4. **moto 上完整 `apply_seed` 要十秒級**（P56 報告已記）。**解法：** 整合測試用
   `dataclasses.replace` 把 bundle 裁成兩篇教學（工單／規則／Feature 全留），
   單次 `apply_seed` 降到 0.5 秒，八個測試合計 9.3 秒。
5. **Dashboard 要有資料，但不想在展示頁寫業務邏輯，也不想為了畫圖去接真實表。**
   **解法：** `demo/view_model.py:SeedRepository` 把 `SeedBundle` 包成唯讀 Repository 形狀
   （只有讀取方法），`load_dashboard()` 是 `dashboard.py` 唯一要呼叫的函式。指標仍由
   P53／P54 現算，離線可用（P56 §7.2 第 4 條）。
6. **守門測試自己打到自己**：`demo/view_model.py` 的 docstring 裡寫了守門用的 regex 字面值，
   被 `test_demo_package_has_no_second_metric_formula` 掃到。**解法：** docstring 改成指向
   守門測試的名稱，不重複貼 regex。
7. **`mypy` strict 與 `boto3.client(service: str)`。** 本專案不用 `# type: ignore`，
   改成把工廠函式本身收成 `Any`（與 `Repository` 的 `client: object` 同一條慣例，00A §6.3）。
8. **`streamlit run` 沒有非互動輸出。** 腳本只在瀏覽器連上時執行，所以另外用官方的
   `streamlit.testing.v1.AppTest` 實跑一次（見 §3.5(f)），兩種都留了原文。
