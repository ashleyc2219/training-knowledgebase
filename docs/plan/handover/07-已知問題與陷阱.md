# 07 已知問題與陷阱

> 前人踩過的坑，分「環境」「AWS 行為」「程式行為」「已知但刻意沒修」四類。遇到奇怪狀況先來這裡對一下。

---

## 1. 環境與工具

| 症狀 | 原因 | 怎麼辦 |
|---|---|---|
| 打 `node` 出現 `Security: node blocked in workspace` | 終端機的 shell 設定把 `node` 定成會拒絕的函式（AI 助手的沙盒保護） | 用 `command npx aws-cdk@2 ...`；一般人的終端機可能沒這問題 |
| `aws` 指令找不到資源 | 你的 AWS CLI 預設區域是 `ap-northeast-1`，專案在 `us-east-1` | 每個指令加 `--region us-east-1` 或 `export AWS_DEFAULT_REGION=us-east-1` |
| `uv run` 讀不到 `.env` | `uv run` 不會自動載入 `.env` | `set -a; source .env; set +a` 或在指令前 `export` |
| `cdk deploy` 印 `[infra] 跳過 TrainingKbApp` 然後只部署了 Data stack | 缺 `TKB_GITHUB_WEBHOOK_SECRET`、`TKB_CONTENT_BUCKET`、或 layer 沒建 | 看 stderr 缺哪個；補上再跑。這個「跳過」是刻意的（讓 Data stack 能單獨部署），但容易誤以為部署成功 |
| Lambda 第一次呼叫 `Runtime.ImportModuleError: No module named 'pydantic'` | layer 沒建、或在本機（arm64 Mac）裝出來的 wheel 不是 x86_64 | `uv run python -m infra.scripts.build_lambda_layer`（它固定打 x86_64 manylinux wheel）再部署 |
| 測試跑出一堆 `skipped` | 標 `aws` 的測試沒設 `TKB_RUN_AWS_INTEGRATION=1` | 正常。要跑就設變數 ＋ `TKB_CONTENT_BUCKET` |
| 測試出現少數 `xfailed`／`skipped` | 需要真 AWS 或 Bedrock 的測試 | 正常；模型開通後那幾條會自己變綠 |
| `-W error` 讓第三方套件的 warning 把測試弄紅 | 專案規定任何 warning 都算失敗 | 用 `pyproject.toml` 的 `filterwarnings` 精準壓那一條，不要全域關 |

## 2. AWS 的真實行為（moto 模擬不出來的）

| 事實 | 影響 |
|---|---|
| **Step Functions 的 `Retry.ErrorEquals` 只比對例外的類別名字串，不認繼承** | 程式丟 `TransientError` 的子類不會被重試。故障注入曾因此差點做出「假的重試證據」，現在 `faults.py` 一律丟本尊 |
| **直接用函式 ARN 當 Task Resource 時，失敗事件的欄位是 `lambdaFunctionFailedEventDetails`**，不是文件常見的 `taskFailedEventDetails` | 查 execution history 或寫斷言時要用對欄位名 |
| **DynamoDB 的 IAM 沒有「排序鍵」條件** | 沒辦法用 IAM 限制「只能刪 `SK` 以 `APPLIED_TO#` 開頭的項目」，改成程式層 `DELETABLE_RELATIONS` 守門 ＋ 單表 `DeleteItem` |
| **DynamoDB 和 S3 做不成一個交易** | 多篇發布的「半新半舊」窗口真的存在（O3 FAIL）；`resume_publish` 能補完，但補之前外面看得到 |
| **S3 website endpoint 只有 HTTP** | 公開站沒有 HTTPS；bucket 原本的「強制 SSL」Deny 已拿掉，否則網站打不開。要 HTTPS 得加 CloudFront（設計目前不允許） |
| **GSI 可能落後** | 所有走 `by_target` 反查的地方都會回基表核對一次；moto 的 GSI 是即時的，所以本機測不出落後 |
| **`sts:GetCallerIdentity` 不需要任何權限** | 之前多授了一條 `Resource: "*"`，已移除；不要再加回去 |
| **Lambda 預設的 log 格式不吐 `INFO`** | `handlers/import_.py` 的 `_log.info` 在 CloudWatch 看不到；要看得改 `_function()` 的 `LoggingConfig`（會影響四支 Lambda，尚未做） |
| **同一秒內兩次 `start-execution` 用同名會撞** | 測試的 execution name 都帶時間戳或 run-id |

## 3. 程式行為上要知道的事

| 事實 | 在哪 | 為什麼這樣 |
|---|---|---|
| `find_release_hits` **會**命中已退役的教學 | `pipelines/release.py` | 反查層維持忠實（設計 D-38）；`prepare_update` 在 UPDATE 那一步才跳過退役的，並記 log |
| `removed` 改版就算零命中也會 RETIRE | `release.py` `_release_action` | 退役是功能層級的事，不看有沒有步驟提到它 |
| `retire.json` 的 `successor` 記的是「維護者要求的值」，不是「實際寫入的值」 | `release.py` `task_retire` | 後繼不合法時 `retire_tutorial` 不會寫，但紀錄保留原始要求供追查 |
| 同一天重跑已成功的回饋檢視，不會再產生新版本 | `feedback.py` `_guard`（F23） | 同一批證據已經產過完整且**已發布**的版本；若上次「產了版本但沒發布」，會改成重新發布那一版 |
| 回饋檢視的診斷結果會存成 `operations/<op>/diagnose-weak.json` | `feedback.py` | 重送時重用，不再問模型；舊的改寫結果若和診斷對不上會丟掉重叫 |
| 匯入批次：**形狀**錯 → 整批 `PermanentError` 零寫入；**資料**錯 → 只拒那一筆 | `handlers/import_.py` | 形狀錯代表匯出檔壞了；資料錯是單筆的事 |
| 回饋 ID 必須 `f_` 開頭 | `ingress.py` `FEEDBACK_ID_PREFIX` | 本計畫選擇（00A 沒規定）；widget 產生的 ID 都符合 |
| `View` 的 `ts` 不能有微秒、不能缺 | `ingress.py` | 看過的時間是「重開票」指標的前提，不能補假值 |
| `select_weak_targets` 只看 **current 且已發布**的版本 | `feedback.py` `current_published_versions` | 舊版與未發布版的評分不算 |
| 規則狀態只會從 `candidate → active → retired` 單向走，且只有 `status_writer` 能寫 | `analytics/status_writer.py` `LEGAL_TRANSITIONS` | 單一寫入點 |
| `validate_rules` 只看「這一次呼叫」帶進來的批次 | `handlers/analytics.py` | 要判「連續兩批未改善」，呼叫端必須一次把該規則的全部批次帶進來；分批呼叫永遠退役不了（已在 docstring 寫明） |
| `TKB_ENV` 的比對是 `.strip().lower() == "prod"` | `faults.py` `is_production` | `Prod`、`prod ` 都算正式 |
| `demo.cli seed --apply` 與 `cluster_demo_tickets.py --write` 在 `TKB_ENV=prod` 時拒絕 | `demo/` | 防止把合成資料寫進正式環境 |
| `TrainingKbApp` 用**純字串名稱**接 table 與 bucket，沒有跨 stack 參照 | `infra/training_kb_stack.py` | 兩個 stack 可以各自 `--exclusively` 部署 |

## 4. 已知但刻意沒修的（下次有空再處理）

這些都在最終 review 被指出，判斷「不影響正確性、先記下來」。若你要動到那個檔案，順手處理。

| 項目 | 位置 | 說明 |
|---|---|---|
| `check_iam` 抓不到部分萬用字元（`s3:*Object`）、看不到 `ManagedPolicyArns` | `infra/scripts/checks.py` | 目前四支 Lambda 都掛 `AWSLambdaBasicExecutionRole`，它的 `logs:*` 不在檢查範圍 |
| `check_public` 對 `Principal: {"AWS": ["*", "arn:…"]}` 這種混合寫法會漏掉；不讀 Block Public Access 設定 | `checks.py` | 目前 bucket policy 沒這種寫法 |
| `_row_status` 只要證據欄非空就算 `pass`，不檢查檔案存不存在 | `checks.py` | 驗收表的 Rule 列是「測試收集得到且整套綠」，不是「那一條單獨跑過」 |
| 部署時 shell 若有 `TKB_ENV=demo`，會被烤進 Lambda | `infra/training_kb_stack.py` `base_env` | 部署前檢查清單第 1 項；可加一個 synth 時的拒絕 |
| `_grant_data` 的預設值仍是最寬集合 | `infra/training_kb_stack.py` | 目前所有呼叫都明寫參數，預設值沒人用；可改成必填 |
| Lambda `LoggingConfig` 未開 `INFO` | `infra/training_kb_stack.py` `_function()` | 見上表 |
| 冷啟動時、在 `deps_for` 之前發生的失敗（例如注入的 `TKB_FAULT_TASK`）不會寫進 ledger | `pipelines/common.py` | 真實失敗都發生在之後；演練用開關本來就不該在正式環境設 |
| `TKB_FAULT_TASK` 只驗格式與 pipeline 名，task 名打錯會靜靜不注入 | `pipelines/common.py` | 演練時看 execution history 就知道有沒有注入 |
| `feedback.py` 與 `release.py` 各有一份 `_rules_for_hits`／`_assert_unchanged`／`_apply_rewrite` | 兩支檔 | 已對齊檢查項目，但仍是兩份；可抽到共用模組 |
| `_semantic_match` 對每個候選 Feature 各算一次 embedding，沒快取 | `release.py` | Feature 數量少時無所謂 |
| `analytics/version.py` 每個版本都掃一次全部工單 | `analytics/version.py` | 資料量大時要改成查詢 |
| `update_feature_aliases` 的唯一性檢查不是併發安全的 | `release.py` | 兩個改版同時改名到同一個別名時可能都過 |
| `render_site_index` 把退役教學列出但沒標示 | `site.py` | 退役提示在該篇的教學索引頁（設計只要求那裡） |
| 舊的功能資料夾頁不會自動刪 | `publishing.py` `_write_site_index` | 資料夾頁只重建、不刪；某功能不再被任何教學引用時，它的 `site/features/<slug>/index.html` 會留著但沒有連結指過去。要清就 `aws s3 rm` |
| 真 AWS 的回饋檢視測試會刪掉「當天」的 `OPS#<review op>` 紀錄 | `tests/integration/test_feedback_review_state_machine.py` | 若正式排程當天已跑過，測試清理會把它的紀錄一起刪；建議改用不同 project_id |
| P41 報告 §8 的 commit 表沒列修正回合的 commit | `docs/plan/report/phases/2026-09-14-Phase41-REP.md` | 文件而已 |

## 6. 曾經發生過的事故（避免重蹈）

| 事故 | 原因 | 現在的規矩 |
|---|---|---|
| 一個 commit 從分支上消失（後來補回） | 多個 AI 助手同時提交，其中一個用了 `git commit --amend` ＋ `git reset` | **禁止 amend／reset／rebase**，要補就開新 commit |
| 真 AWS 測試把公開站的 `site/index.html` 覆寫成只剩測試資料（後來還原） | 測試的 seed 直接寫共用的索引頁 | 測試不再寫共用索引；fixture 會先備份再還原 |
| 安全檢查抓到自己的測試檔含「像金鑰的字串」 | 測試檔 docstring 有範例 | 改測試檔的寫法，**不放寬檢查** |
| 一個空的 `build/lambda-layer/python/` 目錄讓部署守門通過，Lambda 上線才炸 | 守門只檢查目錄存在 | 現在檢查 `pydantic`、`jsonschema` 真的在裡面 |
| `streamlit run demo/dashboard.py` 找不到 `demo.view_model` | Streamlit 只把 `demo/` 放進 `sys.path` | 儀表板已於 2026-09-17 整個移除（Demo 用公開站與命令列即可） |
