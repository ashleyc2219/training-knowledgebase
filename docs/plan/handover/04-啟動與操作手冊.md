## 1. 操作時會碰到的三條流程

工單／改版／回饋 → 接入層 → Step Functions → 表＋S3 → 公開站。


| 流程                | 何時               | 做什麼            |
| ----------------- | ---------------- | -------------- |
| `ticket-analysis` | 每張工單             | 分群；同群滿 5 張寫新教學 |
| `feedback-review` | 每日 UTC 00:30 或手動 | 改低分步驟、提規則      |
| `release-update`  | 每筆改版             | 改提到該功能的步驟；功能移除則退役 |


寫教學走 Bedrock。帳號沒開通時那些步驟會 `PipelineFailed`，不是程式壞掉（見 05）。

## 2. 本機設定（`.env`）

本機：Python 3.12、`uv`（指令一律 `uv run`）、AWS CLI。Region 用 `us-east-1`。部署用的 Node／CDK／密鑰見 05。

讀取順序（`load_settings`、`demo/scripts/publish_site.sh`）：已 `export` 的非空值 → `.env` 裡非空的 `TKB_` 鍵 → 仍缺就停。`cdk deploy` 只讀當下 shell，不讀 `.env`。

複製 `.env.example` 成 `.env`。本機碰雲端至少要：


| 鍵                    | 用途                                           |
| -------------------- | -------------------------------------------- |
| `TKB_AWS_REGION`     | `demo.cli` 沒設會拒絕；通常 `us-east-1`              |
| `TKB_CONTENT_BUCKET` | Data stack 輸出的 `TrainingKbBucketName`，不要抄別人的 |


可選／有預設：`TKB_TABLE_NAME`（`training_kb`）、`TKB_PROJECT_ID`（`demo`）、模型三鍵（未開通留空，見 05）。不要設 `TKB_ENV=demo`、`TKB_FAULT*` 再去部署。真 AWS 測試才設 `TKB_RUN_AWS_INTEGRATION=1`。讀取：`src/training_kb/config.py`。

## 3. 本機指令

```bash
uv run pytest tests -q -W error
uv run ruff check src tests infra demo
uv run mypy
uv run python -m infra.scripts.check_asl
uv run python -m demo.cli --help
```


| 子命令                                | 做什麼                                         | 碰雲端？                                      |
| ---------------------------------- | ------------------------------------------- | ----------------------------------------- |
| `seed`                             | 檢查種子；`--apply` 才寫表／私有 S3（`TKB_ENV=prod` 拒絕） | 僅 `--apply`                               |
| `trigger-ticket`／`upload-tickets`  | 送測試工單                                       | 是（`training-kb-import`；`github_issue` 不送） |
| `trigger-release`／`trigger-review` | 改版／每日回饋                                     | 是                                         |
| `import`                           | widget 下載檔                                  | 是                                         |
| `metrics`                          | 評分／重開票                                      | 是（`training-kb-analytics`）                |


工單檔在 `demo/test-tickets/<主題>/<來源>/<格式>/`，本機由 `demo/ticket_files.py` 轉成 JSON 再 invoke。加主題：複製同一套格子。從種子重拆：`uv run python -m demo.scripts.export_test_tickets`。丟工單不會立刻改公開站；要滿群、模型開通、發布成功才會出新頁。

## 4. 公開教學站

沒有「改 HTML 再上傳」。畫面 `src/training_kb/site.py`（`group_by_feature`、`render_*`），樣式 `demo/site_assets/`，寫入 `src/training_kb/publishing.py` 的 `Publisher`。上線：`demo/scripts/publish_site.sh`（`--assets`／`--pages`／`--index`）。


| 你改的         | 檔                           | 備註                         |
| ----------- | --------------------------- | -------------------------- |
| CSS／widget  | `demo/site_assets/`         | `--assets`；舊版本頁也會套到新 CSS   |
| 首頁／資料夾／版本紀錄 | `site.py` 的 index 三個 render | `--index`；可覆寫              |
| 版本頁版面       | `render_version_page`       | 已發布 `v<n>.html` 不可覆寫       |
| Demo 正文     | `demo/seed/*.json` → `seed --apply` → `--pages` | 種子只寫庫；只補缺頁        |
| 線上正文        | 三條 pipeline                 | `Publisher.commit` 才寫 `site/` |


結構：`site/index.html`、`site/features/<功能>/`、`site/tutorials/<slug>/`。一篇教學可出現在多個功能資料夾。第一次把種子頁推上公開站見 05。

**站台一律英文**（2026-09-17 起）：畫面文字在 `site.py` 頂端的常數與 `widget.js`，種子正文 `demo/seed/`（tutorials／versions／steps）也是英文；回饋類別預設值改成 `Button not found`／`Missing information`（`ingress.py` 的 `DEFAULT_FEEDBACK_CATEGORIES`）。改了種子檔就要重簽 `demo/seed/approvals/*.json` 的 `seed_commit`（值＝`seed_digest(Path("demo/seed"))`），不然 O7 會變成未核定。已發布的版本頁不會自動換語言：要換就得先刪掉 `site/tutorials/<slug>/v*.html`、`v*.diff.txt` 與私有 `tutorials/<slug>/v*.md`、`v*.diff`，再 `seed --apply` → `--pages`。

## 5. 事件怎麼進來


| 入口           | 去哪                                                                        |
| ------------ | ------------------------------------------------------------------------- |
| GitHub Issue | webhook Function URL（部署輸出 `WebhookFunctionUrl`）＋與部署相同的 Secret；事件勾 Issues |
| 測試工單／改版      | `demo.cli` → import Lambda                                                |
| widget 回饋    | 頁面下載檔 → `demo.cli import`                                                 |
| 每日回饋         | EventBridge 排程，或 `trigger-review`                                         |


第一次接 GitHub 見 05。`ticket-analysis`／`release-update` 不要空手 `start-execution`，表裡要先有工單／改版。

四支 Lambda 共用同一份 `src/` zip，差在 handler（`infra/training_kb_stack.py`）：


| Lambda                      | 進門                                                   | 何時被叫                         |
| --------------------------- | ---------------------------------------------------- | ---------------------------- |
| `training-kb-webhook`       | `training_kb.handlers.github_webhook.handler`        | GitHub HTTP（唯一 Function URL） |
| `training-kb-import`        | `training_kb.handlers.import_.handler`               | `demo.cli` 匯入工單／回饋           |
| `training-kb-pipeline-task` | `training_kb.pipelines.common.pipeline_task_handler` | 三條 Step Functions            |
| `training-kb-analytics`     | `training_kb.handlers.analytics.handler`             | `demo.cli metrics`           |


pipeline-task 再依 event 的 `pipeline`／`task` 分派：`src/training_kb/pipelines/common.py`。

## 6. 結果與 log


| 想看    | 哪裡                                                                         |
| ----- | -------------------------------------------------------------------------- |
| 公開站   | `http://<bucket>.s3-website-us-east-1.amazonaws.com/site/index.html`       |
| 流程走到哪 | 主控台 Step Functions → Executions                                            |
| Log   | `/aws/vendedlogs/states/training-kb-*`、`/aws/lambda/training-kb-*`（留 90 天） |
| 指標    | `demo.cli metrics --version <id>`                                          |
| 表裡一筆  | DynamoDB `training_kb`；鍵算法在 `src/training_kb/keys.py`                      |


失敗事件看 `lambdaFunctionFailedEventDetails.error`：`TransientError` 已重試；`PermanentError` 多半是資料或模型未開通；`PublishError` 是發布切點。

改 `src/` 或 `infra/` 後要重部署 App（先 `build_lambda_layer`，shell 要密鑰與桶名，不要帶 `TKB_ENV=demo`）。檢查清單見 05。

## 7. 常見問題（操作）


| 現象                            | 先看                                                 |
| ----------------------------- | -------------------------------------------------- |
| `[infra] 跳過 TrainingKbApp`    | 密鑰、`TKB_CONTENT_BUCKET`、layer 三者缺一（`infra/app.py`）；第一次部署見 05 |
| `No module named pydantic`    | 重跑 `build_lambda_layer` 再 deploy                   |
| `demo.cli` 要 `TKB_AWS_REGION` | `.env` 或 export                                    |
| `publish_site.sh` 要 bucket    | 抄自己的 `TrainingKbBucketName`                        |
| webhook 簽名不符                  | GitHub Secret 與上次 deploy 的密鑰不一致                   |
| 整合測試 skip                     | 正常；要跑再設 `TKB_RUN_AWS_INTEGRATION=1`                |
| 流程停在模型節點                     | 見 05（O5）                                           |
