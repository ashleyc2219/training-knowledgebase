## 2. 第一次部署（表、S3、Lambda）

- [ ] 完成

本機還要：Node／`npx aws-cdk@2`、AWS CLI、`~/.aws/credentials`。Region 用 `us-east-1`。


| 要備的東西               | 是什麼                                                    | 相關程式                                                                                           |
| ------------------- | ------------------------------------------------------ | ---------------------------------------------------------------------------------------------- |
| AWS 憑證              | 決定部署進哪個帳號                                              | `~/.aws/credentials`（不在 repo）                                                                  |
| CDK 入口              | 怎麼啟動 synth／deploy                                      | `cdk.json` → `infra/app.py`                                                                    |
| 表、S3、公開站 policy     | Data stack `TrainingKbData`；表名固定 `training_kb`；桶名部署後才有 | `infra/training_kb_data_stack.py`                                                              |
| 4 支 Lambda、3 條流程、排程 | App stack `TrainingKbApp`                              | `infra/training_kb_stack.py`                                                                   |
| Lambda 依賴 layer     | `pydantic`／`jsonschema`（Linux x86_64）                  | `infra/scripts/build_lambda_layer.py` → `build/lambda-layer/`                                  |
| 流程定義                | ASL 快照                                                 | `infra/stepfunctions/<pipeline>/v1.json`、`infra/scripts/check_asl.py`                          |
| Webhook 密鑰          | 烤進 webhook Lambda                                      | 部署當下的 `TKB_GITHUB_WEBHOOK_SECRET`（不要寫進 `.env`）                                                 |


換帳號從零：該帳號 `us-east-1` 先 `cdk bootstrap` → 部署 Data → 抄輸出的桶名 → 建 layer → 部署 App（shell 要密鑰與 `TKB_CONTENT_BUCKET`）。缺前提時 `infra/app.py` 會跳過 App stack，不是報錯。表與桶是 `RETAIN`，刪 stack 不會刪資料。

四支 Lambda 的進門與何時被叫見 04。本機對準雲端的 `.env` 也見 04。

**做完：** Data 有 `TrainingKbBucketName`／`TrainingKbSiteUrl`；App 印 `✅ TrainingKbApp`，沒有 `[infra] 跳過`。

## 3. 開通 Bedrock（O5）

- [ ] 完成

**現況：** 帳號還沒有模型使用權。呼叫會被回 `ValidationException: Operation not allowed`，程式再包成 `PermanentError`（`O5 尚未通過`）。證據：`docs/plan/report/o5-20260915T030245Z.md`。這不是 bug。

**要開什麼：** `us-east-1` 的 Bedrock Model access：`Titan Text Embeddings V2` ＋ 一個 Claude（Haiku 4.5 或 Sonnet 4.5）。候選順序寫在 `check_models.py` 的 `PREFERRED_*`。

**通過後做三件事（不要猜 model ID）：**

1. `uv run python -m infra.scripts.check_models`——兩列 `ok`。
2. 把腳本印出的 ID 填進 `.env` 的 `TKB_BEDROCK_REGION`／`TKB_EMBEDDING_MODEL_ID`／`TKB_GENERATION_MODEL_ID`（範本 `.env.example`；讀取 `src/training_kb/config.py`）。未通過前這三鍵留空。
3. 打開 `infra/training_kb_stack.py`，搜 `TKB_GENERATION_MODEL_ID`：把實測 ID 加進 `base_env`，並把生成模型 ARN 加進 `bedrock:InvokeModel`（webhook／task／import 三處，照旁邊 Titan 那行）。然後做第 3 項重部署。

**做完：** `training-kb-ticket-analysis` 能走過 `NameGap`（`src/training_kb/pipelines/ticket.py`）。

**沒核准也能 Demo：** 公開站、`metrics`、`trigger-review`（零目標時 SUCCEEDED）、`trigger-release` 的退役路徑。避開要寫新教學／改步驟的畫面。

- [ ] 完成
