## 2. 每個檔案在做什麼

### 基礎層（沒有它們什麼都動不了）

| 檔案 | 責任 | 改它之前想一下 |
|---|---|---|
| `models.py` | 十個資料實體（Tutorial、TutorialVersion、TutorialStep、Feature、Ticket、Release、Feedback、TutorialView、AuthoringRule、ProvenWorkflow）與七個列舉；全部是嚴格的 pydantic model（多一個欄位就報錯） | 加欄位會影響 DynamoDB 裡既有資料的讀取 |
| `keys.py` | 把實體變成 `PK`／`SK` 的**唯一**地方（`tutorial_pk(slug)`、`edge_sk(...)`…） | 程式其他地方不准自己拼 `TUTORIAL#` 字串 |
| `errors.py` | 例外階層：`TransientError`（會重試）、`PermanentError`（不重試）及其子類 `IngressError`、`ContentError`、`ObjectAlreadyExists`…；`PublishError`、`CoordinationError` 是獨立的 | 流程的 Retry 只認類別名 |
| `clock.py` | 時間格式：只接受整秒 UTC 的 ISO 字串（`to_iso`／`parse_iso`） | 微秒會被拒絕，這是刻意的 |
| `config.py` | `Settings`（從 `TKB_*` 環境變數讀）與 `Thresholds`（0.85、5、5、10、8、3.5 六個門檻） | 門檻只在這裡改 |
| `vectors.py` | `cosine`、`centroid` 純函式 | — |
| `source_ids.py` | 來源 ID 的確定性編碼（同一個 Issue 永遠算出同一個 ticket id）、穩定使用者編碼、來源核定表讀取 | 五種來源都已核定（Demo 用途）；加新來源要同步 `rote.py` 的 `STABLE_KEYS` |

### 儲存層

| 檔案 | 責任 | 改它之前想一下 |
|---|---|---|
| `repository.py` | 所有 DynamoDB／S3 讀寫：`put_meta`／`get_meta`／`update_meta`（帶 `_revision` 樂觀鎖）、關係邊、`query_by_target`（GSI）、`transact_write`、`put_object(if_none_match=True)` | 唯一能看到 `PK`／`SK` 的檔案；`delete_edge` 只准刪 `APPLIED_TO` |
| `operations.py` | operation ledger：`accept`（永久去重）、`complete`、`fail`、`record_execution`、版號序列、租約 | 這是 O2 的核心，動它要重跑 `tests/integration/test_o2_cases.py` |

### AI 邊界（只有這裡能碰 Bedrock）

|---|---|
| `writing/client.py` | `Writer` 介面與 `BedrockWriter`；每次呼叫記錄 attempt（`CallTrace`）；模型參數（判斷類 512 tokens、寫作類 2048 tokens、temperature 0.1） |

## 3. 誰可以呼叫誰（依賴方向）

```
handlers/*  ──▶  ingress ──▶ rote ──▶ adapters
    │                │
    │                └──▶ operations、repository、pipeline_starter
    ▼
pipelines/{ticket,feedback,release} ──▶ content、publishing、rules、writing、analytics、repository、operations
pipelines/common ──▶ pipelines/{ticket,feedback,release}（延後 import，只在分派時）
publishing ──▶ site、content、repository
analytics/* ──▶ repository、writing/client（只讀 CallTrace）
所有人 ──▶ models、keys、errors、clock、config
```

原則：**下層不 import 上層**。例如 `repository.py` 絕不 import `pipelines`；`site.py` 絕不 import `publishing`。違反的話會出現循環 import，測試會直接爆。

## 6. tests/

```
tests/
├── conftest.py               aws marker 自動 skip；Rote 用的 fixture
├── unit/                     純本機、不碰 AWS（69 檔）
│   ├── conftest.py              RecordingWriter（假 Bedrock）、FIXED_EMBEDDING、P55 的合成 fixture
│   ├── pipelines/               三條流程的 Task 級測試（12 檔）
│   ├── rote/                    接入層（6 檔）
│   └── infra/                   CDK template 斷言（4 檔）；conftest 有 fake_layer
└── integration/              用 moto 假 AWS（45 檔）；標 @pytest.mark.aws 的是真 AWS
    └── conftest.py              table／bucket／repository fixture（moto）
```

- **測試檔名全專案唯一**（`tests/` 沒有 `__init__.py`）；新檔案先 `ls tests/**/test_*.py | grep 名字` 確認沒撞。
- 每個 Phase 用哪些測試檔證明哪條需求，查 `docs/plan/unfinish/00B-需求覆蓋對照.md` 第 2 節。
- `-W error`：任何 warning 都算失敗。第三方套件的 warning 要用 `filterwarnings` 精準壓，不要全域關。
