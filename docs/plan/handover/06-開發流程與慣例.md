# 06 開發流程與慣例

> 這個專案有幾條「不成文但大家都守」的規矩。守著它們，你改的東西才不會被測試或 review 打回來。

---

## 1. 改程式的固定步驟

```
1. 查名稱 ──▶ 2. 先寫會失敗的測試 ──▶ 3. 寫最少的程式讓它過 ──▶ 4. 跑三個檢查 ──▶ 5. commit ──▶ 6. 部署（若動到 src/ 或 infra/）
```

### 步驟 1：查名稱（00A）

任何函式名、欄位名、檔案路徑、環境變數、AWS 資源名，先在 `docs/plan/unfinish/00A-共用契約與名詞.md` 搜一下：

```bash
grep -n "你要找的名稱" docs/plan/unfinish/00A-共用契約與名詞.md
```

- 00A 有寫的，照它用，不要自己取別名。
- 00A 沒寫的新東西，做完後把它加進 00A 對應章節（§3.2 檔案 owner、§5 欄位、§6 各模組簽名、§8 決策清單）。
- 00A 和程式碼不一致時，**程式碼＋設計文件為準**，順手改 00A 並加「（<日期> 同步）」。

### 步驟 2：先寫會失敗的測試（TDD／BDD）

- 測試名稱用「Given／When／Then」的意思寫，例如 `test_resend_same_operation_reuses_version_number`。
- 先跑一次確認它**因為正確的理由**失敗（`cannot import name ...`、`AttributeError`、斷言失敗），不是 `SyntaxError`。
- 測試要驗**結果**（表裡有什麼、S3 有什麼、回傳值），不要只驗「某個 mock 被呼叫幾次」。
- 放哪裡：純邏輯 → `tests/unit/`；要 DynamoDB／S3 → `tests/integration/`（用 moto fixture）；要真 AWS → `tests/integration/` 加 `@pytest.mark.aws`，而且要**自己 seed、自己清乾淨、缺 `TKB_CONTENT_BUCKET` 就 skip**。
- 檔名全專案唯一（`tests/` 沒有 `__init__.py`）。

### 步驟 3：寫最少的程式

- 一個檔案一個責任（03 的地圖）；不要把新邏輯塞進不相干的檔案。
- 既有函式能用就用，不要複製一份改兩行（review 會抓「逐字重複的邏輯區塊」）。
- 下層不准 import 上層（03 第 3 節）。

### 步驟 4：三個檢查全綠

```bash
uv run pytest tests -q -W error          # 任何 warning 都算失敗
uv run ruff check src tests infra demo   # 風格
uv run mypy                              # 型別（strict）
```

不要跑 `ruff format` 在既有檔案上（舊檔沒格式化過，會產生一堆無關 diff）；新建的檔案可以。

### 步驟 5：commit

格式：`<type>(<scope>): <subject>`，subject 用繁體中文、50 字以內。

```
feat(feedback): 弱教學診斷只回命中步驟
fix(infra): 匯入角色不得碰公開站
test(release): 驗證改版重送同版號
docs(plan): 更新 Phase 51 文件
chore(deps): 升級 pytest
```

type 只有 `feat|fix|docs|style|refactor|perf|test|chore|revert`。

規矩：
- 只 `git add` 你改的檔案路徑，不用 `git add -A`／`git add .`。
- **不要 `git commit --amend`、`git reset`、`git rebase`**（多人同時提交時曾把別人的 commit 輾掉）。要補東西就再開一個 commit。
- 不提交：`.env`、`build/`、`cdk.out/`、任何 outputs 或憑證檔。

### 步驟 6：部署

改了 `src/` 或 `infra/` 就要重部署 `TrainingKbApp`，檢查清單見 05「之後改程式要重部署 App」。部署後：
- 真 AWS 測試：`TKB_RUN_AWS_INTEGRATION=1 TKB_CONTENT_BUCKET=... uv run pytest tests/integration/test_*_state_machine.py -q`
- 安全檢查：`uv run python -m infra.scripts.checks security ...`

## 2. 幾條硬規則（違反就是 bug）

| 規則 | 為什麼 |
|---|---|
| Lambda handler **不准** `try/except` 把例外吞掉 | Step Functions 靠例外的類別名決定要不要重試；吞了就沒有重試也沒有失敗紀錄 |
| 程式丟的一定是 `TransientError`／`PermanentError` 本身或它們的子類；**故障注入只准丟本尊** | ASL 的 `ErrorEquals` 只比類別名字串，不認繼承 |
| 流程的 state 只放 ID 和 S3 key，**不放全文、向量、模型輸出** | execution history 是可查的，不能洩露內容；也避免超過 256 KB |
| 同一個 `operation_id` 重送 → 同版號、不重呼叫模型、不重複計數 | O2 的核心；`tests/integration/test_o2_cases.py` 守著 |
| 只有 `Publisher` 能切 `published_at`／`current_version`；只有 `status_writer` 能改 `RULE.status` | 單一寫入點，狀態才追得到 |
| 已發布的版本頁不可覆寫（`put_object(if_none_match=True)`） | 讀者看到的東西不能事後變 |
| 公開的只有 `site/`；Lambda 只給它需要的最小權限；webhook role 不能碰 `site/` | 安全檢查 `checks security` 會抓 |
| 不可信文字進 prompt 一律過 `_as_data`（跳脫）放進 `<source_data>` | 防 prompt injection |
| 零分母的指標回 `None`，不是 `0` | 「沒資料」和「0%」是兩件事 |
| 模型 ID 開通前留空，不填猜的 | 填錯的 ID 只會在雲端第一次呼叫時才爆 |

## 3. 改到流程定義（ASL）時

1. 改 `pipelines/<x>.py` 的 `*_TASKS` 順序或 Task 名稱。
2. 改 `infra/stepfunctions/<x>/v1.json` → **升成 `v2.json`**（快照不可覆寫）。
3. 每個 Task state 必須是 `pipelines/asl.py` 的 `task_state(...)` 加上 `Parameters: {pipeline, task, "state.$": "$"}`，測試會逐字比對。
4. `uv run python -m infra.scripts.check_asl` 要過。
5. 部署前用 `save_asl_snapshot` 把同一份 bytes 存到 S3 `stepfunctions/<x>/v2.json`。

---

## 4. 改到 IAM 時

- 用 `_grant_data(role, prefixes=..., actions=..., with_index=...)` 明寫最小集合，不要用預設值。
- `tests/unit/infra/` 有負面斷言（例如「import role 的 S3 資源不含 `site/*`」、「analytics 沒有 `PutItem`」）；加權限前先看它們。
- `Resource: "*"` 只允許 CloudWatch Logs 那組；其他會被 `checks security` 抓。

## 5. 文件要跟著改哪些

| 改了什麼 | 要更新 |
|---|---|
| 公開名稱、簽名、環境變數、AWS 資源 | `00A` 對應章節 |
| 做了一個設計決定 | `00A` §8 加一條 D-<下一號>（目前到 D-107） |
| 某條需求的測試檔換了 | `00B` §2 那一列 |
| 系統行為或操作方式 | 這個 handover 資料夾的 02／04 |
| 完成一個大功能 | `docs/plan/report/` 寫一份 REP（格式參考 `phases/` 裡任一份：實作內容、步驟、測試證據、問題與解法、結果） |

## 6. 用 AI 助手（Claude Code 等）開發時

前人的做法，供參考：
- 讓助手先讀 `00A` 相關段落與這個資料夾，再動手。
- 一次一個功能；先測試後程式；commit 只加自己的路徑；禁 amend／reset。
- 重要的改動（部署、IAM、發布、匯入）另外請一個獨立的 reviewer 看 diff；小改動不用。
- 所有需要維護者決定的事，助手應該「自己做一個保守的決定、寫進報告、繼續做」，不要停下來等；你事後看報告裡的「裁決」清單，不同意再改。
