## Demo 領域常數（所有 Example 共用）

- 資料集：[bitext/Bitext-customer-support-llm-chatbot-training-dataset](https://huggingface.co/datasets/bitext/Bitext-customer-support-llm-chatbot-training-dataset)（欄位 `instruction` / `category` / `intent` / `response`；27 intents / 10 categories；CDLA-Sharing-1.0）
- 主打三類 UserProblem（topic = intent）：`cancel_order`（ORDER）、`track_refund`（REFUND）、`change_shipping_address`（SHIPPING_ADDRESS）
- 對應 Feature：`Cancel Order`、`Track Refund`、`Change Shipping Address`
- 貫穿範例 Tutorial：`tutorials/cancel-order.md`，Step 3 `Click "Cancel Order"`；Release Note `"Cancel Order has been renamed to Cancel Purchase."` → Step 3 改 `Click "Cancel Purchase"`
- Feedback 貫穿範例：v1 avg rating 2.9（Step 3 反覆被抱怨）→ v2 avg rating 4.4
- 顧客範例：`customer_ref` = `alice@example.com`、`bob@example.com`

### 分析SupportTickets

| 檔名 | 答案 |
|---|---|
| 觸發CREATE的決策應屬於分析SupportTickets還是建立Tutorial | A：分析決定 CREATE，建立只產 v1 |

| 系統判斷Tickets語意相似並聚成同一主題的判定標準為何 | A：Given 已標同一 topic（Bitext intent）的 Tickets → Then 輸出該 topic；規格不驗演算法 |
| 聚集出recurring_topic後何時才識別為Knowledge_Gap | B：沒有 published Tutorial 才是 Knowledge Gap |
