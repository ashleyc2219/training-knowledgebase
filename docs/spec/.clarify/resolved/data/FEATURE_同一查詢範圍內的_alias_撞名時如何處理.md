# 釐清問題

同一查詢範圍內的 alias 撞名時如何處理？

# 定位

- 追蹤 ID：D07
- [FEATURE.aliases](../../erm.dbml)，第 93 行。
- [依改版更新教學，Rule 2「改名前後的 alias 對應同一個 Feature 節點」](../../features/依改版更新教學.feature)，第 12 行。

現況：來源沒有 alias 唯一性或撞名解法，任取第一個節點可能改到另一功能的教學。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | alias 必須唯一；新增或改名造成衝突時拒絕該次 alias 更新。 |
| B | 允許撞名，但必須取得額外產品情境才能對應；無法區分時列為未決事件。 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響 alias 索引、改名失敗行為，以及同名、大小寫與前後空白的正規化測試。

前置釐清：D06（見 overview.md）。
已解決前置：D01（MVP 固定單一專案）。

# 優先級

Medium

- 影響邊界行為、資料一致性或驗收完整性。

# 解決記錄

- **回答**：A - alias 必須唯一；新增或改名造成衝突時拒絕該次 alias 更新。
- **更新的規格檔**：docs/spec/erm.dbml、docs/spec/features/依改版更新教學.feature
- **變更內容**：同一專案內 alias 必須唯一，亦不可與其他 Feature 的 name 撞名；衝突拒絕該次更新。
