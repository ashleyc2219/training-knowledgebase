# 釐清問題

版本建立失敗後重試是否重用原版本號？

# 定位

- 追蹤 ID：D26
- [TUTORIAL_VERSION.version_id](../../../erm.dbml)，第 49 行。
- [TUTORIAL_VERSION.supersedes](../../../erm.dbml)，第 51 行。
- [建立教學版本，Rule 2「任一 pipeline 修改既有教學時使用該篇的下一個版本號」](../../../features/建立教學版本.feature)，第 14 行。

現況：正常情況已規定每篇從 v1 遞增，但沒有說明部分建立失敗是否消耗號碼；S3 路徑又由版本號決定。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 同一邏輯變更重試時重用原版本號；若永久失敗，後續版本可保留號碼缺口。 |
| B | 只有完成發布才消耗版本號；失敗重試與下一次成功都使用尚未發布的下一號。 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

決定版本識別的穩定性、supersedes 不分叉的限制，以及失敗後重試不覆蓋已發布內容的驗收。

前置釐清：D25（見 overview.md）。

# 優先級

High

- 阻礙核心資料契約或主要流程定義。

---
# 解決記錄

- **回答**：A - 同一邏輯變更重試時重用原版本號；若永久失敗，後續版本可保留號碼缺口。
- **更新的規格檔**：docs/spec/erm.dbml、docs/spec/features/建立教學版本.feature
- **變更內容**：同一邏輯變更失敗後重試重用原 version_id；永久失敗可不補號，後續版本允許號碼缺口。規格回寫由並行 agent 處理。
