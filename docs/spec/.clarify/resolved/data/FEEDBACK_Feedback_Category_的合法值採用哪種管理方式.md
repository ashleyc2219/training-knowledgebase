# 釐清問題

Feedback Category 的合法值採用哪種管理方式？

# 定位

- 追蹤 ID：D13
- [FEEDBACK.category](../../../erm.dbml)，第 153 行。
- [收集教學回饋，Rule 3「使用者勾選的 Feedback Category 優先於模型分類」](../../../features/收集教學回饋.feature)，第 19 行。
- [接入來源事件，Rule 19「正規化物件的枚舉欄位必須使用合法值」](../../../features/接入來源事件.feature)，第 107 行。

現況：來源只有找不到按鈕、缺少資訊等例子，卻要求枚舉合法與同類計數；無完整 taxonomy。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | MVP 固定只接受找不到按鈕與缺少資訊；其他文字歸為未分類，不自動新增類別。 |
| B | 使用可擴充的核定類別表；先提供完整初始清單，未知值進入待分類狀態。 |
| C | 接受自由字串，再用另一個正規化類別識別碼供聚合；原始值保持可追溯。 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

決定選單、模型輸出 schema、未知分類處理；若選擇類別表，清單本身仍需補入規格後才算解決。

# 解決記錄

- **回答**：B - 使用可擴充的核定類別表；初始清單為找不到按鈕、缺少資訊；未知值進入待分類。
- **更新的規格檔**：docs/spec/erm.dbml、docs/spec/features/收集教學回饋.feature、docs/spec/features/接入來源事件.feature
- **變更內容**：寫入初始核定類別表；未知值寫待分類，不自動新增類別。負面類別集合仍留 F43。
