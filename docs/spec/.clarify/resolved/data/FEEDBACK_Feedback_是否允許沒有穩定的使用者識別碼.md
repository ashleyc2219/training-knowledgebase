# 釐清問題

Feedback 是否允許沒有穩定的使用者識別碼？

# 定位

- 追蹤 ID：D11
- [FEEDBACK.user](../../erm.dbml)，第 155 行。
- [TICKET.author](../../erm.dbml)，第 110 行。
- [收集教學回饋，Rule 1「Feedback 的 tutorial_version 必須存在於圖譜」](../../features/收集教學回饋.feature)，第 8 行。

現況：D23 已要求瀏覽、回饋與 Ticket 接入時提供同一穩定使用者 ID。本題仍決定 widget 是否允許匿名穩定 ID；選 C 會與 D23 衝突。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 不允許；每次提交都必須提供可重用的使用者識別碼。 |
| B | 允許未登入使用者，但 widget 必須提供穩定的匿名識別碼。 |
| C | 允許 user 為空；此類回饋可計評分，但不能用來連結重開票使用者。 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響 widget 必要輸入、回饋去重與無法識別使用者時的指標範圍。

# 優先級

Medium

- 影響邊界行為、資料一致性或驗收完整性。

---
# 解決記錄

- **回答**：A - 不允許；每次提交都必須提供可重用的使用者識別碼。
- **更新的規格檔**：docs/spec/features/收集教學回饋.feature
- **變更內容**：缺 user 則操作失敗；與 D23 的穩定使用者 ID 契約對齊。
