# 釐清問題

fail_count 代表連續失敗還是累積失敗？

# 定位

- 追蹤 ID：D20
- [PROVEN_WORKFLOW.fail_count](../../../erm.dbml)，第 203 行。
- [接入來源事件，Rule 14「每次重放失敗時 fail_count 增加 1」](../../../features/接入來源事件.feature)，第 83 行。
- [接入來源事件，Rule「重放成功時 fail_count 歸零」](../../../features/接入來源事件.feature)，第 89 行。
- [接入來源事件，Rule 16「同一流程連續三次重放失敗後 status 變為 retired」](../../../features/接入來源事件.feature)，第 99 行。

現況：來源同時說每次失敗加 1 與連續三次退役，沒有指定成功後如何重置或是否另有 streak。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 代表連續失敗；成功重放後歸零，達到 3 才退役。 |
| B | 代表累積失敗；另保存連續失敗計數，退役只依連續計數判斷。 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響 PROC schema、成功與失敗交錯的狀態轉換；1 次失敗、1 次成功、2 次失敗不能誤判為連續 3 次。

# 優先級

High

- 阻礙核心資料契約或主要流程定義。

# 解決記錄

- **回答**：A - 代表連續失敗；成功重放後歸零，達到 3 才退役。
- **更新的規格檔**：docs/spec/erm.dbml、docs/spec/features/接入來源事件.feature
- **變更內容**：fail_count 為連續失敗；成功重放歸零；新增「重放成功時 fail_count 歸零」規則。
