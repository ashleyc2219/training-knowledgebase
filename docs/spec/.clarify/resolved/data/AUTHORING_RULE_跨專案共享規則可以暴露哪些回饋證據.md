# 釐清問題

跨專案共享規則可以暴露哪些回饋證據？

# 定位

- 追蹤 ID：D27
- [AUTHORING_RULE.evidence](../../../erm.dbml)，第 173 行。
- [AUTHORING_RULE.derived_from](../../../erm.dbml)，第 176 行。
- [提出教學規則，Rule 6「教學規則庫在平台層跨專案共享」](../../../features/提出教學規則.feature)，第 68 行。

現況：平台規則要跨專案共享且可追溯 evidence，但未說明其他專案是否能沿 evidence 或 derived_from 讀到原始資料。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 只共享抽象規則與聚合計數，Feedback ID、原文與來源版本只供所屬專案追溯。 |
| B | 可共享經去識別及明確核准的證據摘要；原始回饋與來源身分仍限制在原專案。 |
| C | MVP 跨專案共享只接受明示的合成種子證據，真實專案證據暫不進共享庫。 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

決定規則卡片、跨專案查詢與 prompt 注入可讀範圍；不用此題引入企業權限系統，僅確立已要求共享的資料界線。

# 解決記錄

- **回答**：C - MVP 跨專案共享只接受明示的合成種子證據，真實專案證據暫不進共享庫。
- **更新的規格檔**：docs/spec/erm.dbml、docs/spec/features/提出教學規則.feature
- **變更內容**：跨專案共享規則的 evidence 僅接受明示合成種子證據；真實專案回饋與來源版本不進入共享庫。規格回寫由並行 agent 處理。
