# 釐清問題

同篇教學的 Release 與 Feedback 改版同時執行時如何排序？

# 定位

- 追蹤 ID：F35
- [建立教學版本，Rule 2「任一 pipeline 修改既有教學時使用該篇的下一個版本號」](../../features/建立教學版本.feature)，第 14 行。
- [建立教學版本，Rule 3「新版以 supersedes 關聯同一篇教學的前一版」](../../features/建立教學版本.feature)，第 23 行。
- [依改版更新教學，Rule 9「UPDATE 只重寫受影響的步驟」](../../features/依改版更新教學.feature)，第 75 行。
- [定期檢視回饋，Rule 6「REFINE 只重寫診斷命中的步驟」](../../features/定期檢視回饋.feature)，第 34 行。

現況：版本號共用且 supersedes 一對一，未定義兩條 pipeline 同時從 v2 嘗試建立 v3 的處理。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 同篇變更依接受順序串行處理，每次讀取最新可用基底再產生下一版。 |
| B | Release 優先；正在進行的 Feedback 改寫必須依 Release 新版重新診斷。 |
| C | 先完成發布者成功，另一個偵測基底已變動後結束為衝突，等待明確重試。 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

決定版本鏈是否分叉、使用者修正是否被覆蓋，以及跨 pipeline 併發與重送案例。

前置釐清：D26（見 overview.md）。

High

# 解決記錄

- **回答**：A - 同篇變更依接受順序串行處理，每次讀取最新可用基底再產生下一版。
- **更新的規格檔**：docs/spec/features/建立教學版本.feature
- **變更內容**：同篇 Release／Feedback 改版依接受順序串行，每次讀最新基底再長下一版。
