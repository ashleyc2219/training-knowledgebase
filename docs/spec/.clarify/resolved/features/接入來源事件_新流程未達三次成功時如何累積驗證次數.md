# 釐清問題

新流程未達三次成功時如何累積驗證次數？

# 定位

- 追蹤 ID：F05
- [PROVEN_WORKFLOW.success_count](../../../erm.dbml)，第 196 行。
- [接入來源事件，Rule 7「第一層流程的 success_count 必須至少為 3」](../../../features/接入來源事件.feature)，第 44 行。
- [接入來源事件，Rule 12「寫回新流程前最後一個 tool 必須是通過的 validate」](../../../features/接入來源事件.feature)，第 71 行。
- [接入來源事件，Rule 13「寫回新流程前 Step Functions 必須成功啟動」](../../../features/接入來源事件.feature)，第 76 行。

現況：來源只提供 success_count 為 4 的成熟流程，沒有第一次成功如何升到可重放門檻的路徑。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 首次成功記為 1；同簽名事件再由 Agent 完成相同可泛化序列，每次完整成功才累加。 |
| B | 首次探索後進入隔離驗證，以額外事件重放並完成成功判準，達 3 次後才提供正式重放。 |
| C | 透過第二層試用累積成功次數；只有第二層允許未滿 3 次重放時才能採用。 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

決定計數初始化、同簽名不同序列是否重算，以及從探索到成熟流程的端到端範例。

前置釐清：F03（見 overview.md）。
