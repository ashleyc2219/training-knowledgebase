# 釐清問題

candidate 與既有規則的衝突由誰判定？

# 定位

- 追蹤 ID：F55
- [驗證教學規則，Rule 4「與既有規則衝突的 candidate 規則變為 retired」](../../features/驗證教學規則.feature)，第 24 行。
- [AUTHORING_RULE.applies_when](../../erm.dbml)，第 172 行。
- [設計 11.2 生命週期](../../draft/training-kb-design-doc.md)，第 668 行。

現況：來源用詳細與太長說明衝突，卻沒有判定者或可驗收的決策格式；合併相近規則並不能取代衝突判定。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 使用核定的適用範圍與不相容條件表，由確定性檢查判定。 |
| B | 由模型輸出結構化衝突判定與證據，Analytics 依通過驗證的判定自動退役。 |
| C | 系統只提出衝突候選，由維護者確認後交給 Analytics 寫入狀態。 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

決定候選規則自動退役程度、互斥與僅文字相似的區別，以及只在不同 applies_when 生效時不應誤判的案例。

前置釐清：D16（見 overview.md）。

# 優先級

Medium

- 影響邊界行為、資料一致性或驗收完整性。

# 解決記錄

- **回答**：B - 由模型輸出結構化衝突判定與證據，Analytics 依通過驗證的判定自動退役。
- **更新的規格檔**：docs/spec/features/驗證教學規則.feature
- **變更內容**：模型輸出結構化衝突判定；Analytics 依通過驗證的判定把該 candidate 退役。不自動覆蓋 active。
