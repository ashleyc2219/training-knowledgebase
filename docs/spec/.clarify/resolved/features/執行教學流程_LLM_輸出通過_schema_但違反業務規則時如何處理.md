# 釐清問題

LLM 輸出通過 schema 但違反業務規則時如何處理？

# 定位

- 追蹤 ID：F48
- [執行教學流程，Rule 7「LLM 輸出遵循指定 JSON schema」](../../features/執行教學流程.feature)，第 39 行。
- [依改版更新教學，Rule 9「UPDATE 只重寫受影響的步驟」](../../features/依改版更新教學.feature)，第 75 行。
- [定期檢視回饋，Rule 5「診斷結果包含需要改寫的步驟編號與原因」](../../features/定期檢視回饋.feature)，第 29 行。
- [建立教學版本，Rule 8「建立 TutorialStep 時保存 references Feature 邊」](../../features/建立教學版本.feature)，第 54 行。

現況：JSON schema 只能檢查形狀；存在的 step 編號、不可改動步驟與有效 Feature 引用並非單靠型別即可確認。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 以明確的業務驗證拒絕結果，進入有限重試與最終失敗路徑，不發布不合規內容。 |
| B | 先保存待審結果，由人工確認符合步驟與引用規則後才繼續。 |
| C | MVP 只自動驗證 schema，業務正確性以展示前的人工驗收保障，需明示此限制。 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

決定模型錯誤的處理方式、必要驗證節點與負向案例；固定低 temperature 不能替代驗證。

# 優先級

Medium

- 影響邊界行為、資料一致性或驗收完整性。

# 解決記錄

- **回答**：A - 以明確的業務驗證拒絕結果，進入有限重試與最終失敗路徑，不發布不合規內容。
- **更新的規格檔**：docs/spec/features/執行教學流程.feature
- **變更內容**：通過 schema 但違反業務規則時拒絕並走重試／最終失敗，不寫入不合規物件。
