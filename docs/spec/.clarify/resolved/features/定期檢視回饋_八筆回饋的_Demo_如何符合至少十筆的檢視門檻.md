# 釐清問題

八筆回饋的 Demo 如何符合至少十筆的檢視門檻？

# 定位

- 追蹤 ID：F20
- [定期檢視回饋，Rule 3「弱教學的版本回饋樣本數必須至少為 10」](../../../features/定期檢視回饋.feature)，第 18 行。
- [設計 9.3 Periodic Feedback Review](../../../draft/training-kb-design-doc.md)，第 589 行。
- [設計 11.3 轉移](../../../draft/training-kb-design-doc.md)，第 684 行。
- [設計 12.1 五輪循環](../../../draft/training-kb-design-doc.md)，第 704 行。
- [設計 16. Demo 腳本](../../../draft/training-kb-design-doc.md)，第 781 行。

現況：pipeline 要求 n>=10，但五輪循環與 T1 都以 8 筆直接產生 A v2；現有示範不能通過原門檻。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 維持 n>=10，補足 Demo 至少 10 筆有效回饋，其中至少 8 筆可屬找不到按鈕。 |
| B | 正式規則維持 n>=10，Demo 使用明示且隔離的 n>=8 門檻。 |
| C | 將所有規格的弱教學樣本門檻統一改為 n>=8。 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

決定 Demo 是否能實際驅動核心回饋 loop；既有 avg<3.5 條件仍需同時成立，不能只補筆數便宣稱可改版。

# 優先級

High

- 阻礙核心資料契約或主要流程定義。

# 解決記錄

- **回答**：B - 正式規則維持 n>=10，Demo 使用明示且隔離的 n>=8 門檻。
- **更新的規格檔**：docs/spec/features/定期檢視回饋.feature（本批未回寫）
- **變更內容**：弱教學正式樣本維持 n>=10；Demo 明示隔離使用 n>=8，不得改寫正式門檻。
