# 釐清問題

已退役簽名重新學到流程時如何保存新序列？

# 定位

- 追蹤 ID：F53
- [PROVEN_WORKFLOW.pk](../../erm.dbml)，第 193 行。
- [PROVEN_WORKFLOW.status](../../erm.dbml)，第 198 行。
- [接入來源事件，Rule 16「同一流程連續三次重放失敗後 status 變為 retired」](../../features/接入來源事件.feature)，第 92 行。
- [接入來源事件，Rule 17「已退役流程在下次接入時視同未命中」](../../features/接入來源事件.feature)，第 97 行。
- [接入來源事件，Rule 24「只有 Rote 接入層讀寫 PROVEN_WORKFLOW」](../../features/接入來源事件.feature)，第 133 行。

現況：下一次視同未命中會觸發重新探索，但相同結構仍得到同一 PK；覆寫、保留歷史與計數重置未定義。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 同一 PROC PK 保存新的序列並重置驗證計數，舊序列僅保留於操作紀錄。 |
| B | 保留舊 PROC 為 retired，另有流程修訂識別與當前序列指標，重新計算成功門檻。 |
| C | 退役簽名保持停用，由人工核定新的序列後再明確重置流程。 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

決定 retired 是否為某序列的終態、重新學習的版本模型，以及失敗舊序列不會沿用成熟成功次數的驗收。

前置釐清：D20、F05（見 overview.md）。

# 優先級

Medium

- 影響邊界行為、資料一致性或驗收完整性。

# 解決記錄

- **回答**：C - 退役簽名保持停用，由人工核定新的序列後再明確重置流程。
- **更新的規格檔**：docs/spec/erm.dbml、docs/spec/features/接入來源事件.feature
- **變更內容**：已退役 PROC 不覆寫舊序列；重學須人工核定新序列後再明確重置。
