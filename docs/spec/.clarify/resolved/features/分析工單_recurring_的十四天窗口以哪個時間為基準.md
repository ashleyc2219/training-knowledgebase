# 釐清問題

recurring 的十四天窗口以哪個時間為基準？

# 定位

- 追蹤 ID：F11
- [TICKET.ts](../../erm.dbml)，第 111 行。
- [分析工單，Rule 3「同群在 14 天內至少有 5 筆 Ticket 才算 recurring」](../../features/分析工單.feature)，第 18 行。

現況：規則只說 14 天內至少 5 筆；基準時間、遲到事件與恰在起點的資料可能使計數不同。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 以本次分析時間 t 計算 (t-14 天, t]，使用 Ticket 的事件時間落點計數。 |
| B | 以新進 Ticket 的事件時間 t 計算 (t-14 天, t]，遲到事件依其歷史窗口重算。 |
| C | 以每日 UTC 日界線計算當日及前 13 個日期，該日內的所有事件歸同一窗口。 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

決定排程計數、晚到與未來時間事件的處理前提，以及窗口起點、終點與差一秒的案例。

前置釐清：D09（見 overview.md）。

# 優先級

Medium

- 影響邊界行為、資料一致性或驗收完整性。

---
# 解決記錄

- **回答**：C - 以每日 UTC 日界線計算當日及前 13 個日期，該日內的所有事件歸同一窗口。
- **更新的規格檔**：docs/spec/erm.dbml、docs/spec/features/分析工單.feature
- **變更內容**：recurring 窗口為 UTC 當日加前 13 個日期；Ticket.ts 先換成 UTC 日期。
