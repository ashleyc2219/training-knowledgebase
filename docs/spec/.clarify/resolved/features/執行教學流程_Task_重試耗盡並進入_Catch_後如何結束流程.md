# 釐清問題

Task 重試耗盡並進入 Catch 後如何結束流程？

# 定位

- 追蹤 ID：F49
- [執行教學流程，Rule 5「每個 Step Functions Task 設定 Retry」](../../features/執行教學流程.feature)，第 28 行。
- [執行教學流程，Rule 6「每個 Step Functions Task 設定 Catch」](../../features/執行教學流程.feature)，第 34 行。
- [發布教學版本，Rule 1「publish 上架指定的 TutorialVersion」](../../features/發布教學版本.feature)，第 8 行。

現況：要求所有 Task 有 Retry 與 Catch，但附錄骨架未定義完整 Catch 路徑與外部可見終止結果。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 整次執行以失敗結束，不發布新版本；來源可依既定重試契約重新執行。 |
| B | 保存可恢復的待處理執行，提供明確的重新處理入口，完成前不發布新版。 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

決定失敗時版本是否可見、操作人員如何恢復與錯誤狀態的驗收；Retry 次數與 timeout 秒數留到設計階段。

# 優先級

High

- 阻礙核心資料契約或主要流程定義。

# 解決記錄

- **回答**：A - 整次執行以失敗結束，不發布新版本；來源可依既定重試契約重新執行。
- **更新的規格檔**：docs/spec/features/執行教學流程.feature
- **變更內容**：Catch 後整次失敗、不發布；來源可依既定重試契約重跑。不另建待處理執行入口。
