# 釐清問題

向量搜尋取得的最相近 Feature 如何確認可用？

# 定位

- 追蹤 ID：F15
- [依改版更新教學，Rule 3「alias 比對未命中時以向量搜尋最相近的 Feature」](../../../features/依改版更新教學.feature)，第 27 行。
- [RELEASE.feature](../../../erm.dbml)，第 133 行。

現況：來源只說最像，沒有最低可信條件；沒有 Feature 或所有候選都不相似時，不能推定找到正確節點。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | alias 未命中後直接使用最相近的 Feature，只要候選集合非空。 |
| B | 必須達明確的相似度門檻才可採用；門檻與未達標輸出需列入規格。 |
| C | 向量搜尋只提供候選，必須由指定的人工確認步驟選定 Feature 才可改版。 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

決定錯改風險與未決事件路徑；選擇門檻策略後，數值及臨界範例仍需實際補齊。

前置釐清：D06（見 overview.md）。

# 解決記錄

- **回答**：B - 必須達明確的相似度門檻才可採用；門檻與未達標輸出需列入規格。
- **更新的規格檔**：docs/spec/features/依改版更新教學.feature（本批未回寫）
- **變更內容**：最相近 Feature 須 cosine >= 0.85 才可用於改版，否則不改版。
