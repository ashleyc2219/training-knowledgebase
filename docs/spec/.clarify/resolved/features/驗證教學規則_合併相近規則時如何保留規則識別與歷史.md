# 釐清問題

合併相近規則時如何保留規則識別與歷史？

# 定位

- 追蹤 ID：F34
- [驗證教學規則，Rule 7「curation 合併相近教學規則」](../../../features/驗證教學規則.feature)，第 47 行。
- [AUTHORING_RULE.rule_id](../../../erm.dbml)，第 170 行。
- [AUTHORING_RULE.applied_to](../../../erm.dbml)，第 175 行。
- [AUTHORING_RULE.evidence](../../../erm.dbml)，第 173 行。

現況：curation 只說合併相近規則，未描述 ID、證據與已套用版本的歸屬。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 建立新的規則 ID，原規則退役並保留各自歷史；新規則重新驗證。 |
| B | 保留其中一個既有 ID，合併證據與適用範圍，其餘規則退役並記錄合併關係。 |
| C | MVP 只建立相近群組供人工檢視，不自動改寫規則或移轉歷史。 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

決定歷史版本可追溯性、去重計數與合併後是否繼承 active 資格；相近候選的計算方式可留到設計。

前置釐清：D17、D18（見 overview.md）。

# 優先級

Medium

- 影響邊界行為、資料一致性或驗收完整性。

---
# 解決記錄

- **回答**：C - MVP 只建立相近群組供人工檢視，不自動改寫規則或移轉歷史。
- **更新的規格檔**：docs/spec/features/驗證教學規則.feature
- **變更內容**：MVP curation 只建相近群組供人工檢視；不自動改寫規則、不移轉 ID／證據／歷史、不自動改 status。
