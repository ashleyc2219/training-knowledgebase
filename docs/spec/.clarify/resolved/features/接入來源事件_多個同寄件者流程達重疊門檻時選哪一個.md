# 釐清問題

多個同寄件者流程達重疊門檻時選哪一個？

# 定位

- 追蹤 ID：F04
- [接入來源事件，Rule 8「第一層未命中才在同寄件者的流程中以 Jaccard 至少 0.8 比對欄位」](../../features/接入來源事件.feature)，第 49 行。
- [PROVEN_WORKFLOW.last_used](../../erm.dbml)，第 199 行。
- [設計 7.3 三層比對](../../draft/training-kb-design-doc.md)，第 330 行。

現況：範例在迴圈中回傳第一個合格流程，但 same_sender 的順序與平手處理沒有定義。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 選 Jaccard 最高者，同分時選最近成功使用者；須固定最後的識別碼排序以消除平手。 |
| B | 選成功次數最多者，同分再比 Jaccard 與穩定識別碼。 |
| C | 只在唯一候選時重放；出現多個合格候選就交給 Agent。 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響重放可重現性與錯配率；若使用最近成功時間，last_used 的更新契約也須同步明確化。

前置釐清：D19、F03（見 overview.md）。

# 優先級

Medium

- 影響邊界行為、資料一致性或驗收完整性。

# 解決記錄

- **回答**：A - 選 Jaccard 最高者，同分時選最近成功使用者；須固定最後的識別碼排序以消除平手。
- **更新的規格檔**：docs/spec/erm.dbml、docs/spec/features/接入來源事件.feature
- **變更內容**：第二層多候選時 Jaccard 最高 → last_used 最近成功 → 穩定識別碼升序。成功時更新 last_used。
